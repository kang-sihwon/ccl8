# ccl8 작업 지도

진행 중인 작업의 재개 지점은 `../../../Docs/Work/README.md` 한 곳이다. 작업마다 지도 파일 하나를 두고, 끝난 작업은 결과를 소유 사양서로 옮긴 뒤 지운다. 근거는 결정 28(`../../../Docs/DesignLog.md`)이다. 사용자가 말한 일이 무엇인지 보고 아래 모드 하나를 고른다.

## 만들기

한 세션에 끝나지 않을 작업, 또는 순서가 있는 조각이 셋 이상인 작업에 만든다.

1. `Docs/Work/<영어-kebab-이름>.md`를 만든다. 첫 문단에 무엇을 하는 작업인지, 근거 결정이나 문서가 무엇인지 쓴다.
2. 다음 절을 이 순서로 쓴다.
   - **목적지**: 모두 참이면 끝나는 조건 목록. 조건마다 명령이나 파일로 확인할 수 있어야 한다.
   - **진행**: `- [ ] N. 제목 (선행 조각 번호 또는 없음). 할 일. 완료 조건은 ...` 형식. 조각 하나는 커밋 하나나 몇 개로 끝나는 크기다.
   - **정한 것**: 이 작업에서 정한 것과 근거.
   - **아직 모르는 것**: 조각을 시작하기 전에 정해야 하는 질문. 어느 조각 전에 정할지 함께 쓴다.
   - **범위 밖**: 이 작업이 하지 않는 일.
3. `Docs/Work/README.md`의 표에 한 줄을 넣는다.
4. 사용자에게 목적지와 조각 목록을 보여 주고 고칠 점을 묻는다.

## 조각 끝내기

1. 조각의 완료 조건을 실제로 확인한다. 확인하지 못했으면 끝난 것으로 표시하지 않는다.
2. `[x]`로 바꾸고 아래에 `- 결과:` 줄을 붙인다. 지금 참인 것, 쓴 명령과 그 결과, 남긴 한계를 쓴다. 과정 서술은 쓰지 않는다.
3. 다음 조각에 영향을 준 사실(새로 찾은 링크, 바뀐 범위)은 해당 조각 아래에 적는다.
4. "아직 모르는 것"에서 풀린 질문은 "정한 것"으로 옮긴다.
5. `Docs/Work/README.md`의 상태 칸을 고친다.

## 닫기

목적지의 조건이 모두 참일 때 한다.

1. 결과 가운데 오래 유효한 것(규칙, 수치, 절차)을 소유 사양서나 규칙 문서로 옮긴다. 소유 문서는 `Docs/README.md`의 문서 지도로 정한다.
2. 지도 파일 삭제와 README 행 삭제를 사용자에게 확인받는다.
3. 확인을 받으면 `git rm`으로 지우고, 옮긴 문서와 함께 커밋한다.
