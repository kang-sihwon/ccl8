---
description: UE 5.8 소스에서 심볼·CVar를 추적해 볼트 Wiki에 기록한다
---

$ARGUMENTS 로 주어진 심볼/CVar/셰이더를 additionalDirectories로 등록된 로컬 UE 5.8 엔진 설치본에서 추적하라.

1. 볼트의 해당 주제 MOC(엔진이면 `UE5/UE5-MOC.md`)를 읽는다.
   - 이미 항목이 있으면: 해당 노트를 읽고, 기록된 앵커 문자열로 엔진에서 줄번호만 재확인한다. 전체를 재조사하지 않는다. 어긋난 부분만 갱신한다.
   - 없으면 2로 간다.
2. UE 5.8 Graft가 연결돼 있으면 Graft에서 심볼의 선언, 호출자와 소비 지점을 먼저 찾는다. 결과가 없거나 범위가 잘린 경우에만 엔진 원본을 Grep으로 찾아 해당 범위만 읽는다. 셰이더는 `-g '*.usf' -g '*.ush'`로 확장자를 명시한다.
   - CVar: `TAutoConsoleVariable` / `FAutoConsoleVariableRef` 선언 위치, 기본값, `ECVF_` 플래그, 설명 문자열을 원문 그대로 인용하고, `GetValueOnRenderThread` 등 소비 지점과 `Engine/Config/*.ini`의 오버라이드 여부를 확인한다.
   - 글로벌 셰이더: `IMPLEMENT_GLOBAL_SHADER`로 .cpp와 .usf 대응을 찾는다.
   - 렌더 패스: `AddPass`와 `RDG_EVENT_NAME`으로 진입점을 검색한다.
3. 모든 사실에 엔진 루트 기준 상대 `경로:줄` + 앵커 문자열(그 줄 코드 원문)을 붙인다. 일반 UE 지식(기억)으로 채우지 않는다. 5.4-5.5 기준 기억으로 5.8 동작을 추정하지 않는다. 못 찾은 것은 "없음"이 아니라 "검색으로 확인 못 함"으로 남긴다.
4. 다른 프로젝트에서도 재사용할 수 있고 조사 비용이 큰 결론이면 볼트의 해당 주제 폴더(예: `UE5/Rendering/<Topic>.md`)에 기록한다. 심볼 하나를 추적했어도 파일은 그 심볼이 속한 시스템·주제 단위로 만들거나 기존 노트에 합친다. 해당 MOC 표에 한 줄(다루는 심볼 열 포함)을 추가·갱신한다. 규격은 볼트 `CLAUDE.md`의 "쓰기 규칙"을 따른다. 편집 전 대상 노트와 MOC의 기존 미커밋 변경을 확인하고, 편집 후 diff만 검토한다. `git pull`, commit, push는 사용자가 요청할 때만 실행한다.
