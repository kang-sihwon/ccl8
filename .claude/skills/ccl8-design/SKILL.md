# ccl8 설계 세션

`Docs/Guide.md` 규칙 1과 2가 전제다. 설계와 코드 예시는 AI가 대화와 `Docs/`에 내고, 사용자는 그것을 보며 토론한 뒤 `Source/`와 `Config/`에 직접 적용한다. 코딩 세부 규칙은 `../../../Docs/Coding.md`, 현재 유효한 결정은 `../../../Docs/Decisions.md`, 해당 영역의 사양서는 Guide의 문서 지도에서 찾는다.

## 시작 전

1. 관련 사양서와 `Decisions.md`의 해당 주제 표를 읽어 이미 정해진 것을 확인한다. 정해진 것을 다시 묻지 않는다.
2. 현재 코드는 `graft` MCP로, 엔진 동작은 `graft_ue58` MCP로 확인한다. 근거에는 `path:line`을 붙인다. 5.8 이전 버전의 기억으로 동작을 단정하지 않는다.
3. 열린 결정이 셋 이상이면 `grilling` 스킬로 결정 트리를 먼저 좁힌다. 사실 조사는 AI가 하고 결정만 사용자에게 묻는다.
4. 사용자 초안이 있으면 타당한 부분과 고칠 부분을 나눠 적는다. 초안이 없으면 AI가 설계안을 낸다.

## 산출물 형식

한 응답에 아래 순서로 낸다. 항목이 해당 없으면 "해당 없음"과 이유 한 줄을 쓴다.

1. **목표와 제약**: 이 설계가 만족해야 하는 것과 ccl8에서 확인된 제약. 미정인 장르·성능·네트워크 요구를 추정하지 않고, 확정된 내용은 근거를 붙인다.
2. **책임과 수명**: 관여하는 클래스·컴포넌트·서브시스템마다 책임 한 줄, 소유자, 생성·소멸 시점, 네트워크 권위.
3. **클래스 다이어그램**: Mermaid `classDiagram` 코드 블록. 상속, 소유, 참조 방향을 구분한다. 문서에 넣으면 GitHub가 렌더링한다.
4. **인터페이스 초안**: 공개 함수 시그니처, 델리게이트, 데이터 타입. 헤더 초안 수준의 C++ 코드 블록.
5. **코드 예시**: UE 5.8 기준 실제 C++ 코드. 핵심 경로 하나를 함수 본문까지 보여준다. 모듈 의존(`Build.cs`)이 늘면 명시한다.
6. **검증 방법**: 실행 전에 적을 예상 결과, 확인할 로그나 테스트, 성능이면 측정 조건.
7. **이번에 배울 점**: 이 설계에 쓰인 UE5 개념이나 모던 관례 가운데 UE3·UE4 시절과 다른 것, 그리고 대안과 트레이드오프.

## 마무리

- 사용자가 설계를 고르면 확정 내용을 해당 사양서에 기록하고, 결정이면 `ccl8-docs`의 결정 기록 모드로 `Docs/DesignLog.md`에 붙인다.
- `Docs/LearningLog.md`의 "힌트 단계와 도움의 범위"에 코드 예시를 제공했다고 적는다 (`Docs/Mentoring.md`).
- 사용자가 훈련 모드를 요청하면 이 형식 대신 `Docs/Mentoring.md`의 힌트 사다리를 따른다.
- 파일 생성·수정은 사용자가 파일과 범위를 명시할 때만 한다. 이 스킬의 호출은 그 권한이 아니다.
