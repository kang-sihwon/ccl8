# MCP PIE 실행 검증

Unreal MCP로 에디터 PIE를 띄워 실제 키·마우스·Slate 조작으로 검증하는 절차다. 스모크가 입력 경로를 대신 호출해서 키 배치, 입력 매핑, 위젯 포커스, 화면 상태를 확인할 수 없을 때 쓴다. 이 절차는 2026-10-12 종합 QA의 실행 조건에서 옮겼다. 그때의 결과와 결함 기록은 [환경·전투·멀티플레이·Campaign PIE QA](../../../../Docs/FullGameplayMCPQA-2026-10-12.md)와 [환경 실험장 PIE QA](../../../../Docs/EnvironmentPIEQA-2026-10-12.md)에 있다.

## 준비

1. `SKILL.md` 2단계의 Doctor를 한다. 이 경로에서는 `http://127.0.0.1:8000/mcp` 연결과 에디터의 Unreal MCP 서버 상태까지 확인한다. 에디터가 실행 중이어야 연결된다.
2. 작업 트리의 미커밋 변경과 현재 에디터 맵을 적어 둔다. 정리할 때 이 상태로 돌아온다.
3. 이번 검증이 바꿀 수 있는 에디터 설정(PIE 네트워크 구성, 플레이 창, 백그라운드 성능 제한, 사용자 그래픽 설정)을 기록하거나 백업한다.

## 실행 구성

- MCP로 레벨을 불러오고 PIE를 시작·종료한다. Simulate는 끈다.
- 입력 포커스가 관련된 변경은 뷰포트 PIE와 별도 창 PIE를 모두 실행한다. 최초 메뉴의 입력 정책 누락은 뷰포트 PIE에서만 재현됐다.
- 멀티플레이는 한 프로세스의 Listen Server와 Client 1, Dedicated Server와 Client 1·2로 구성한다. 이 구성은 별도 프로세스·장치, 지연, 패킷 손실을 검증하지 않는다. 그 범위는 `run_network_smoke.ps1`의 옵션이나 별도 검사로 확인한다.
- 시험에 필요한 픽업은 PIE 월드에만 임시로 배치하고 에디터 맵에 저장하지 않는다. 체력, 스태미나, 피해, 적 AI 값은 강제로 바꾸지 않는다. 바꿔야 한다면 그 조건을 결과에 적는다.

## 조작과 진단

- 화면 조작은 Slate 클릭·키·드래그와 화면 캡처로 한다.
- 연속 이동과 공격은 Enhanced Input에 입력을 주입한다. 증거 강도는 `MCP`다.
- 뷰포트 포커스는 마우스 클릭 없이 전달한다. 클릭이 게임 입력으로 처리돼 상태를 바꿀 수 있다. 2026-10-12 QA에서는 포커스용 클릭이 소총 발사로 처리돼 장전량이 바뀌었다.
- 상태 진단은 MCP 콘솔의 읽기 전용 Python으로 한다. Controller의 입력 차단, Pawn 위치, CommonUI 위젯 트리, 입력 정책을 덤프하는 정도로 제한하고 게임 상태를 쓰지 않는다.

## 판정

- 도구의 클릭 성공 응답이 아니라 실제 상태 변화로 판정한다. 근거는 체력·위치·태그·아이템·저장 레코드의 변화, 화면 상태, 검사 결과 JSON이다.
- 실행한 동작만 판정한다. 자동 검사 통과를 수동 조작이나 경계 조건의 통과로 넓히지 않는다. 확인하지 못한 범위는 결과에 미확인으로 적는다.
- 입력 도구 준비 중의 시간 초과나 조작 실수로 실패한 시도는 유효한 조건으로 다시 실행하고, 다시 통과하면 제품 결함으로 분류하지 않는다. 버린 시도와 그 이유는 기록한다.
- 같은 이름의 결과 파일이 여럿이면 판정에 쓴 파일과 조건을 결과에 지정한다.

| 영역 | 읽을 상태 |
|---|---|
| 환경 실험장 | `Saved/EnvironmentExperiments/Results/<ID>.json`의 구역 판정과 화면의 수치. 자동 검사의 범위 밖 조작은 수동 관측으로 따로 판정한다 |
| 전투 | HP, 스태미나, 위치, GAS 태그(`State.Combat.Stagger` 등), Pawn 수명 |
| 멀티플레이 | 플레이어마다 서버와 클라이언트의 Pawn, 위치, 사망·재도전 상태. 다른 플레이어의 상태가 유지되는지 |
| Campaign·저장 | 퀘스트, 동전, 성장, 아이템·장비·장전량. 저장 복원은 저장 파일의 아이템을 ID로 정렬해 수량·슬롯·장전량을 비교한다 |
| 메뉴·입력 | 입력 정책, 이동·시점 차단 값, 메뉴를 열어 둔 채 이동 입력을 유지했을 때의 위치 |

## 증거

`Saved/Tests/MCP-<주제>-<날짜>/`에 다음을 둔다. 이 폴더는 Git에 제출하지 않는다.

- 상태 기록: `probes.jsonl`(상태 측정), `inputs.jsonl`(연속 입력), `snapshots*.json`(Slate 화면·조작 상태)
- 영역별 결과 JSON과 저장 파일 사본
- 화면 캡처
- `editor.log` 사본. 앞선 실행의 로그가 섞이므로 시각과 발생 주체로 구분한다. 에디터 로그는 UTC, 보고 시각은 KST로 적는다.

## 정리

1. PIE를 종료하고 준비 2단계에서 적은 에디터 맵으로 돌아온다.
2. Slate 관측기를 해제하고 준비 3단계에서 기록한 설정을 복원한다.
3. 저장하지 않은 렌더링 변수처럼 복원을 보증할 수 없는 설정은 결과에 적는다.
4. 증거 폴더와 이번 검증이 만든 저장 데이터는 지우지 않는다.
