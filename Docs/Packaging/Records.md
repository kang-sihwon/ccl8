# 패키지 기록

패키지별 생성·실행 기록을 보존한다. 상위 문서는 [Packaging](../Packaging.md)이다.

## 패키지 기록

아래는 패키지별 시점 기록이다. 최근 기록이 마지막에 있다.

### 2026-10-07 단계 7 최초 전달본

노트북의 UE 5.9.0 소스 엔진에서 생성 BAT, CCLEditor, 게임·패키징 도구 빌드와 쿠킹·스테이징·아카이브가 성공했다. UAT는 종료 코드 0을 반환했다. 첫 게임·도구 빌드의 UBA 실행 시간은 약 27분, 전체 UAT 실행 시간은 약 38분이다.

모두 패키징한 실행 파일에서 통과했다.

| 검사 | 확인한 결과 | 로그 |
|---|---|---|
| 시작·저장·복원 | 실제 Enter 입력, 부분 진행·성장·승리 복원, 잘못된 저장 거부, 설정, 메뉴 복귀와 정상 종료 | |
| 방 생성·접속 | 메뉴에서 호스트 생성, 원격 접속, 게스트 저장 거부와 정상 종료 | |

| 사용자 실행 파일 | 루트 `CCL.exe`에서 맵 인자 없이 시작·저장·복원, 자식 게임과 실행기의 정상 종료 | |

패키징한 시작·저장 복원·메뉴 화면과 NPC·승리 화면을 확인했다. 확인한 화면에서 메시·머티리얼·글꼴 누락은 발견하지 않았다. 스테이징된 엔진 설정에 자동 생성 SecurityToken 키가 포함되지 않은 것도 확인했다.

로그 검토에서는 의도한 접속 실패의 타임아웃과 검사 종료 후 서버를 닫을 때의 연결 종료 메시지를 구분했다. 게임플레이의 치명적 오류·어설션과 빌드·쿠킹 실패는 발견하지 않았다.

#### 검증 범위

이 결과는 Windows 노트북 한 대에서 실행한 Development 패키지다. 패키지의 Standalone·Listen을 검증했고 Dedicated Server는 이전 단계의 에디터 실행 결과만 있다. Shipping 게임 타깃, 다른 PC, 외부 인터넷·NAT 환경은 검증하지 않았다. UE 5.8 호환성을 확인한 결과도 아니다.

아트·애니메이션·밸런스는 프로토타입 수준이며 최종 조작감은 사용자 검토가 필요하다. 메뉴의 모든 마우스 조작과 창 모드 전환에 대한 수동 검사는 [SessionFoundation](../SessionFoundation.md)의 미확인 항목을 따른다.

디버그 심볼을 포함한 폴더 크기는 약 3.16 GiB다.

#### 장비 UI 검증본

`-ArchiveDirectory`로 별도 출력 폴더를 지정할 수 있다. 첫 쿠킹에서는 Zen 저장소의 `Missing chunk references` 오류가 발생했다. `-SkipZenStore` 옵션으로 쿠킹 결과를 파일로 저장한 재시도는 UAT 종료 코드 0으로 통과했다. 이 옵션은 엔진 `CookCommandlet.cpp`의 `SkipZenStore` 분기를 사용하며 프로젝트의 기본 설정을 바꾸지 않는다.

장비 UI 검증본의 실제 게임 실행 파일을 `run_ui_smoke.ps1 -PackagedExecutable`에 전달하고 `-Offscreen`으로 렌더링했다. 1280×720과 1920×1080에서 가방 이동·교환·취소, 장착·해제, 장비 8칸 표시와 NPC 대화를 확인했다. 이 검사는 게임 내부 Slate 이벤트를 사용하며 Windows의 수동 마우스 조작과 구분한다.

### 2026-10-11 자연 환경의 Server 타깃

환경 통합은 `CCLServer`의 `TargetType.Server`와 Windows Development 게임 패키지에서 각각 확인한다. 서버 패키지와 게임 패키지는 별도 아카이브 경로에 만들고 여섯 검사 맵을 쿠킹 대상으로 명시한다. 실제 서버 실행 파일에 게임 클라이언트 두 개를 연결해 환경 상태와 조작을 검사한다. 타깃 선언과 빌드·쿠킹·실행 성공은 구분한다.

#### 최초 Server 패키지와 시작 실패

2026-10-11 UE 5.8.3에서 `CCLServer Win64 Development`의 컴파일·링크와 여섯 맵의 WindowsServer 쿠킹·스테이징·아카이브가 성공했다. 빌드 영수증의 `TargetType`은 `Server`다. UAT는 `BUILD SUCCESSFUL`, 종료 코드 0과 총 3236.68초를 기록했다. 이 첫 바이너리에는 이후 작성한 지형 경계 최적화가 들어 있지 않다.

실제 패키지의 첫 실행은 실패했다. 맵 로딩과 19971 포트 개방 뒤 `ACCLVegetationPresentation::BeginPlay`의 `Clear`가 없는 레이블에 접근해 종료됐다. 결과 JSON은 `passed=false`다. 따라서 패키지 생성 성공을 실행 통과로 기록하지 않는다. Game 최초 빌드는 이 문제를 먼저 수정·재검증하기 위해 중단했고 중간 산출물은 보존했다.

Dedicated Server에서는 시각 요소 갱신 전에 서버 모드를 확인하도록 식생·생태 표현 경로를 수정한다. 작업장은 레이블이 없어도 권위 단계 갱신과 복제를 계속해야 하므로 표현 포인터만 선택적으로 사용한다. 표면의 서버 충돌과 내비게이션·생태 상태 계산은 유지한다. 엔진의 `UPrimitiveComponent::NeedsLoadForServer`는 충돌이 없고 `AlwaysLoadOnServer`도 꺼진 컴포넌트를 제외한다. 근거는 `<Engine>/Source/Runtime/Engine/Private/Components/PrimitiveComponent.cpp:2076`이다. 최종 생성·Editor 빌드와 재패키징 뒤 실제 Server의 기동·첫 접속·관측·재접속을 다시 검사한다.

#### Server 실행 수정과 실제 네트워크 통과

표현 컴포넌트가 없는 서버 경로를 수정하고 프로젝트 생성·Editor 빌드를 통과했다. 재패키징은 93.71초·종료 코드 0으로 통과했다. 다음 실행은 서버가 기동됐지만 경로로 로딩하는 `DA_FoodSample`이 쿠킹에서 빠져 실험 준비를 끝내지 못했다. 이 실패는 보존했다.

`Config/DefaultGame.ini`의 패키징 목록에 두 환경 맵과 `/Game/Environment`를 추가했다. 음식 정의와 경로로 선택하는 표면 재질 등 환경 에셋을 포함한다. 맵에서 직접 참조하는 것만 쿠킹하는 방식보다 패키지 크기가 늘지만, 현재 실험장이 경로로 선택하는 에셋을 함께 전달한다. 재쿠킹·아카이브 후 실제 `CCLServer.exe`에서 80ms 지연·2% 손실·조작자·관측자·관측자 재접속 검사를 통과했다. 서버는 실제 Server 타깃이고 클라이언트는 Editor 게임 모드다. 일반 Game 타깃 패키지는 아직 최초 컴파일 중이며 이 결과로 완료 처리하지 않는다. 구역 09의 후속 변경 전 검증 결과다.

### 전체 검토 직후의 패키지 미검증 기록

2026-10-11 전체 검토 직후에는 에디터에서 다시 검증했지만 Windows 게임 패키지를 다시 만들지 않았다. 이 절은 아래 집계 영양 상태 패키지 생성 전의 기록이다. `LocalPlayerClassName` 설정, `DA_ItemCatalog` 카탈로그와 적 정의 에셋, 재접속 신원 연결은 패키지에서 확인하지 않았다. 카탈로그와 적 정의는 `/Game/Progression`에 있어 기존 항상 쿠킹 목록에 들어간다. 에디터 재검증 결과는 [2026-10-11 재검증 기록](../QA/FullReviewReverification-2026-10-11.md)을 따른다.

### 집계 영양 상태를 포함한 패키지

2026-10-11 UE 5.8.3에서 캠페인 배치 식별 수정과 집계 영양 상태를 포함한 Windows Development Game·Server 패키지를 생성했다. Game의 첫 빌드는 엔진 게임 타깃과 셰이더의 최초 생성 비용을 포함해 BuildCookRun 3126.37초였으며 보존한다. 영양 상태의 후속 수정을 반영한 Game은 80.39초, Server는 275.19초로 성공했다. 두 최종 UAT 모두 `BUILD SUCCESSFUL`과 종료 코드 0을 기록했다.

검토 실행 파일은 다음 위치에 있다. Game의 사용자는 루트 실행 파일을 사용하며 검사 도구는 내부 실행 파일을 직접 사용한다. 다른 PC로 전달할 때는 해당 Windows 또는 WindowsServer 폴더 전체가 필요하다.

환경 전체의 최초 Game Listen 실행에서는 구역 09의 물이 하류에 도달하기 전에 판정해 실패했다. 실패 로그를 보존하고 실험 관찰 시간에 게임 시간 조건을 추가했다. 계산식과 수량 임계값은 유지했으며 근거는 [순환 실험의 두 시간](../EnvironmentPlan/Integration.md#순환-실험의-게임-시간과-세계-시간)을 따른다.

구역 09 관찰 시간 수정 후에도 Game·Server를 다시 빌드·쿠킹했다. BuildCookRun 198.15초138.02초와 각각 종료 코드 0을 기록했다. 위 실행 파일 경로에는 이 후속 결과가 들어 있다. Game Listen의 환경 전체·80ms 지연·2% 손실·관측자 재접속은 통과했다.

실제 Server와 Game 클라이언트의 환경 전체 검사도 통과했다. `server_target=true`, `packaged_client=true`이며 80ms 지연·2% 손실을 적용한 상태에서 조작자·관측자 접속과 관측자 재접속을 확인했다. 에디터 게임 모드로 Server를 대신한 결과가 아니다.

Game의 Playground 렌더링 전체 검사는 통과했다. 같은 폴더의 안내·12개 구역 배치·열린 문을 확인했다. 생태 전용 검사의 두 화면도 [영양 상태 문서](../EnvironmentPlan/Ecology/Nutrition.md)에 연결했다. 시험 영역 바깥의 검은 배경과 단순한 형상·재질은 그대로 남아 있다.

이 결과는 한 PC의 로컬 Development 검사다. Shipping, 다른 PC·외부 인터넷·NAT와 최종 아트 품질은 검증하지 않았다. 실험장 관측자의 재접속은 환경 상태 복제를 검사하며 모든 캠페인 원격 프로필 복원 조합의 검증으로 확대하지 않는다.

프레임 계측은 기능 검사와 별개다. 18,000프레임 실행의 중단과 600프레임 재실행의 행 수 불일치로 최신 패키지의 완료 성능 수치는 아직 없다. 근거와 재검사 항목은 [프레임 계측의 미완료 범위](../EnvironmentPlan/Integration.md#프레임-계측의-미완료-범위)를 따른다.

빌드 영수증의 `TargetType`은 각각 Game·Server이며 패키지 내부 실행 파일은 `Binaries/Win64`의 해당 빌드 파일과 SHA-256이 일치한다. 검증한 소스 파일은 `verified-source.json`에 기록했다.

#### 서버 생성자의 시각 에셋 로딩

최초 전용 서버의 기능 검사는 통과했지만 CDO 생성 시 화면용 글꼴을 찾지 못했다. `CCLVegetationPresentation`, `CCLWorkshop`, `CCLVillageSteward`의 생성자가 서버 패키지에 없는 `F_VegetationLabel`·`F_KoreanLabel`을 조회한 것이 원인이다.

세 생성자는 `IsRunningDedicatedServer()`일 때 글꼴 조회를 건너뛴다. 게임의 글꼴 설정과 기본 컴포넌트 생성은 유지한다. 이 함수는 서버 전용 플랫폼을 먼저 판정한다 (`<Engine>/Source/Runtime/Core/Public/Misc/CoreMisc.h:152`, 앵커 `FPlatformProperties::IsServerOnly()`). `BeginPlay`의 시각 갱신 분기만으로는 그보다 앞선 생성자 조회를 막을 수 없다.

복제 검사 도구에도 CDO 생성자 오류를 실패 조건으로 추가했다. 수정 전 패키지가 실제로 거부된 기록은 다. 최종 패키지에서는 이 오류가 사라지고 같은 복제 검사가 통과했다.

#### 재현과 한계

최종 쿠킹에는 에디터 미리보기의 `ETonemappingMethod=Default` 가져오기 경고와 환경 맵의 `FString` 기반 `FText` 저장 경고가 남았다. Game·Server 패키징 로그에서 확인했으며 경고 0인 빌드로 보고하지 않는다. 이번 검증에서 에셋은 재저장하지 않았다.

검증 환경은 Windows 한 대의 UE 5.8.3 Development다. UI 도구는 게임 내부 Slate 이벤트를 사용하며 운영체제 마우스의 수동 검사는 아니다. Shipping, 다른 PC·외부 인터넷, Iris 전환과 성능 목표 충족은 검증하지 않았다. 기능 PASS와 치명적 오류·어설션·생성자 오류를 함께 확인했다. 환경 검사에서 의도한 구역 09 취소 1건은 `CCL_EXPERIMENT FAIL`로 기록되며, 이어지는 취소 확인·원래 입력 복구와 최종 성공을 대조했다.

#### Server 디버그 심볼 복사 보완

최초 Server 아카이브는 디스크 공간 부족으로 CCLServer.pdb를 복사하지 못했는데도 BuildCookRun이 성공으로 종료됐다. 실행 파일·콘텐츠 생성 성공과 디버그 심볼 전달을 구분해 확인했다. 이번 Game 아카이브와 SHA-256이 같은 Game 스테이징 PDB 중복본 하나만 제거해 공간을 확보했다. 원본 Binaries·Game 아카이브의 심볼과 기존 패키지는 보존했다.

누락된 Server PDB를 이번 Server 스테이징에서 아카이브로 복사한 뒤 SHA-256 일치를 확인했다. 결과와 정리한 단일 경로는 `archive-pdb-repair.json`에 기록했다. 따라서 최초 UAT 종료 코드만으로 아카이브 전체 복사가 성공했다고 판정하지 않는다.
