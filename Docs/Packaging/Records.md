# 패키지 기록

패키지별 범위와 결과를 보존한다. 상위 문서는 [Packaging](../Packaging.md)이다. 최근 기록이 마지막에 있다.

모든 기록은 Windows 한 PC의 Development 패키지다. Shipping, 다른 PC, 외부 인터넷, NAT, Iris, 성능 목표 충족, 장시간 안정성은 검증하지 않았다. UI 도구는 게임 내부 Slate 이벤트를 쓰므로 운영체제 마우스의 수동 검사가 아니다.

## 패키지에서 얻은 규칙

- **종료 코드만 믿지 않는다.** 패키지 생성 성공을 실행 통과로 기록하지 않는다. 최초 Server 아카이브는 디스크 공간 부족으로 `CCLServer.pdb`를 복사하지 못했는데도 BuildCookRun이 성공으로 끝났다. 누락된 PDB는 스테이징에서 복사해 SHA-256을 대조했다.
- **서버 코드는 표현 포인터를 선택적으로 쓴다.** 실제 패키지 첫 실행이 `ACCLVegetationPresentation::BeginPlay`의 `Clear`가 없는 레이블에 접근해 종료됐다. 시각 요소 갱신 전에 서버 모드를 확인하고, 표면의 서버 충돌, 내비게이션, 생태 계산은 유지한다. 엔진 `UPrimitiveComponent::NeedsLoadForServer`는 충돌이 없고 `AlwaysLoadOnServer`도 꺼진 컴포넌트를 뺀다(`<Engine>/Source/Runtime/Engine/Private/Components/PrimitiveComponent.cpp:2076`).
- **생성자의 시각 에셋 조회도 막는다.** `CCLVegetationPresentation`, `CCLWorkshop`, `CCLVillageSteward`의 생성자가 서버 패키지에 없는 `F_VegetationLabel`, `F_KoreanLabel`을 찾았다. `BeginPlay`의 분기로는 그보다 앞선 생성자 조회를 막지 못하므로 `IsRunningDedicatedServer()`일 때 건너뛴다(`<Engine>/Source/Runtime/Core/Public/Misc/CoreMisc.h:152`). 복제와 전투, 투사체 도구는 CDO 생성자 오류를 실패로 판정한다.
- **경로로 찾는 에셋은 쿠킹 목록에 넣는다.** 경로로 로딩하는 `DA_FoodSample`이 쿠킹에서 빠져 실험 준비가 끝나지 않았다. `Config/DefaultGame.ini`의 패키징 목록에 두 환경 맵과 `/Game/Environment`를 넣었다. 맵에서 직접 참조하는 것만 쿠킹할 때보다 패키지가 커지지만 경로로 고르는 에셋을 함께 전달한다.
- **Zen 저장소 오류:** 첫 쿠킹의 `Missing chunk references` 오류는 `-SkipZenStore`로 쿠킹 결과를 파일에 저장해 통과했다. 프로젝트의 기본 설정은 바꾸지 않는다.
- **전달:** 실행 파일만 복사하지 않고 `Windows` 또는 `WindowsServer` 폴더 전체를 쓴다. Game 사용자는 루트 `CCL.exe`를 쓰고 검사 도구는 내부 실행 파일을 직접 쓴다.
- **경고 구분:** 의도한 접속 실패 타임아웃, 검사 종료 후의 연결 종료 메시지, 구역 09 중단 검사의 `CCL_EXPERIMENT FAIL`은 실패가 아니다. 취소 확인, 입력 복구, 최종 성공을 함께 대조한다.

## 2026-10-11 자연 환경의 Server 타깃

환경 통합은 `CCLServer`의 `TargetType.Server`와 Windows Development 게임 패키지에서 각각 확인한다. 두 패키지는 별도 아카이브 경로에 만들고 여섯 검사 맵을 쿠킹 대상으로 명시한다. 타깃 선언과 빌드, 쿠킹, 실행 성공은 구분한다.

첫 Server 패키지는 UE 5.8.3에서 컴파일, 링크, 여섯 맵의 WindowsServer 쿠킹이 성공했고 UAT는 3236.68초, 종료 코드 0이었다. 실행은 19971 포트 개방 뒤 표현 레이블 접근으로 실패했다.

### Server 실행 수정과 실제 네트워크 통과

표현 컴포넌트가 없는 서버 경로를 고치고 재패키징했다(93.71초, 종료 코드 0). 다음 실행은 쿠킹 누락으로 실험 준비를 끝내지 못했고, 쿠킹 목록을 고친 뒤 실제 `CCLServer.exe`에서 80ms 지연, 2% 손실, 조작자, 관측자, 관측자 재접속 검사를 통과했다. 서버는 실제 Server 타깃이고 클라이언트는 Editor 게임 모드다. 구역 09의 후속 변경 전 결과다.

전체 검토 직후에는 에디터에서만 재검증했다. `LocalPlayerClassName` 설정, `DA_ItemCatalog` 카탈로그와 적 정의 에셋, 재접속 신원 연결은 이때 패키지에서 확인하지 않았다. 카탈로그와 적 정의는 `/Game/Progression`에 있어 항상 쿠킹 목록에 들어간다. 에디터 재검증은 [2026-10-11 재검증 기록](../QA/FullReviewReverification-2026-10-11.md)을 따른다.

## 집계 영양 상태를 포함한 패키지

2026-10-11 UE 5.8.3에서 캠페인 배치 식별 수정과 집계 영양 상태를 포함한 Game과 Server 패키지를 만들었다. Game의 첫 빌드는 엔진 게임 타깃과 셰이더의 최초 생성 비용을 포함해 BuildCookRun 3126.37초였다. 후속 수정을 반영한 Game은 80.39초, Server는 275.19초였고, 구역 09 관찰 시간 수정 뒤 Game 198.15초, Server 138.02초로 모두 종료 코드 0이다.

실험장 관측자의 재접속은 환경 상태 복제를 검사하며 모든 캠페인 원격 프로필 복원 조합의 검증이 아니다. 프레임 계측은 기능 검사와 별개다. 18,000프레임 실행의 중단과 600프레임 재실행의 행 수 불일치로 완료 성능 수치는 없다. 근거는 [프레임 계측의 미완료 범위](../EnvironmentPlan/Integration.md#프레임-계측의-미완료-범위)다.
