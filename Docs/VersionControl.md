# GitHub 버전 관리

ccl8은 독립 Git 저장소이며 기본 브랜치는 `main`이다. 엔진 소스는 저장소 밖에서 관리한다. 초기 구성에서는 GitHub 저장소 생성, 원격 연결과 push를 수행하지 않는다.

## 동기화

- 먼저 `git status --short --branch`와 `git remote -v`를 확인한다. 원격이 없으면 로컬 작업을 계속한다.
- 승인된 원격과 upstream이 있고 작업 트리가 깨끗하면 `git pull --ff-only`, `git lfs pull` 순으로 받는다. 미커밋 변경이나 분기가 있으면 자동 stash·reset·강제 push로 덮지 않고 상태를 보고한다.
- 의도한 파일만 stage하고 staged diff를 검토한다. 브랜치 변경·reset·강제 push는 별도 명시 요청을 따른다.
- 커밋 제목은 영어 명령형 한 줄로 쓰고 필요한 경우 이유와 검증을 본문에 남긴다.

## 커밋 주체

AI가 수행한 `Docs/`, `.claude/`, `.agents/`, `.codex/`의 공유 지침·스킬, `README.md`, `CLAUDE.md`, `AGENTS.md` 변경은 작업 묶음별로 AI가 commit·push한다. push는 사용자가 연결을 승인한 원격과 브랜치가 있을 때만 수행한다. 미연결 상태는 커밋 후 보고한다.

게임 코드·설정·에셋과 도구 코드 변경의 제출은 사용자가 정한 작업 범위를 따른다. 이번 최초 구성은 승인된 도구·설정·빈 폴더를 하나의 로컬 초기 커밋으로 기록한다. 학습 기록 자동 갱신만으로 commit·push를 실행하지 않는다.

## 에셋·생성 파일

- 에셋을 에디터에서 저장한 뒤 변경을 확인한다. `.uasset`, `.umap`과 원본 미디어는 `.gitattributes`에 따라 LFS로 관리한다.
- 같은 바이너리 에셋을 여러 기기에서 동시에 편집하지 않는다. 충돌 시 자동 병합 가능성을 전제하지 않고 보존할 버전을 결정한다.
- 새 PC는 `git lfs install --local`과 `git lfs pull`을 실행한다. 업로드 전 `git lfs status`로 대상과 용량을 확인한다. 서비스 요금·한도는 GitHub의 현재 계정 설정을 확인한다.
- 엔진, 빌드 산출물, IDE 생성물, 로컬 설정과 분석 캐시는 제외한다. `Build/`의 아이콘·배포 원본과 필요한 `*_BuiltData.uasset`은 추적한다.
- 공유 설정에는 토큰과 기기별 절대 경로를 넣지 않는다. 플러그인 로그인·연결은 각 기기에서 수행한다.
