# 음식 상태와 인벤토리

음식 묶음의 부패와 곰팡이 모델, 인벤토리 이동, 세션 저장을 다룬다. 단계 8의 음식 요구와 아이템 조합 원칙인 결정 9·15를 따른다. 검증은 2026-10-10 UE 5.8.3의 Editor Standalone과 NullRHI다.

## 모델

음식은 선택적인 `FCCLItemFragment_Perishable`로 정의한다. 공유 정의에는 기준 보존 시간과 곰팡이 발현, 성장 시간을 두고, 인벤토리 항목은 생성 묶음별 수량, 생성 시각, 누적 부패 노출, 곰팡이 노출을 소유한다.

| 소유자 | 책임과 수명 |
|---|---|
| `FCCLFoodState` | 아이템 묶음의 생성 이력, 노출, 보관 조건. 인벤토리 이동과 저장 수명을 따른다 |
| `CCLFood` | UObject 없이 값 후보의 진행, 합치기, 분할, 검증을 수행한다. 실패하면 원본과 출력을 모두 보존한다 |
| `UCCLInventoryComponent` | 서버에서 음식 생성, 묶음 이동, 조건 변경을 요청하고 Fast Array에 게시한다 |
| 세션 저장 | 아이템의 음식 상태와 공통 세계 저장을 함께 보관하고 세계 ID와 완료 시각을 대조한다 |

- **시간:** 서버 인벤토리가 변경 권한을 갖고 현재 완료 세계 시각을 부패 계산에 넘긴다. 상태에는 세계 ID, 마지막 평가 시각, 당시 보관 조건을 저장한다. 같은 조건에서는 누적 노출에 경과 시간을 더하고, 조회는 복사본을 평가한다. 조건 변경, 합치기, 분할 전에는 이전 조건으로 현재 시각까지 계산한다. 음식만 따로 Tick해 공통 시계보다 먼저 진행하지 않는다.
- **신선도:** 누적 부패 노출을 기준 보존 시간으로 나눈 값이 신선도 감소다. 기준 조건은 20°C, 상대 습도 100%, 보존 계수 1이다. 0°C 이하에서 계산을 정지하는 초기 정책과 온도, 습도, 보존 계수는 게임용 입력이고 실제 식품 안전의 근거가 아니다.
- **곰팡이:** 습한 조건에서 별도의 누적 노출이 발현 시간을 넘으면 증가한다. 건조와 냉각만으로 이전 노출을 지우지 않는다.
- **표시:** 영구 상태의 이력은 그대로 두고 화면에는 0-1 비율을 준다. 합치기의 평균 신선도와 곰팡이 비율은 수량 가중 표시값이고, 부패한 개수와 곰팡이가 있는 개수는 따로 반환한다.
- **묶음:** 원본 ID는 분할해도 유지한다. 같은 슬롯에 새 음식과 오래된 음식이 들어가도 평균 내거나 생성 시각을 다시 쓰지 않는다. 원본, 생성 시각, 노출이 완전히 같은 묶음만 수량을 합친다. 같은 원본 ID에 다른 생성 시각을 넣으면 거부한다. 한 항목의 묶음은 256개가 한도이고 초과 요청은 원본을 보존한 채 거부한다.
- **소비와 이동:** 소비와 분할은 생성 시각이 가장 오래된 묶음부터 한다. 전체 묶음을 빈 컨테이너로 옮기면 아이템 GUID를 유지하고 기존 조건도 유지한다. 일부만 옮기거나 기존 묶음에 합치면 대상 항목의 GUID 규칙을 따르되 음식 원본 ID와 시각은 보존한다. 기존 대상과 합칠 때는 양쪽을 각자의 이전 조건으로 현재 시각까지 계산한 뒤 대상의 조건을 쓴다.
- **정책 보존:** 새 음식 상태에는 생성 시점의 부패 정책 값을 함께 보존해, 에셋 수치 변경이 기존 음식의 과거를 소급해 바꾸지 않게 한다.

평균 한 개보다 저장, 복제, 검증 비용이 늘지만 합치기를 통한 신선도 회복과 일부 소비 뒤 남은 음식의 나이 변경을 막는다. UE5의 기존 Fragment와 Fast Array를 쓰며 별도 모듈은 추가하지 않았다. Fast Array는 UE4에도 있던 기능이고 구조체 Fragment는 이 프로젝트의 UE5 조합 방식이다.

`DA_Bread`는 최대 20개, 기준 보존 시간 86,400초, 곰팡이 발현과 성장 각 43,200초다. 기능 검증용 초기 설정이고 생물학적 정확도나 최종 밸런스가 아니다.

## 음식 상태·인벤토리·세션 검증

세션 형식 7은 음식 바이트를 Base64로 보관한다. 내부 형식 1은 세계 ID, 마지막 평가 시각, 생성 당시 정책, 보관 조건, 최대 256개 묶음을 CRC와 함께 검증한다.

- 음식 수량은 인벤토리 수량과 같아야 하고, 음식의 세계 ID는 함께 저장된 Campaign 세계와 같아야 한다.
- 마지막 평가 시각이 저장 세계 시각보다 미래면 거부한다.
- 이전 세션 형식 1-6은 음식 생성 시각을 주입하지 않고 빈 상태로 변환한다.
- 구조와 CRC는 손상 검사용이고, 신뢰할 수 없는 외부 파일의 보안 경계를 제공하지 않는다.

음식 자동 검사 5개는 온도, 습도, 밀폐, 냉각, 정확한 만료와 곰팡이 경계, 조회 원본 보존, 시간 분할, 혼합과 분할과 소비, 다른 세계, 정책, 시간 역행, 묶음 예산 거부, 직렬화 재개, 손상, 미지원 버전을 본다.

| 검사 | 결과 |
|---|---|
| 환경 자동화 | 107/107, 경고, 실패, 미실행 0 |
| Campaign, Scenario, Playground의 음식과 새 프로세스 | 통과 |
| 기존 세션 저장, 장비 태그, 획득, 장착, 회복, 성장, 캠페인 회귀 | 통과 |

실제 월드 검사는 공통 시간을 진행하며 합치기, 분할, 컨테이너 이동, 소비, 슬롯 이동을 본다. 대상 컨테이너가 가득 차면 원본 음식 바이트가 유지되고, 알림은 양쪽 상태가 확정된 뒤 발생한다. 새 프로세스는 음식 바이트, 아이템 GUID, 세계 시각을 대조한 뒤 부패를 이어 갔다. Campaign은 세션 형식 7의 왕복과 미래 음식 시각 거부도 확인했다.
