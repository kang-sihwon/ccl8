# 통합 검증

시간 분할 정밀도, 순환 실험, 프레임 계측, 통합 Game·Server 패키지 실행을 소유한다. 상위 문서는 [자연 환경과 생태계 구현 계획](../EnvironmentPlan.md)이다.

## 시간 분할 정밀도 구현·검증

60배율에서 0.25게임초를 1세계초씩 처리해도 입력받은 두 종료 시각까지 진행한다. 서버 공통 시계의 `FKSIWorldClock::Prepare`에서 남은 게임·세계 구간이 각각 예산에 들어오는지 확인하고, 모두 들어오면 저장된 두 종료 시각을 사용한다. 기존 `Prepare`·`Commit`·`Abort` 인터페이스와 저장 형식은 유지한다. 허용 오차를 늘리거나 잔여 시간을 삭제하지 않는다.

`CCLWorldAdvance`와 각 참가자는 같은 후보 구간을 소비하며 실패하면 원본을 유지한다. 시계는 실행 중인 서버 World가 소유하는 값 객체이므로 새 UObject나 복제 수명은 추가하지 않는다. 종료 경계를 기준으로 판단하면 게임·세계 시각의 반복 덧셈 차이를 마지막 분할에서 해소할 수 있다. 대신 두 단위의 남은 구간과 예산을 함께 검사해야 한다. 고정 정수 시간으로 전환하는 방식은 저장·배율 표현 변경이 필요하므로 이 수정에는 사용하지 않는다.

`CCL.Environment.Clock.SplitAcceptedBoundaries`는 시작 세계 시각 0·86400·315360000에서 각각 200개의 입력을 15개 구간으로 처리했다. 총 9000개 구간에서 취소·재시도와 매 구간 저장·복원을 실행했고 입력 종료 시각과 정확히 일치했다. 일시정지 입력 제외와 기존 배율 0 검사도 통과했다. 실제 게임 월드에서는 온라인·연결 해제 플레이어 음식이 60배율의 15세계초를 함께 처리했다.

2026-10-10 UE 5.8.3의 로컬 작업 트리에서 `Tools/Validation/run_automation.ps1 -Filter 'CCL.' -TimeoutSeconds 300`의 144개 검사가 경고·실패·미실행 없이 통과했다. 첫 실행은 시계 수정 후, 두 번째는 계정 조회 분리까지 적용한 빌드다. 시계 구현은 `Source/KSIWorldTime/Private/KSIWorldClock.cpp:140`, 반복 검사는 `CCLWorldClockTests.cpp:206`이 소유한다. 이는 장시간 전체 월드의 처리 성능을 증명하지 않는다.

## 시계 실험의 대기·시간 소유권과 통합 검사

구역 01의 공통 시간 검사는 지형 초기화 뒤 내비게이션 준비를 기다리고 같은 대기 구간을 재시도한다. 실행 세대와 Run ID를 유지한 타이머가 대기열을 최대 16개 구간씩 나눠 진행한다. 2게임초 입력과 실패 주입은 한 번만 수행하고 남은 구간을 다음 타이머에서 재시도한다. `AcquireManualAdvance`의 단일 소유자가 자동 프레임 입력을 보류하고, 기존 대기 입력과 시험 입력을 완료한 뒤 반납한다. 완료·중지·초기화·Actor 종료가 반납 경로다. 준비 중인 내비게이션 외의 오류는 실패로 유지한다. 전체 세계를 1세계초씩 계산하므로 구역 01의 실제 시간 제한은 지형·물·눈 검사와 같은 120초다. 입력·완료 시각과 Agent 시각의 정확한 일치 판정은 유지한다.

수동 제어는 게임의 일시정지 기능과 별개다. 소유권을 가진 실험 동안 자동 세계 시간 입력을 생성하지 않으며, 기존 대기 시간은 삭제하지 않는다. 소유자는 같은 서버 World의 살아 있는 객체여야 하고 다른 객체의 반납 요청은 무시한다. 소유자의 약한 참조가 무효화되면 자동 진행을 다시 허용한다. 서버 런타임 계약은 `Source/CCL/Environment/CCLWorldSimulationSubsystem.cpp:172`에 있다.

`run_environment_smoke.ps1`은 지연·손실 옵션, 관측자 재접속, 게임·서버 실행 파일 선택을 지원한다. 각 네트워크 로그에서 요청한 에뮬레이션 설정이 적용됐는지 확인한다. 관측자 재접속은 새 클라이언트 프로세스의 세계 상태 수신·조작 권한 검증이며 저장 플레이어 신원 복원 검사가 아니다.

2026-10-10 최종 프로젝트 파일 생성과 Editor 빌드는 통과했다. 이후 변경은 구역 01의 실제 시간 제한뿐이다. 렌더링한 환경 실험은 통과했고 단일 시간 소유자·잘못된 반납·정상 재개, 초기화의 플레이어 계좌·금화 83 보존, 메뉴·차폐 조작을 포함한다. 최종 아트 검토를 완료한 결과는 아니다.

Dedicated 모드의 환경 Scenario는 80ms 지연·2% 손실에서 조작자·관측자·관측자 재접속까지 통과했다. `Saved/Tests/Environment/EnvironmentScenario-Dedicated-20261010-232811-881/result.json`은 전체 115.15초와 각 프로세스 로그를 기록한다. 서버와 세 클라이언트 실행 로그에서 `PktLag set to 80`, `PktLoss set to 2`를 확인했다. 이 실행의 서버는 Editor 서버 모드이고 클라이언트도 Editor 게임 모드다. 실제 Server 타깃·게임 패키지의 실행 결과는 [Packaging](../Packaging.md)이 소유한다.

### 통합 실행의 CPU·메모리 계측 계획

`run_environment_smoke.ps1`은 직접 시작한 프로세스만 0.5초 간격으로 관측한다. CPU 누적 시간, 작업 집합·private bytes, 운영체제가 제공하는 최대 작업 집합과 같은 관측 회차의 작업 집합 합계를 로컬 결과에 기록한다. 각 표본에 프로세스 ID·역할·실제 경과 시간을 남긴다. 종료 사이에 얻지 못한 마지막 CPU 값은 추정하지 않으며, 표본 수가 없는 프로세스는 미측정으로 표시한다. 실패한 실행도 결과와 이미 얻은 표본을 보존한다.

이는 프로세스 비용의 첫 측정이며 프레임 CPU/GPU 시간이나 네트워크 대역폭을 대신하지 않는다. 반복 실행의 각 회차는 별도 결과를 유지한다. 실제 패키지에서 기능 통과와 계측 파일 생성을 확인한 뒤 측정값을 기록한다. 패키지 빌드와 실행을 동시에 수행한 값은 성능 기준으로 사용하지 않는다.

프레임 비용은 선택적인 `-ProfileFrames` 실행으로 분리한다. 같은 실험장 맵을 자동 시험 조작 없이 실행하고, UE CSV profiler가 지정 프레임을 기록한 뒤 정상 종료한다. 렌더링 실행은 `-csvGpuStats`도 요청한다. 초기 로딩 이후의 실행 명령으로 캡처를 시작하지만, 측정 안의 초기 프레임에는 셰이더 준비·내비게이션 생성 등의 비용이 남을 수 있다. NullRHI 실행에는 GPU 측정값을 요구하지 않는다. 근거는 UE 5.8.3의 `<Engine>/Source/Runtime/Core/Private/ProfilingDebugging/CsvProfiler.cpp:1050`, `:4309`, `:5069`다. 장시간 평균뿐 아니라 프레임 원본을 보존하며, 표본이 없는 지표를 0으로 보고하지 않는다.

CSV 요약은 요청한 프레임 수가 실제 파일의 표본 수와 같은지 확인한 뒤 첫 30프레임을 제외한다. 30프레임 이하의 짧은 진단은 마지막 한 프레임을 남긴다. 평균·중앙값·95/99백분위·최댓값과 원본을 보존하며, 백분위는 nearest-rank 방식을 쓴다. 월드의 완료 세계 시각·대기 게임 시간·아직 입력되지 못한 게임 시간도 초 단위의 별도 필드로 남긴다. CSV 출력의 정밀도는 저장·시간 경계 검증에 쓰지 않는다. `PROFILE PASS`는 계측 완료를 뜻하며 기능 검사나 프레임 예산 통과를 뜻하지 않는다.

## 구역 09 순환 실험 설계

구역 09는 서버 Director가 소유하는 단계 실행기로 연결한다. 별도의 16×16 표면을 공통 월드 시계·저장·표면 복제·표현에 등록하고, 경사 상단 네 열에 시험 적설을 공급한다. 건조한 시작 상태에서 적설, 접촉 압축, 융해·낮은 쪽으로 유출·진흙, 결빙, 건조를 두 번 반복한다. 각 전환에서 보존 원장을 검사하고 마지막에는 표면 바이트의 저장·복원 일치도 검사한다. 입력은 자연 기후가 아닌 명시적인 시험 조건이다.

실행 상태·입력 원복은 Director의 기존 Run ID·Generation·중지·초기화 수명을 따른다. 진행 중 다른 조작은 기존 권한 검사로 거부한다. 표면 상태는 시뮬레이션에 남고, 시험 종료·중지 시 원래 강수·기온 입력을 복구한다. 새로운 격자는 현재 실험장과 과거 저장에 없을 때만 추가한다. 매 회차 앞의 건조는 기존 물을 삭제하지 않고 증발 원장으로 처리하므로 재실행에서도 질량의 출처를 추적할 수 있다.

단일 구역에서 반복을 관찰할 수 있지만 경사 바닥은 시험 자료다. 실제 영구 지형의 새 수로 편집은 구역 05의 충돌·표면 교체 경로를 이어서 검사해야 한다. 이 순환 실험만으로 단계 9 전체, 자동 자연 기후 순환이나 최종 시각 품질을 완료 처리하지 않는다.

## 집계 생태와 통합 규모 검증 계획

이 결과는 후속 개별 행동의 기아 시간 정밀화와 메뉴 표시 보완 전의 빌드다. 값 모델의 규모·새 프로세스 공간 진행·지연과 손실 결과는 [집계 생물의 영양 상태](../EnvironmentNutrition.md)가 소유한다. 최종 빌드와 패키지 실행 결과는 아래 순환 실험 수정과 통합 패키지 절을 따른다.

### 순환 실험의 게임 시간과 세계 시간

Windows Game의 Listen 실행에서 구역 09의 융해 뒤 하류 물이 0이어서 검사가 실패했다. 물질 수지는 0 오차였고 적설은 모두 녹았다. 개인 세션, 환경 새 프로세스 재개와 맵 왕복은 같은 패키지에서 통과했다.

표면 융해·침투는 세계 시간, 이웃 유량은 게임 시간으로 계산한다. 기존 실험은 모든 단계의 종료를 세계 시간만으로 판단했다. 60배율에서 융해 단계의 60세계초는 유량에 1게임초만 제공한다. 융해·유출 단계는 60세계초와 10게임초를 모두 채운 뒤 판정하도록 바꿨다. 하류 수량·진흙·물질 수지의 기존 임계값은 유지한다. 단계 로그에는 실제 두 경과 시간을 함께 기록한다. 10게임초는 실험장 관찰 입력이며 실제 수문학의 보장 시간은 아니다.

수정 후 프로젝트 생성·Editor 빌드를 통과했다. Editor Listen의 80ms 지연·2% 손실·관측자 재접속도 통과했다. 중지 후 재시작과 실험 재실행의 두 회차를 모두 확인했고, 첫 융해 단계의 하류 물은 0.639996784m³, 기록된 물질 수지 오차는 0이었다.

### 통합 Game·Server 패키지 실행

구역 09 관찰 시간까지 수정한 Game·Server 패키지를 각각 생성하고 에디터 없이 실행했다. 생성 로그·실행 파일 경로와 세션·세계 저장 재개·맵 왕복은 [패키징의 최신 결과](../Packaging/Records.md#집계-영양-상태를-포함한-패키지)를 따른다. 아래 세 검사는 최종 패키지의 결과다.

| 실행 | 결과 | 원본 폴더 |
|---|---|---|
| Game Listen | 환경 전체·80ms 지연·2% 손실·관측자 재접속 통과 | |
| 실제 Server와 Game 조작자·관측자 | 환경 전체·80ms 지연·2% 손실·관측자 재접속 통과 | |
| Game Playground 렌더링 | 환경 전체·실험 재실행 통과, 안내·배치·문 캡처 확인 | |

Dedicated의 각 접속 관측 구간은 1.88초에서 2.03초다. 이 구간에서 클라이언트 수신은 평균 약 24.7-26.5kB/s, 송신은 약 2.1-3.2kB/s였다. 접속 직후 짧은 검사 구간의 총 전송량이며, 생태 상태만의 대역폭이나 장시간 정상 상태 평균은 아니다. 같은 PC의 로컬 지연·손실 주입이며 인터넷·NAT 환경은 검사하지 않았다.

### 프레임 계측의 미완료 범위

18,000프레임을 요청한 대화 중단 시점까지 CSV 일부만 남았고 완료 결과 JSON과 정상 종료 기록이 없다. 약 5분의 완료 계측이나 장시간 성능 통과로 계산하지 않는다.

문서 정리 때 다시 실행한 600프레임 요청에 CSV의 수치 행이 601개여서 요약 검사가 실패했다. `result.json`은 `passed=false`와 `Frame profile validation failed`를 기록한다. 원본 CSV와 로그를 같은 폴더에 보존했다. 요청 프레임 수와 실제 CSV 행의 경계가 달라진 원인은 아직 확인하지 않았다. 표본을 임의로 제거하거나 기대 개수를 바꿔 통과로 처리하지 않는다.

다음 계측은 패키지의 CSV 시작·종료 프레임과 요약기의 행 판정을 먼저 대조한 뒤 다시 수행한다. 전체 월드의 장시간 CPU·GPU·메모리 비용은 미검증으로 유지한다. 이 상태는 위의 자동화·패키지 기능 검사 통과와 구분한다.
