## 집계 생태와 통합 규모

단계 8의 집계 에너지·기아는 [집계 생물의 영양 상태](Ecology/Nutrition.md)에 구현과 검증을 기록했다. 단계 9 검증에는 네 매체의 실제 공간 이동·저장 복원에 80ms 지연과 2% 패킷 손실을 주입하고 적용 로그를 확인하는 항목을 추가한다. 구역 06의 집계 관측은 서버·첫 접속자·늦은 접속자가 같은 값을 읽어야 한다.

규모 검사는 100개 개체군·100만 집계 개체를 세계 시간 3600초 동안 진행하며 60회 저장·복원한다. 이는 100만 Actor의 비용을 측정하는 검사가 아니다. 실제 실험장에서는 별도의 프레임 기록으로 진행 지연·CPU·메모리를 측정한다. Windows Game·Server 패키지는 에디터 결과와 분리하고, 최종 코드의 생성·빌드·쿠킹·실행을 각각 확인한다. 식생·피식자 먹이 연결, Agent 생애 소유권 이전, 개체 간 회피와 최종 아트·PCG의 미완료 상태는 이 검증으로 대체하지 않는다.

## 집계 영양 상태 변경 후 통합 검사

경비·보스 ID와 보급품 배치 수정 위에 집계 영양 상태와 생태 본문 형식 6을 더한 빌드에서 개인 세션 저장, 새 프로세스 재개, 승리 복원, Scenario 환경 세계의 새 프로세스 재개, Playground 환경 세계와 지형의 맵 왕복이 통과했다. 개별 행동의 기아 시간 정밀화와 메뉴 표시 보완 전 빌드다.

## 통합 Game·Server 패키지 실행

구역 09 관찰 시간까지 수정한 Game·Server 패키지를 각각 생성하고 에디터 없이 실행했다. 생성 로그·실행 파일 경로와 세션·세계 저장 재개·맵 왕복은 [패키징의 최신 결과](../Packaging/Records.md#집계-영양-상태를-포함한-패키지)를 따른다. 아래 세 검사는 최종 패키지의 결과다.

| 실행 | 결과 |
|---|---|
| Game Listen | 환경 전체·80ms 지연·2% 손실·관측자 재접속 통과 |
| 실제 Server와 Game 조작자·관측자 | 환경 전체·80ms 지연·2% 손실·관측자 재접속 통과 |
| Game Playground 렌더링 | 환경 전체·실험 재실행 통과, 안내·배치·문 캡처 확인 |

Dedicated의 각 접속 관측 구간은 1.88초에서 2.03초다. 이 구간에서 클라이언트 수신은 평균 약 24.7-26.5kB/s, 송신은 약 2.1-3.2kB/s였다. 접속 직후 짧은 검사 구간의 총 전송량이며, 생태 상태만의 대역폭이나 장시간 정상 상태 평균은 아니다. 같은 PC의 로컬 지연·손실 주입이며 인터넷·NAT 환경은 검사하지 않았다.

## 프레임 계측의 미완료 범위

18,000프레임을 요청한 대화 중단 시점까지 CSV 일부만 남았고 완료 결과 JSON과 정상 종료 기록이 없다. 약 5분의 완료 계측이나 장시간 성능 통과로 계산하지 않는다.

재실행한 600프레임 요청에서 CSV의 수치 행이 601개여서 요약 검사가 실패했다. 결과는 `passed=false`와 `Frame profile validation failed`로 남았다. 요청 프레임 수와 실제 CSV 행의 경계가 달라진 원인은 아직 확인하지 않았다. 표본을 임의로 제거하거나 기대 개수를 바꿔 통과로 처리하지 않는다.

다음 계측은 패키지의 CSV 시작·종료 프레임과 요약기의 행 판정을 먼저 대조한 뒤 다시 수행한다. 전체 월드의 장시간 CPU·GPU·메모리 비용은 미검증으로 유지한다. 이 상태는 위의 자동화·패키지 기능 검사 통과와 구분한다.
