# 지형 확인과 검증

구역 05를 직접 확인하거나 지형 검사 결과와 규모 비용을 볼 때 읽는다. 실행 절차는 `ccl8-verify`가 소유한다. 커서 편집, 저장 안내, 복제 송신량 보완은 [실험실 보완 검증](../IntegratedLab/Observation.md#실험실-보완-검증)에 있다.

## 직접 확인

조작 좌표·브러시 크기는 `Source/CCL/Environment/CCLExperimentTerrain.cpp`, 미리보기는 같은 폴더의 `CCLExperimentPlayerController.cpp`가 구현한다. 아래 수치는 현재 실험 지역의 설정이며 범용 지형 크기 제한이 아니다.

1. 두 환경 실험장 중 하나를 실행하고 F7 메뉴에서 구역 05를 골라 **선택 구역으로 이동**한다.
2. **구덩이 굴착**, **흙 쌓기**, **수로 파기** 중 하나를 선택한다. 메뉴 오른쪽 바닥에서 화살표와 구형 범위를 확인하고 클릭한다.
3. 청록색 지역 테두리 안에서 유효한 범위를 고른다. 빨간 범위는 경계·보호 구역·준비 상태 등을 확인해야 한다는 뜻이다. 거부 이유는 메뉴 하단에 표시한다.
4. **수로 파기**는 얕은 구형 굴착이다. 인접 위치를 겹쳐 클릭해 홈을 연결한다. 두 끝점을 고르는 자동 수로 도구는 아직 없다. 물은 연결된 표면 모델이 새 지표에 맞춰 계산한다.
5. 우클릭, 다른 구역 선택 또는 메뉴 닫기로 도구를 취소한다. **자동 검사**는 기존 고정 위치의 굴착·충돌·경로·보호 검사를 실행한다.
6. **실험 저장** 후 추가로 편집하고 **저장 불러오기**를 누른다. 저장 시각·지형 리비전과 복원 완료를 확인한다. 충돌 준비와 복원 중에는 캐릭터를 안전 지점으로 옮긴다.

구역 05는 가로세로 16m, 높이 8m이며 초기 표면은 기존 바닥보다 4m 높다. 수동 굴착·성토 반지름은 1m다. 수로는 반지름 0.8m, 클릭 지점보다 중심을 0.35m 높여 얕게 판다. 현재 샘플 간격에서 보간용 다섯 샘플인 2.5m의 여유 범위도 지역 안에 있어야 한다. 테두리 바로 옆이나 깊게 판 바닥은 편집을 거부할 수 있다.

서버는 조작 권한·실행 세대·게시 순번에 더해 좌표의 유효성, 지역 범위와 실제 바닥 충돌을 검사한다. 미리보기가 보인다는 이유만으로 편집을 확정하지 않는다. 저장은 시계·천체 입력·문 상태·Agent·지형·눈·물을 같은 완료 세대로 보관한다.

## 검증

2026-10-09 단계 완료 시점의 기록이다. 프로젝트 파일 생성과 `CCLEditor Win64 Development` 빌드가 성공했고, CCL 환경 자동 검사 42개가 경고·실패·미실행 0으로 성공했다.

충돌·점유·실패·취소·복원·경로 검사가 통과했다. Dedicated와 클라이언트 2개, Listen과 클라이언트 2개에서 완료 응답 지연 후 재전송, 중복 후보 유지, 동순번 내용 충돌 거부, 전체·변경량 전송과 늦은 접속이 통과했다. 맵 왕복은 Standalone에서 두 실험장 사이 4회 전환, 도메인별 세계·지형 복원과 준비 중 전환 거부가 통과했고, Listen과 Dedicated는 클라이언트 1개와 4회 전환 뒤 최신 충돌 준비 응답까지 통과했다. 격리 실험장은 디스크 저장과 새 프로세스 복원에서 굴착·성토·수로·초기화·취소와 세계·지형 복원이 통과했고, 격리·종합 실험장 모두 실제 Slate 시작 버튼과 재실행 취소, 복원이 통과했다. 기존 세계 저장 재시작과 생활 Agent의 행동·저장·Actor 재구성도 통과했다. 화면에서 한국어 버튼과 상태가 잘리지 않고 굴착과 성토가 표시되는지 확인했다.

표면 자동 검사는 같은 XY의 지상·천장·동굴 바닥, 재질, 청크 순서 독립적인 ID, 오래된 질의와 결과 예산을 확인한다. 세대 저장 자동 검사는 최신 파일 손상, 완료 표식 누락과 세대 혼합 거부, 이전 완료 세대 선택을 확인한다. 지형 시나리오 검사는 비동기 복원 중 시계의 자동 Tick을 끄고 명시적으로 누적한 시간·대기 입력·Agent와 실제 충돌을 비교한다.

왕복 검사는 자동 시계 Tick을 끄고 서로 다른 완료 시간과 대기 입력을 넣는다. 저장된 Agent의 필드 전체와 기존 경제 기록, 지형 바이트, 충돌 높이와 새 Epoch를 비교한다. 맵 로드 후 새 PlayerState가 개설한 계좌만 현재 접속자 ID와 미사용 초기 잔액으로 따로 검사한다. 그 밖의 추가 기록이나 기존 기록의 변화는 허용하지 않는다.

복제 재시도 검사는 최종 준비 응답 하나를 서버에서 무시하고 해당 전송의 제한 시간을 넘긴다. 정상 시간 초과 분기, 변경량 기준 불일치에 따른 전체 전송, 서버 준비 상태의 회복을 확인한다. 같은 순번을 준비 중이나 적용 후 다시 처리해도 후보 작업과 Epoch가 바뀌지 않는지 검사한다. 조건을 주입한 재현이며 실제 패킷 손실 측정은 아니다.

대규모 지역의 질의 시간, 다수 접속자의 메모리와 전송량, 실제 네트워크 손실, 패키지 실행과 아트 품질은 별도 측정이 필요하다. 현재 표면은 기본 재질을 사용한다.

## 지형 질의 비용

2026-10-10 프레임 예비 계측에서 `FKSITerrainSurface::QuerySurfaces`는 질의 선분이 청크와 만나지 않아도 모든 삼각형을 검사했다. 그래서 불변 지형 게시 객체가 청크별 로컬 경계를 한 번 계산하고, UE의 `FMath::LineBoxIntersection`으로 선분과 만나지 않는 청크를 제외한다. 경계는 기존 삼각형 판정의 작은 가장자리 오차를 포함하도록 확장한다. 교차 후보의 삼각형 판정, 정렬, 중복 제거, 결과 상한은 유지한다. 경계는 저장과 복제 상태에 넣지 않고, 충돌과 같은 세대의 제공자가 교체될 때 새로 만든다.

청크마다 경계 저장 비용과 질의당 경계 검사 비용이 생긴다. 청크 밖을 지나는 강수, 일조, 바람 질의에는 유리하지만, 청크 안의 모든 삼각형을 지나는 질의까지 빠르게 만들지는 않는다. 그 경우의 공간 트리는 별도 측정 후 판단한다.

`CCL.Environment.Terrain.SurfaceChunkBounds`가 평행축, 양방향, 선분 길이 제한, 청크 꼭짓점과 가장자리, 작은 허용 오차, 회전과 이동, 빈 청크, 다층 결과를 검사하며 2026-10-11 CCL 자동 검사 145/145에 포함돼 통과했다. 600프레임 계측의 범위는 [환경 통합 기록](../Integration/Profiling.md#지형-질의-수정-후-프레임-계측)과 [패키지 기록](../../Packaging/Records.md#server-실행-수정과-실제-네트워크-통과)을 따른다.
