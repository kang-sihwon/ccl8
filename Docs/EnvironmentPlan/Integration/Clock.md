# 시계의 시간 분할과 소유권

공통 시계의 구간 분할, 수동 진행 소유권, 구역 01 검사를 바꿀 때 읽는다.

## 시간 분할 정밀도 구현·검증

60배율에서 0.25게임초를 1세계초씩 처리해도 입력받은 두 종료 시각까지 진행한다. 서버 공통 시계의 `FKSIWorldClock::Prepare`에서 남은 게임·세계 구간이 각각 예산에 들어오는지 확인하고, 모두 들어오면 저장된 두 종료 시각을 사용한다. 기존 `Prepare`·`Commit`·`Abort` 인터페이스와 저장 형식은 유지한다. 허용 오차를 늘리거나 잔여 시간을 삭제하지 않는다.

`CCLWorldAdvance`와 각 참가자는 같은 후보 구간을 소비하며 실패하면 원본을 유지한다. 시계는 실행 중인 서버 World가 소유하는 값 객체이므로 새 UObject나 복제 수명은 추가하지 않는다. 종료 경계를 기준으로 판단하면 게임·세계 시각의 반복 덧셈 차이를 마지막 분할에서 해소할 수 있다. 대신 두 단위의 남은 구간과 예산을 함께 검사해야 한다. 고정 정수 시간으로 전환하는 방식은 저장·배율 표현 변경이 필요하므로 이 수정에는 사용하지 않는다.

`CCL.Environment.Clock.SplitAcceptedBoundaries`는 시작 세계 시각 0·86400·315360000에서 각각 200개의 입력을 15개 구간으로 처리했다. 총 9000개 구간에서 취소·재시도와 매 구간 저장·복원을 실행했고 입력 종료 시각과 정확히 일치했다. 일시정지 입력 제외와 기존 배율 0 검사도 통과했다. 실제 게임 월드에서는 온라인·연결 해제 플레이어 음식이 60배율의 15세계초를 함께 처리했다.

2026-10-10 UE 5.8.3에서 CCL 자동 검사 144개가 경고·실패·미실행 없이 통과했다. 시계 구현은 `FKSIWorldClock::Prepare`, 반복 검사는 `CCLWorldClockTests.cpp`가 소유한다. 장시간 전체 월드의 처리 성능을 증명하지는 않는다.

## 시계 실험의 대기·시간 소유권과 통합 검사

구역 01의 공통 시간 검사는 지형 초기화 뒤 내비게이션 준비를 기다리고 같은 대기 구간을 재시도한다. 실행 세대와 Run ID를 유지한 타이머가 대기열을 최대 16개 구간씩 나눠 진행한다. 2게임초 입력과 실패 주입은 한 번만 수행하고 남은 구간을 다음 타이머에서 재시도한다. `AcquireManualAdvance`의 단일 소유자가 자동 프레임 입력을 보류하고, 기존 대기 입력과 시험 입력을 완료한 뒤 반납한다. 완료·중지·초기화·Actor 종료가 반납 경로다. 준비 중인 내비게이션 외의 오류는 실패로 유지한다. 전체 세계를 1세계초씩 계산하므로 구역 01의 실제 시간 제한은 지형·물·눈 검사와 같은 120초다. 입력·완료 시각과 Agent 시각의 정확한 일치 판정은 유지한다.

수동 제어는 게임의 일시정지 기능과 별개다. 소유권을 가진 실험 동안 자동 세계 시간 입력을 생성하지 않으며, 기존 대기 시간은 삭제하지 않는다. 소유자는 같은 서버 World의 살아 있는 객체여야 하고 다른 객체의 반납 요청은 무시한다. 소유자의 약한 참조가 무효화되면 자동 진행을 다시 허용한다. 서버 런타임 계약은 `UCCLWorldSimulationSubsystem::AcquireManualAdvance`가 소유한다.

`run_environment_smoke.ps1`은 지연·손실 옵션, 관측자 재접속, 게임·서버 실행 파일 선택을 지원한다. 각 네트워크 로그에서 요청한 에뮬레이션 설정이 적용됐는지 확인한다. 관측자 재접속은 새 클라이언트 프로세스의 세계 상태 수신·조작 권한 검증이며 저장 플레이어 신원 복원 검사가 아니다.

2026-10-10 최종 프로젝트 파일 생성과 Editor 빌드는 통과했다. 이후 변경은 구역 01의 실제 시간 제한뿐이다. 렌더링한 환경 실험은 통과했고 단일 시간 소유자·잘못된 반납·정상 재개, 초기화의 플레이어 계좌·금화 83 보존, 메뉴·차폐 조작을 포함한다. 최종 아트 검토를 완료한 결과는 아니다.

Dedicated 모드의 환경 Scenario는 80ms 지연, 2% 손실에서 조작자, 관측자, 관측자 재접속까지 통과했고 전체 115.15초가 걸렸다. 서버와 세 클라이언트 로그에서 `PktLag set to 80`, `PktLoss set to 2`를 확인했다. 이 실행은 Editor 서버 모드와 Editor 게임 모드다. 실제 Server 타깃과 게임 패키지의 결과는 [Packaging](../../Packaging.md)이 소유한다.
