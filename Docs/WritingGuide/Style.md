# 문장과 표기

상위 문서는 [ccl8 문서 작성 가이드](../WritingGuide.md)다.

## 제목과 문단

- 제목은 찾기 쉬운 짧은 명사구로 쓴다.
- 본문은 주어와 서술어가 분명한 완결문으로 쓴다. 관계를 명사 나열이나 화살표·등호로 대신하지 않는다.
- 한 문단은 주제 하나를 다룬다. 배경, 판단, 근거, 후속 조치가 다른 주제면 문단을 나눈다.
- 같은 설명은 소유 문서 한 곳에만 쓴다. 다른 문서는 그 문서를 연결하고 필요한 요약만 둔다.
- 다른 문서가 링크하는 제목은 앵커가 바뀌므로 고치기 전에 링크를 찾아 함께 바꾼다.

## 목록과 표

- 절차 목록의 각 단계는 누가 무엇을 하는지 드러나는 문장으로 쓴다.
- 상태, 이름, 수치, 짧은 분류값은 명사구로 적는다.
- 표의 한 셀에는 판단 하나를 둔다. 길어지면 표 아래에서 설명한다.
- 코드, 명령, 경로, URL, 해시는 인라인 코드나 코드 블록으로 쓴다.
- 클래스 다이어그램은 Mermaid `classDiagram` 코드 블록으로 쓴다.

## 용어와 표기

- 코드, API, 클래스명, 파일명, 명령, 상태값, 스키마 키, 문서 ID, 작품 고유명사는 원래 표기를 유지한다.
- 여러 문서에 걸친 시스템·제작 용어는 [GLOSSARY](../../GLOSSARY.md), 서사 용어는 [서사 용어](../Narrative/Glossary.md)가 소유한다. 그 밖의 프로젝트 용어는 처음 등장할 때 뜻을 설명하고 문서 안에서 같은 표기를 쓴다.
- ID를 처음 쓸 때는 `세계의 공간 구성을 정하는 항목(AX-05)`처럼 뜻을 함께 쓴다.
- 일반 문장의 영어는 한국어로 쓴다. `claim`은 주장, `coverage`는 확인 범위, `mechanism`은 작동 방식이나 구조, `cutoff`는 확인 기준일, `batch`는 작업 묶음이나 차수, `downstream`은 후속 항목이다. `gameplay`는 조작과 규칙이면 게임플레이, 진행 과정이면 게임 진행이다.
- 절차의 상태값이나 필드 이름인 영어(`canon`, `writer`, `reviewer`, `PASS` 등)는 그대로 둔다.
- 범위는 `1-3`, `단계 4-13`처럼 하이픈, 근사값은 `약 5MB`, 이름 접미사는 `...Rad`로 쓴다. 물결표(`~`)는 GitHub가 취소선으로 해석해 문단이 깨지므로 쓰지 않는다. VS Code 미리보기는 정상으로 보이므로 판정 기준은 GitHub 렌더링이다.
- 문장 부호는 쉼표, 마침표, 괄호를 쓴다. em dash는 결정 파일의 제목 형식(`# 날짜 — 결정 N: 제목`)에만 쓴다.

## 보존해야 하는 기록

- 직접 인용문, 실행한 명령, 실제로 쓴 프롬프트, URL, SHA-256, 출처 원문은 표현을 고치지 않는다.
- 과거 결정과 검토 기록의 날짜, 판정, 불확실성은 유지한다. 문장만 읽기 쉽게 고칠 수 있다.
- 현행 경로는 최신값으로 바꾸고, 과거 이동 기록은 날짜와 함께 남긴다.
