# 제작 로드맵

확정 작업 순서의 단계 1-7은 기능 프로토타입으로 구현과 검증을 마쳤다. 2026-10-07까지 UE 5.9.0 노트북에서 검증했고, 2026-10-11 UE 5.8.3에서 [다시 검증](QA/FullReviewReverification-2026-10-11.md)했다. 남은 것은 사용자의 실제 플레이로 조작감, 콘텐츠 분량, 아트와 밸런스를 검토하는 일과 최종 품질 작업이며, 이번 기능 검증으로 전체 제작 기간이 완료된 것은 아니다. 지금 진행 중인 작업과 다음 작업 후보는 [진행 중인 작업](Work/README.md)이 소유한다.

이 문서는 작업 순서, 단계별 범위, 일정 초안을 소유한다. 작업 순서는 2026-10-05 사용자가 승인한 [결정 3](decisions/0003-multiplayer-first-order.md)을 따른다. 제작 기간은 [Direction](Direction.md), 단계 제출 절차는 [DeliveryPlan](DeliveryPlan.md)이 소유한다. 범위를 넓힌 자연 환경 작업은 [EnvironmentPlan](EnvironmentPlan.md)이 따로 소유한다.

## 확정 작업 순서

| 순서 | 작업 범위 | 완료 기준 | 상태 | 근거 문서 |
|---|---|---|---|---|
| 1 | 멀티플레이 기본 흐름: 스폰, 이동·카메라, 사망·재도전 | 접속한 플레이어가 각자 캐릭터를 조작하고 사망 후 재도전할 수 있음 | 구현·자동 검증·Standalone 수동 확인 완료 | [MultiplayerFoundation](MultiplayerFoundation.md) |
| 2 | 일반 몹 한 종류와 최소 전투: 무기·능력치·공격·방어·피격 | 일반 몹과의 전투가 성립하고 서버와 클라이언트에서 결과가 일치함 | UE 5.9 에셋 생성·빌드·전투 5개·이동 4개 구성 통과, 화면 6개 확인 | [CombatFoundation](CombatFoundation.md) |
| 3 | 보스 초안과 승리·종료 조건 | 마을부터 일반 몹, 보스 전투와 승리·종료까지 이어짐 | 구현·빌드·AI 접근·네트워크 진행·늦은 접속·화면 확인 완료 | [CampaignFoundation](CampaignFoundation.md) |
| 4 | 인벤토리·장비·능력치·스킬 기능과 UI | 아이템 획득·장착과 스킬 포인트 사용·습득 결과가 전투에 반영됨 | 구현·빌드·네트워크·재스폰·화면 검증 완료 | [ProgressionFoundation](ProgressionFoundation.md) |
| 5 | 콘텐츠 확장: 일반 몹·보스 보강, NPC·상점·퀘스트·튜토리얼 | 추가한 콘텐츠와 기능이 전체 플레이 흐름에 연결됨 | 구현·빌드·거래·보상·패턴·네트워크·NPC 화면 검증 완료 | [ContentFoundation](ContentFoundation.md) |
| 6 | 시작 화면, 방 생성·접속 UI, 세이브·로드·설정 | 배경·시작·종료 화면에서 게임에 진입하고 방 생성·접속과 저장·불러오기·설정을 사용할 수 있음 | 메뉴·저장 복원·접속·실패 처리·빌드·화면 검증 완료 | [SessionFoundation](SessionFoundation.md) |
| 7 | 패키징과 전체 흐름 검증 | 패키징한 게임에서 시작부터 접속, 전투, 재도전과 종료까지 검증함 | Windows Development 패키징·Standalone·Listen·저장 복원·회귀·화면 확인 완료 | [Packaging](Packaging.md) |

평소에는 Standalone으로 테스트 맵에 진입하고 Dedicated Server와 Listen Server 양쪽에서 멀티플레이를 검증한다. 근거는 [결정 5](decisions/0005-run-modes-and-respawn.md)다. PIE(Play In Editor)의 실행 설정과 별도 프로세스 실행을 사용할 수 있다. 패키징 실행도 순서 1-3 사이에 확인해 에디터 밖에서 발생하는 문제를 점검한다.

순서 3의 보스는 전체 흐름을 연결하는 첫 버전이다. 일반 몹 종류 추가와 일반 몹·보스의 패턴·연출 보강은 순서 5에서 진행한다. 전투에 필요한 최소 능력치는 순서 2에 포함하고, 순서 4의 기능과 UI는 작은 단위로 추가한다.

## 단계별 구현 범위

단계 3-7의 범위는 기존 기획을 실행 가능한 단위로 나눈 구현 초안이다. 최종 아트, 조작감과 밸런스의 사용자 검토를 대신하지 않는다.

| 단계 | 구현 범위 | 검사할 결과 |
|---|---|---|
| 3 | 마을 출발점, 일반 적 구간, 보스 초안과 서버 권위의 승리 상태 | 보스 사망 후 모든 접속자에게 승리 표시, 개별 재도전, 새 접속자의 진행 상태 일치 |
| 4 | 정의 데이터와 인스턴스를 분리한 인벤토리, 장비, 성장·스킬과 UI | 획득·장착·소비·스킬 습득의 서버 검증, 중복 지급·비용 초과 방지, 재스폰 후 상태 유지 |
| 5 | 일반 적의 행동 차이, 보스 패턴 보강, 마을 NPC·상점·퀘스트·튜토리얼 | 콘텐츠가 출발부터 보스 격파까지 연결되고 보상·구매를 중복 처리하지 않음 |
| 6 | 시작·방 생성·접속·종료 UI, 저장·불러오기와 설정 | 입력 검증, 접속 실패 표시, 저장 버전·손상 처리, 로드 후 진행과 성장 상태 복원 |
| 7 | Windows 패키징과 전체 실행 검사 | 에디터 외부 실행, 시작·접속·전투·재도전·저장·종료와 필요한 콘텐츠의 포함 |

공통 시스템은 특정 장르의 플레이어·무기·스태미나를 필수로 요구하지 않는다. 서버가 진행과 아이템 변경을 확정하고 UI는 조회와 요청만 담당한다. 성장 상태는 PlayerState 수명, 월드 진행은 GameState 수명, 로컬 메뉴와 저장 요청은 GameInstance 수명을 기준으로 설계한다. 각 단계의 인터페이스와 대안은 해당 사양서에 구현 전에 기록한다.

## 월별 배분 초안

아래 배분은 AI가 제안한 일정 초안이다. 실제 작업은 위의 확정 순서를 따르며, 착수일·제출일·에셋 확보 상황과 멀티플레이 세부 요구를 확인한 뒤 월별 배분을 다시 산정한다. 현재 배분은 납기 약속으로 사용하지 않는다. 착수일이 정해지지 않은 후보라 구간별 진행 상태는 적지 않고, 진행은 위 확정 작업 순서의 상태가 소유한다.

| 구간 | AI 작업 | 사용자 검토 대상 | 완료 증거 |
|---|---|---|---|
| 첫 달 | 기획·아트 초안, 멀티플레이 기본 흐름과 최소 전투 | 접속·재도전 흐름, 전투 방향과 조작감, 대표 룩 | 멀티플레이에서 첫 전투와 재도전이 가능한 실행 결과 |
| 두 번째 달 | 보스까지의 흐름, 성장 기능과 콘텐츠 확장 | 성장 기능, 몹별 차이, 보스까지의 흐름과 분량 | 마을부터 보스까지 연결되고 성장 기능과 콘텐츠를 사용할 수 있는 실행 결과 |
| 세 번째 달 | 시작·접속 UI, 세이브·로드·설정, 전투·아트·소리 조정과 최종 패키징 | 전체 플레이와 제출 결과물 | 합의한 환경에서 실행되는 검토용 빌드 |
| 추가 기간이 확보되는 경우 | 결함 수정, 가독성·성능·연출 보완 | 남은 결함과 완성도 | 새 필수 기능 없이 기존 흐름의 품질 개선 |

CCL 지원은 사용자 설명상 3개월이므로 필수 콘텐츠를 세 번째 달 안에 마치는 계획을 제안한다. 추가 기간은 아직 확보되지 않았고, 사용 가능 여부는 별도로 확인한다. 학습·힌트 훈련은 사용자 요청 때만 편성하며 제작의 선행 조건으로 삼지 않는다.
