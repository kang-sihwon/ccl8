# 제작 로드맵

멀티플레이 기본 흐름부터 구현하고 일반 몹, 보스, 성장 기능과 콘텐츠를 차례로 연결한다. 시작 화면은 후반에 만든다. 작업 순서는 2026-10-05 사용자가 승인한 [결정 3](DesignLog.md)을 따른다. 제작 기간은 [Direction](Direction.md)이 소유한다.

## 확정 작업 순서

| 순서 | 작업 범위 | 완료 기준 | 상태 |
|---|---|---|---|
| 1 | 멀티플레이 기본 흐름: 스폰, 이동·카메라, 사망·재도전 | 접속한 플레이어가 각자 캐릭터를 조작하고 사망 후 재도전할 수 있음 | 구현·자동 검증·Standalone 수동 확인 완료 |
| 2 | 일반 몹 한 종류와 최소 전투: 무기·능력치·공격·방어·피격 | 일반 몹과의 전투가 성립하고 서버와 클라이언트에서 결과가 일치함 | 전투 코드 작성·전체 빌드·클래스 로드 검사 통과, 에셋 생성·전투 검증 대기 |
| 3 | 보스 초안과 승리·종료 조건 | 마을부터 일반 몹, 보스 전투와 승리·종료까지 이어짐 | 미착수 |
| 4 | 인벤토리·장비·능력치·스킬 기능과 UI | 아이템 획득·장착과 스킬 포인트 사용·습득 결과가 전투에 반영됨 | 미착수 |
| 5 | 콘텐츠 확장: 일반 몹·보스 보강, NPC·상점·퀘스트·튜토리얼 | 추가한 콘텐츠와 기능이 전체 플레이 흐름에 연결됨 | 미착수 |
| 6 | 시작 화면, 방 생성·접속 UI, 세이브·로드·설정 | 배경·시작·종료 화면에서 게임에 진입하고 방 생성·접속과 저장·불러오기·설정을 사용할 수 있음 | 미착수 |
| 7 | 패키징과 전체 흐름 검증 | 패키징한 게임에서 시작부터 접속, 전투, 재도전과 종료까지 검증함 | 미착수 |

평소에는 Standalone으로 테스트 맵에 진입하고 Dedicated Server와 Listen Server 양쪽에서 멀티플레이를 검증한다. 근거는 [결정 5](DesignLog.md)다. PIE(Play In Editor)의 실행 설정과 별도 프로세스 실행을 사용할 수 있다. 패키징 실행도 순서 1-3 사이에 확인해 에디터 밖에서 발생하는 문제를 점검한다.

순서 3의 보스는 전체 흐름을 연결하는 첫 버전이다. 일반 몹 종류 추가와 일반 몹·보스의 패턴·연출 보강은 순서 5에서 진행한다. 전투에 필요한 최소 능력치는 순서 2에 포함하고, 순서 4의 기능과 UI는 작은 단위로 추가한다.

## 월별 배분 초안

아래 배분은 AI가 제안한 일정 초안이다. 실제 작업은 위의 확정 순서를 따르며, 착수일·제출일·에셋 확보 상황과 멀티플레이 세부 요구를 확인한 뒤 월별 배분을 다시 산정한다. 현재 배분은 납기 약속으로 사용하지 않는다.

| 구간 | AI 작업 | 사용자 검토 대상 | 완료 증거 | 상태 |
|---|---|---|---|---|
| 첫 달 | 기획·아트 초안, 멀티플레이 기본 흐름과 최소 전투 | 접속·재도전 흐름, 전투 방향과 조작감, 대표 룩 | 멀티플레이에서 첫 전투와 재도전이 가능한 실행 결과 | 미착수 |
| 두 번째 달 | 보스까지의 흐름, 성장 기능과 콘텐츠 확장 | 성장 기능, 몹별 차이, 보스까지의 흐름과 분량 | 마을부터 보스까지 연결되고 성장 기능과 콘텐츠를 사용할 수 있는 실행 결과 | 미착수 |
| 세 번째 달 | 시작·접속 UI, 세이브·로드·설정, 전투·아트·소리 조정과 최종 패키징 | 전체 플레이와 제출 결과물 | 합의한 환경에서 실행되는 검토용 빌드 | 미착수 |
| 추가 기간이 확보되는 경우 | 결함 수정, 가독성·성능·연출 보완 | 남은 결함과 완성도 | 새 필수 기능 없이 기존 흐름의 품질 개선 | 미확보 |

CCL 지원은 사용자 설명상 3개월이므로 필수 콘텐츠를 세 번째 달 안에 마치는 계획을 제안한다. 추가 기간의 사용 가능 여부는 별도로 확인한다. 학습·힌트 훈련은 사용자 요청 때만 편성하며 제작의 선행 조건으로 삼지 않는다.

## 현재 작업과 다음 행동

캐릭터 스폰, 이동·카메라, 사망 후 개별 재스폰과 테스트 맵을 구현했다. 구현 구조와 실행별 검증 결과는 [MultiplayerFoundation](MultiplayerFoundation.md)이 소유한다.

일반 몹 한 종류와 최소 전투는 [CombatFoundation](CombatFoundation.md)의 확정 사양으로 코드를 작성하고 전체 타깃 빌드와 비대화형 에디터의 클래스 로드 검사를 통과했다. 다음 작업은 전투 에셋 생성과 실행 검증이다. 완료 판단은 에셋 생성, 전투·이동 회귀 검사와 시각 검증 후에 한다.
