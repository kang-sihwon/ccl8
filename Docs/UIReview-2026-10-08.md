# 장비·공용 UI 확인 안내

장비 태그, 공용 UI 기반, 인벤토리·메뉴 이전, HUD·NPC 대화창 분리와 연출 제어를 구현했다. UE 5.9에서 생성 BAT·CCLEditor 빌드와 화면·입력·저장·멀티플레이 검사를 통과했다. 이 문서는 2026-10-08 검토용 요약이며, UI 계약은 [UIFoundation](UIFoundation.md), 장비 계약은 [ProgressionFoundation](ProgressionFoundation.md)이 소유한다.

## 구현과 확인 범위

| 항목 | 확인한 결과 | 구현 근거 |
|---|---|---|
| 장비 태그 | 장착 부위·한손/양손·부착 지점을 태그로 설정하고 프로필에서 실제 소켓으로 해석한다. 기존 에셋 변환과 저장 호환을 검사했다 | `6a9cecb` |
| 공용 UI | 로컬 플레이어별 관리자, 루트, 스택·겹침 패널·큐, 등록·문맥·핸들·비동기 로딩·화면 풀을 제공한다 | `b5d9495` |
| 인벤토리·메뉴 | 장비 창과 시작·일시정지 메뉴를 공용 화면에 연결했다. 드래그 이동·교환·장착·해제와 미리보기를 검사했다 | `494a0ac` |
| HUD·대화 | 체력·기력과 안내·NPC 대화창을 독립 위젯으로 구성했다. 능력치 변경 알림, 대사 변경과 재스폰 후 연결을 검사했다 | `bbe9b3b` |
| 연출 제어 | 그룹별 숨김·입력·갱신 정지·페이드를 요청 핸들로 합성한다. 중첩 해제·소유자 소멸·맵 이동·포커스 복구를 검사했다 | `37dd904` |
| 통합 | RTS 패널·대화 중심 구성을 등록 데이터로 교체하고, 일시정지 중 페이드와 화면 생성 중 닫힘을 검사했다 | `b6cc535` |

Dedicated 서버와 Listen 호스트에서 장비·복제·재스폰을 확인했다. 지연·손실을 적용한 Listen 구성에서는 NPC 거래·퀘스트·중복 보상 거부를 검사했다. 시작 메뉴의 실제 키 입력, 별도 프로세스 저장 복원, 방 생성·접속·접속 실패도 통과했다. 로그 위치와 해상도별 검사 결과는 [UIFoundation의 통합 검사 표](UIFoundation.md#이전과-검증)에 있다.

코드 검토에서는 화면 생성 중 표시 정책의 콜백이 화면을 닫아도 열린 핸들을 반환할 수 있는 결함을 수정했다. 서버 RPC 본문은 보존했고, Core에 캐릭터·장비·GAS·퀘스트 의존성이 없는지 확인했다. 최종 생성·빌드 근거는 로컬 `Saved/StageValidation/UIFinal-Generate.log`, `UIFinal-Build.log`다. 최종 검사 코드의 컴파일·링크를 성공했고, 통합 변경의 컴파일·링크 기록은 `UIIntegration-Build.log`에도 있다.

## 직접 확인할 화면

1. `CCL.uproject`에서 Campaign 맵을 실행한다. 왼쪽 위 체력·기력과 아래쪽 안내 글자의 크기를 확인한다.
2. `I`로 인벤토리를 연다. 중앙 캐릭터와 양옆 장비 슬롯, 오른쪽 가방을 확인한다.
3. 아이템을 빈 칸과 다른 아이템 칸으로 드래그한다. 한손 장비 양쪽을 장착한 뒤 양손 장비로 교체해 반환된 아이템을 확인한다.
4. 인벤토리를 닫고 마을 안내인 근처에서 `T`를 누른다. 중앙 아래 대화 상자의 이름과 본문을 확인한다.
5. `Esc`로 메뉴를 열었다 닫는다. 캐릭터 조작이 복구되는지 확인한다.

자동 실행으로 저장한 화면은 로컬 `Saved/Tests/UIVisual/1920x1080-20261008-100611/`에 있다. `equipment-full.png`는 장비 창, `npc-dialogue.png`는 대화창, `presentation-dialogue-only.png`는 HUD 그룹을 숨기고 대화창을 남긴 상태다. 연출 요청은 기반 API로 제공하며 일반 플레이에 새 컷신 단축키를 추가하지 않았다.

## 구현 범위의 한계

미니맵·전체맵·MP·버프·디버프·월드 상호작용 아이콘은 같은 기반에 기능별 문맥과 위젯을 연결할 수 있다. 해당 콘텐츠 화면과 게임 규칙을 모두 만든 상태는 아니다. 현재 퀘스트 진행은 안내 HUD에 표시하며 퀘스트 목록 창·분기 대화 선택지·실제 컷신 타임라인은 별도 구현이 필요하다.

장비 미리보기에는 검증용 임시 외형이 포함돼 있고 최종 아트·조작감·밸런스는 사용자 검토가 필요하다. 장착 프로필의 에디터 드롭다운과 미리보기 도구는 수동 조작을 확인하지 않았다. 여러 로컬 플레이어의 화면과 핸들은 분리했지만 데스크톱 마우스 하나의 독립 캡처는 보장하지 않는다.

검증은 현재 노트북의 UE 5.9 소스 엔진 실행을 기준으로 한다. 이번 UI 결과를 새 Windows 배포 패키지로 만들지는 않았다. 엔진 실험 플러그인 `PythonTestRunner` 초기화 오류와 이전 IncludeOrderVersion 안내는 UI 검사 결과와 구분한다. 로그와 캡처는 Git에서 제외한 로컬 파일이며 상세 코드·검증 문서만 저장소에 제출한다.
