# 플레이어 신원과 계정

원격 플레이어의 프로필 연결, 복원 때의 접속자 유지, 계정의 초기 생성 경계를 다룬다.

## 원격 플레이어 신원 연결과 복원 시 접속자 유지

2026-10-11에 일반 접속에서 세계 프로필을 자동으로 연결했다. 정책과 이유는 [결정 21](../../decisions/0021-server-issued-player-identity.md)을 따른다.

| 단계 | 소유자와 동작 |
|---|---|
| 접속 옵션 | `UCCLLocalPlayer::GetGameLoginOptions`가 접속 중인 `PendingNetGame`의 주소로 저장된 비밀 키를 찾아 `CCLProfile` 옵션에 붙인다. 설정은 `DefaultEngine.ini`의 `LocalPlayerClassName`이다 |
| 접속 기록 | `ACCLGameModeBase::InitNewPlayer`가 원격 PlayerController의 옵션 값을 보류 목록에 넣는다. 로컬 호스트는 넣지 않는다 |
| 연결 | `BindPendingProfiles`가 세계 시뮬레이션과 Agent 세계가 준비될 때까지 0.25초 간격으로 최대 40회 시도한다. 유효한 키는 기존 프로필에 연결하고, 없거나 연결할 수 없는 키에는 새 키를 발급한다 |
| 키 전달과 보관 | 서버는 새 키를 `ClientReceiveProfileKey`로 그 플레이어에게만 보낸다. 클라이언트 GameInstance는 접속 주소 `host:port`별로 `CCL_ProfileKeys` 슬롯에 저장한다 |
| 저장 식별 | 세계 프로필의 식별 키는 `profile:`과 비밀 키 SHA-1 해시의 소문자 16진수다. 구현은 `Source/CCL/Session/CCLProfileIdentity.cpp`다 |

- **미등록 음식:** 연결된 플레이어의 인벤토리는 `bExternalPersistence`로 지속 소유자 표시를 받아, 세계 저장에서는 플레이어 참가자가 항목을 수집한다. 미등록 음식 거부는 등록 전의 짧은 구간과 연결 시도가 끝난 플레이어에만 남는다. 맵 전환의 자동 저장은 실패를 경고로 남기고 이전 상태를 유지한다.
- **접속자 유지:** 세계 복원은 저장 본문에 프로필이 없는 등록 플레이어를 현재 상태로 유지한다. `PrepareWorldRestore`가 그 플레이어의 현재 프로필을 복원 후보에 넣고, 아이템 GUID를 `KeptItems`로 보관함 참가자에 넘긴다. 저장 보관함이 같은 GUID를 복원하거나 개인 세션이 유지 플레이어의 항목을 복원하면 세계 변경 전에 거부한다.
- **재검사:** 병합한 전체 프로필은 `CCLPlayerSnapshot::Validate`로 세계 ID와 저장 시각에 대해 다시 검사한다. 저장 시각보다 미래인 음식 이력을 가진 유지 플레이어도 거부한다.
- **계좌:** 확정 단계는 모든 연결 플레이어에 `UCCLAccountComponent::EnsureOpen`을 호출한다. 복원된 원장에 계좌가 없으면 마지막 잔액 표시값으로 다시 연다. 같은 세계의 사라진 계좌를 다시 여는 호출은 이것뿐이다.

한계는 결정 21의 트레이드오프와 같다. 키는 암호화되지 않은 엔진 기본 채널로 전달되므로 인증이 아니다. 한 PC에서 같은 서버에 여러 클라이언트로 접속하면 두 번째 클라이언트가 새 키를 받아 저장 슬롯을 덮어쓴다. 키 파일을 잃은 클라이언트의 이전 프로필은 세계 기록에 남지만 다시 연결할 수 없다.

## 계정 조회와 초기 생성 분리 구현·검증

복원된 세계에서 `UCCLAccountComponent::Resolve`와 잔액 조회는 원장을 바꾸지 않는다.

- 초기 계좌 생성은 서버 컴포넌트의 시작, Tick, 금화 변경 요청에서 명시적으로 하고 성공한 세계 ID를 기억한다. 새 세계 ID에서는 초기 생성을 다시 한다.
- 같은 세계에서 사라진 계좌는 Tick, 조회, 보상, 이전 금화 가져오기로 재생성하지 않는다. 표시 값은 마지막 잔액 캐시를 유지하고 금화 변경 요청은 거부한다.
- 저장 계좌 연결은 원장에 존재하는 계좌만 받는다.
- 환경 실험의 전체 초기화는 살아 있는 플레이어의 계정 ID와 잔액을 초기 세계 후보에 명시적으로 넣고(`ImportAccountBalance`), 현재 계좌가 없으면 초기화를 거부한다. 미등록 플레이어의 금화 보존이고, 등록된 전체 프로필의 초기화 정책은 이 절의 범위가 아니다.

2026-10-10 UE 5.8.3에서 `Tools/Validation/run_session_smoke.ps1`의 실제 저장, 별도 프로세스 재개, 메뉴 복귀, 승리 재개와 새 계좌 누락 검사를 통과했다. 실제 계좌를 원장에서 잠시 없앤 뒤 조회, Tick, 보상, 이전 금화 가져오기를 실행해 계좌가 늘지 않는 것을 확인했다. 두 플레이어와 세계 재개도 통과했고 환경 초기화의 금화 83 보존을 확인했다.

이 변경은 조회의 부작용을 없앨 뿐 인증 키나 초기 계좌의 중복을 해결하지 않는다.
