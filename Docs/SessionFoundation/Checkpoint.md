# 개인 체크포인트

저장 파일의 범위, 형식, 검증, 변환을 바꿀 때 읽는다. 현재 외부 세션 형식은 8이고 `FCCLSessionRecord::Version`이 정본이다.

## 저장 범위

단일 로컬 슬롯에 호스트의 인벤토리 GUID·정의 ID·수량, 장비, 학습 스킬, 포인트, 금화·퀘스트와 원정 체크포인트를 저장한다. 접속한 손님의 개인 상태는 이번 파일에 포함하지 않는다. 손님은 호스트의 파일 저장·불러오기를 요청할 수 없다. 최종 계정·협동 보상 소유권을 확정하는 정책은 아니다.

체크포인트는 처치한 경비병, 보스 격파 여부와 남은 마을 보급품이다. 호스트는 마을에서 완전한 체력으로 시작한다. Agent 스냅샷이 있는 저장은 생활 NPC와 전투 적의 부상을 복원한다. 살아 있던 전투 적은 체크포인트 위치에 재생성하며 공격 타이머는 다시 계산한다. Agent 스냅샷이 없는 이전 저장은 적의 기본 체력을 사용한다. 사망·행동 중에는 저장을 거부한다. 정확한 적 위치·공격 타이머를 직렬화하는 방식보다 재시작 상태의 일관성을 우선한 초안이다.

## 파일 형식과 검증

파일은 엔진의 플랫폼 저장 슬롯 API로 기록하되 UObject 클래스 경로를 역직렬화하지 않는다. 제한된 크기의 JSON 값 앞에 형식 식별자와 CRC를 붙인다. CRC는 우발적인 손상 감지용이며 변조 방지 장치가 아니다. 필수 필드·버전·알려진 정의 ID·수량·GUID 중복·장비 참조·스킬과 체크포인트 조합을 검증한 뒤 새 월드에 적용한다. 실패한 파일은 자동으로 덮어쓰지 않는다.

Agent 생활 저장은 결정 18과 [AgentFoundation](../AgentFoundation.md)을 따른다. 생활 스냅샷은 Unreal 구조체 기반 로컬 저장이므로 JSON의 Definition 허용 목록과 별개로 Feature 타입, 버전, 교차 참조를 검증한다. 신뢰할 수 없는 외부 저장 파일을 안전하게 읽는 보안 경계로 쓰지 않는다.

테스트는 `CCL_Validation` 슬롯을 쓰며 일반 플레이의 `CCL_Checkpoint` 슬롯과 구분한다. 로컬 저장 파일은 Git에 넣지 않는다.

## 형식별 변환

| 형식 | 더한 것 | 이전 형식을 읽는 법 |
|---|---|---|
| 2 | 항목별 가방 슬롯 | 형식 1은 배열 순서로 가방 칸을 만든다 |
| 3 | 부위별 장착 목록 | 형식 1·2의 단일 장비 참조를 새 부위 목록으로 바꾼다 |
| 4 | 부위를 `Equipment.Slot.*` 문자열로 기록 | 형식 3의 enum 이름이나 숫자를 구체적인 슬롯 태그로 바꾼다 |
| 5 | 아이템 GUID별 `LoadedAmmo`, 선택적 `AgentSimulation`과 `AccountId`, 보급품 기록 최대 64개 | 형식 1-4의 탄창은 비우고, 그 전 보급품 상한은 2개다. 계정이 있는 저장의 `Coins`는 0이고 옛 저장에서만 금화 이관 값이다 |
| 6 | 공통 세계 시계, 환경, 생활 | 이전 형식에는 세계 부분이 없다 |
| 7 | 선택적인 음식 묶음 이력 | 형식 1-6의 누락 상태는 빈 그대로 읽는다 |
| 8 | 보급품의 배치 ID | [배치 식별](#배치-식별과-체크포인트-검증)을 따른다 |

알 수 없는 태그, 상위 태그, 다른 범주의 태그는 거부한다. 탄약 값은 해당 무기의 탄창 용량을 넘을 수 없다. 음식은 세계 ID, 완료 시각, 수량을 함께 검증하며 구현과 검증 범위는 [음식 상태·인벤토리·세션 검증](../EnvironmentPlan/Ecology/Food/State.md#음식-상태인벤토리세션-검증)을 따른다.

각 항목에 가방 슬롯을 기록하고 장착 항목은 `INDEX_NONE`으로 표시한다. 부위별 장착 목록은 GUID를 참조하며 양손 장비는 같은 GUID로 두 손을 모두 차지해야 한다. 중복 부위, 잘못된 장비 종류, 불완전한 양손 점유, 어느 부위에도 연결되지 않은 장착 항목은 거부한다. 구현 근거는 `Source/CCL/Session/CCLSessionRecord.cpp`다.

## 세계 저장과의 경계

세계 저장의 등록 보관함과 호스트 개인 항목은 서로 다른 저장 소유자다. `SaveSession`은 같은 호출에서 개인 항목을 수집하고 해당 인벤토리만 세계 수집에서 제외한다. 다른 미등록 음식은 거부하며, 개인 항목과 세계 보관함의 아이템 GUID 중복도 거부한다. 불러오기는 개인 장비 효과를 먼저 준비한 뒤 세계를 복원하고 개인 인벤토리·장비·진행을 확정한다. 이는 새 맵에서의 세션 재개 순서이며 현재 월드의 개인 프로필 전체를 원자적으로 되돌리는 계약은 아니다. 일반 세계 저장·맵 전환의 개인 음식 연결은 남아 있다. 검증은 [컨테이너 세계 저장 검증](../EnvironmentPlan/Ecology/Food/Containers.md#컨테이너-세계-저장-검증)을 따른다.

## 정의 카탈로그와 보급품 개수

저장 기록의 아이템과 스킬 이름은 코드 목록이 아니라 콘텐츠 카탈로그로 해석한다. `UCCLItemCatalogSettings`가 `DefaultGame.ini`에서 `/Game/Progression/DA_ItemCatalog`를 지정한다. `UCCLItemCatalog`의 `Items`와 `TrainingSkills`에 없는 이름은 null로 해석되어 저장 검증에서 거부된다. 임의 경로를 불러오지 않는다. 카탈로그는 `/Game/Progression`의 항상 쿠킹 목록에 포함된다.

같은 종류의 항목 안에서 이름은 유일해야 하고, 같은 객체의 중복 등록과 빈 참조도 검증 오류다. 아이템과 스킬은 별도 이름 영역을 유지한다. 에디터 Data Validation과 런타임 `Get`에서 전체 카탈로그를 검증하며, 직접 `FindItem`·`FindSkill`을 호출해도 중복 이름을 첫 항목으로 해석하지 않는다. 이름 기반 저장 형식이므로 정의의 이름 변경은 이 검사로 해결되지 않는다. 검증 근거는 [ProgressionFoundation의 2026-10-11 기록](../ProgressionFoundation/Verification.md#2026-10-11-설계-후속-수정)이다.

형식 7까지의 남은 보급품은 남은 픽업마다 정의 이름을 한 번씩 기록하고, 복원은 이름별 개수만큼 픽업을 남긴다. 승리 기록은 처치한 경비병 비트가 하나 이상 있어야 하며 비트 값은 0-255 범위다. 구현은 `Source/CCL/Session/CCLSessionRecord.cpp`와 `Source/CCL/Session/CCLGameInstance.cpp`의 `ApplyRecord`다.

## 배치 식별과 체크포인트 검증

경비 1·2와 보스 3의 Agent ID를 유지하고 세 번째 이후 경비는 4부터 배정한다. 경비 배열 순서 변경은 기존 처치 마스크와 함께 별도 호환성 판단이 필요하다. 구형 저장에서 세 명 이상의 경비가 사용한 충돌 상태는 자동 분리하지 않는다.

보급품은 맵에 저장한 `PlacementId`와 정의·남은 수량으로 저장한다. Director가 자신이 생성한 픽업만 추적하며 음식의 세계 저장용 `PersistentId`는 재사용하지 않는다. 외부 세션 형식은 8로 확장하고 구형 세션은 배치가 확실한 기본 구성만 변환한다. 모호한 구형 저장은 원본을 보존하고 적용 전에 거부한다. 배치 ID·정의·수량과 처치 마스크는 세계·플레이어 복원보다 먼저 검증한다.

검증 대상은 경비 1·2·3·8명과 보스의 ID 고유성, 같은 정의의 서로 다른 두 배치·수량 복원, 설정 순서 변경, 잘못된 배치 거부, 구형 저장과 프로필 회귀다. UE 5.8.3에서 프로젝트 파일 생성과 Editor 빌드, 전체 자동화 155개, 실제 저장, 별도 프로세스 재개, 승리 복원을 통과했다. 맵에 직접 배치됐던 장갑과 포션은 `create_progression.py`로 Director의 배치에 옮겼고 5개 배치를 확인했다.
