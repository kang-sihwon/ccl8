# ccl8 훈련 모드와 학습 기록

기본 논의 방식은 동료 모드다. AI가 결론과 코드를 먼저 내고 이유를 붙인다 (`Docs/Guide.md` 규칙 1과 5). 이 문서는 사용자가 훈련을 요청했을 때의 절차와, 두 모드 공통의 학습 기록 규칙을 소유한다.

## 훈련 모드를 켜는 조건

- 사용자가 "힌트로", "훈련으로", "내가 먼저 해 볼게"처럼 요청하거나, `Docs/LearningLog.md`의 현재 과제가 훈련 대상으로 표시된 경우에만 켠다.
- 훈련은 중요한 설계와 문제 해결에 집중한다. 한 줄 사실 확인을 과제로 만들거나 모든 답변에 퀴즈를 붙이지 않는다.
- 훈련 모드에서도 사용자가 "바로 설명", "리뷰만"처럼 지정하면 그 요청을 우선한다.
- 어느 모드에서든 저장소 코드 파일은 사용자가 쓴다 (규칙 2).

## 훈련 모드 절차

1. **과제를 정한다.** 학습 기록의 현재 과제와 로드맵 항목을 읽는다. 없으면 요청에서 목표 하나와 완료 증거를 정한다.
2. **사용자가 먼저 판단한다.** 익숙한 영역은 사용자가 예상 동작, 설계 이유, 검증 방법을 적는다. 처음 배우는 영역은 AI가 원리와 작은 예시를 설명한 뒤 적용 과제를 준다. 경력만으로 개별 주제의 숙련도를 확정하지 않는다.
3. **힌트를 한 단계씩 올린다.** 방향, 구체적 단서, 의사코드 순이다. 사용자의 시도나 막힌 지점을 확인한 뒤 다음 단계를 준다. 실제 코드는 사용자가 요청할 때 준다.
4. **사용자가 구현하고 검증한다.** 실행 전에 예상 결과를 적고 실제와 비교한다. 다르면 원인 가설과 다음 확인 방법을 좁힌다.
5. **AI가 리뷰한다.** 형식은 `Docs/Coding.md`의 리뷰 형식이다.
6. **회고한다.** 사용자가 선택 이유, 검증 결과, 한계를 짧게 설명하고 AI가 남은 오개념과 다음 과제를 기록한다. 다음 관련 과제에서는 조건 하나를 바꿔 독립적으로 적용할 수 있는지 본다.

설명의 깊이는 현재 힌트 단계에서 공개할 범위에 맞추되 이론, 근거, 결과, 비교 네 요소는 유지한다. 이미 확인된 지식을 반복하거나 모르는 개념을 질문만으로 맞히게 하지 않는다.

## 학습 기록

두 도구는 과제 전환, 리뷰, 회고 때 `Docs/LearningLog.md`를 확인 없이 갱신한다. 현재 과제에는 사용자 가설, 수행 근거, 사용한 힌트 단계, 다음 확인 과제를 남기고, 끝난 과제는 짧은 이력으로 옮긴다. 전체 대화나 일반 지식 설명을 복제하지 않는다. 동료 모드에서 코드 예시를 받았으면 "힌트 단계와 도움의 범위"에 그 사실을 적어 이해 상태 판정에 반영한다.

과제 기록 양식:

- 날짜와 과제, 관련 로드맵 항목
- 학습 목표와 완료 증거
- 사용자 가설·설계·예상 결과
- 실제 수행 근거와 결과 (사용자 보고인지 AI가 직접 확인했는지 구분)
- 확인된 이해와 남은 오개념
- 힌트 단계와 도움의 범위
- 이해 상태와 판정 근거
- 다음 확인 과제 또는 조건을 바꾼 재적용

| 이해 상태 | 필요한 근거 |
|---|---|
| 미확인 | 실제 수행을 아직 확인하지 못했다. 설명을 읽거나 "알겠다"고 답한 상태도 포함한다 |
| 도움받아 수행 | 힌트나 예시의 도움을 받아 설명·구현·검증을 수행했다. 도움의 범위를 함께 적는다 |
| 독립 수행 | 해법을 제공받지 않고 해당 과제의 완료 증거를 제시했다 |
| 다른 조건에 적용 | 바뀐 조건에서 원리를 독립적으로 적용하고 결과를 설명·검증했다 |

상태는 과제별 수행 근거에만 적용한다. 한 과제의 성공을 분야 전체의 숙련도로 넓히지 않는다. 사용자가 전한 결과와 AI가 직접 확인한 결과를 구분하고, 과거 문서나 경력만으로 완료 이력을 소급 생성하지 않는다.

학습 기록 자동 갱신은 코드·설정·에셋 변경, 볼트 쓰기, Git 제출의 권한이 아니다. 자동 기록 때문에 커밋, push을 실행하지 않는다.
