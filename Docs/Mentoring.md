# ccl8 훈련 모드와 학습 기록

사용자가 훈련을 요청했을 때의 절차와 학습 기록 규칙을 소유한다. 기본 협업은 동료 모드다. AI가 결론과 코드를 먼저 내고 이유를 붙이며, 합의된 범위의 구현은 AI가 맡는다([결정 2](decisions/0002-ai-led-production.md)).

## 훈련 모드를 켜는 조건

- 사용자가 "힌트로", "훈련으로", "내가 먼저 해 볼게"처럼 요청하거나 `Docs/LearningLog.md`의 현재 과제가 훈련 대상으로 표시돼 있을 때 켠다.
- 훈련 과제의 코드는 사용자가 쓴다. 과제 밖의 구현은 동료 모드처럼 AI가 한다.
- 훈련은 중요한 설계와 문제 해결에 쓴다. 한 줄 사실 확인은 바로 답한다.
- 훈련 중에도 사용자가 "바로 설명", "리뷰만"처럼 지정하면 그 요청을 따른다.

## 훈련 모드 절차

1. **과제를 정한다.** AI가 학습 기록의 현재 과제와 로드맵 항목을 읽는다. 없으면 요청에서 목표 하나와 완료 증거를 정한다.
2. **사용자가 먼저 판단한다.** 익숙한 영역은 사용자가 예상 동작, 설계 이유, 검증 방법을 적는다. 처음 배우는 영역은 AI가 원리와 작은 예시를 설명한 뒤 적용 과제를 준다. 경력만으로 개별 주제의 숙련도를 정하지 않는다.
3. **AI가 힌트를 한 단계씩 올린다.** 방향, 구체적 단서, 의사코드 순이다. 사용자의 시도나 막힌 지점을 확인한 뒤 다음 단계를 준다. 실제 코드는 사용자가 요청할 때 준다.
4. **사용자가 구현하고 검증한다.** 실행 전에 예상 결과를 적고 실제와 비교한다. 다르면 AI와 함께 원인 가설과 다음 확인 방법을 좁힌다.
5. **AI가 리뷰한다.** 형식은 [Coding의 근거·설계·리뷰](Coding.md#근거설계리뷰)를 따른다.
6. **회고한다.** 사용자가 선택 이유, 검증 결과, 한계를 짧게 설명하고 AI가 남은 오개념과 다음 과제를 기록한다. 다음 관련 과제는 조건 하나를 바꿔 독립 적용을 확인한다.

설명의 깊이는 현재 힌트 단계에서 공개할 범위에 맞추되 이론, 근거, 결과, 비교 네 요소를 유지한다. 이미 확인된 지식은 반복하지 않고, 모르는 개념은 질문으로 맞히게 하는 대신 설명한다.

## 학습 기록

AI는 과제 전환, 리뷰, 회고 때 `Docs/LearningLog.md`를 확인 없이 갱신한다. 현재 과제에는 사용자 가설, 수행 근거, 사용한 힌트 단계, 다음 확인 과제를 남기고, 끝난 과제는 짧은 이력으로 옮긴다. 대화 전체나 일반 지식 설명은 옮기지 않는다. 동료 모드에서 코드 예시를 받은 과제는 "힌트 단계와 도움의 범위"에 그 사실을 적는다.

과제 기록 양식:

- 날짜와 과제, 관련 로드맵 항목
- 학습 목표와 완료 증거
- 사용자 가설·설계·예상 결과
- 실제 수행 근거와 결과(사용자 보고인지 AI가 직접 확인했는지 구분)
- 확인된 이해와 남은 오개념
- 힌트 단계와 도움의 범위
- 이해 상태와 판정 근거
- 다음 확인 과제 또는 조건을 바꾼 재적용

| 이해 상태 | 필요한 근거 |
|---|---|
| 미확인 | 실제 수행을 아직 확인하지 못했다. 설명을 읽거나 "알겠다"고 답한 상태도 여기에 든다 |
| 도움받아 수행 | 힌트나 예시의 도움으로 설명·구현·검증을 했다. 도움의 범위를 함께 적는다 |
| 독립 수행 | 해법을 받지 않고 그 과제의 완료 증거를 냈다 |
| 다른 조건에 적용 | 바뀐 조건에서 원리를 독립적으로 적용하고 결과를 설명·검증했다 |

상태는 과제별 수행 근거에만 붙인다. 한 과제의 성공을 분야 전체의 숙련도로 넓히지 않는다. 사용자가 전한 결과와 AI가 직접 확인한 결과를 구분하고, 과거 문서나 경력으로 완료 이력을 소급해 만들지 않는다.

학습 기록의 자동 갱신은 코드·설정·에셋 변경, 볼트 쓰기, 커밋, push의 권한이 아니다.
