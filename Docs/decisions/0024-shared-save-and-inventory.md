# 2026-10-12 — 결정 24: 공용 저장 계약과 인벤토리의 게임 확장 경계

### 배경

사용자가 Framework 단계 1의 검토와 제출 이후 단계 2 진행을 지시했다. 저장 참여 계약은 표면·생활 타입을 참조하고 있었고 기본 인벤토리의 공개 항목은 음식·탄약 상태를 포함했다. 실행 함수만 옮기면 공용 모듈에 게임 의존이 남는 구조였다.

### 결정

결정 23에서 검토 뒤 진행하기로 한 단계 2를 착수한다. `KSICore`는 저장 참여·이름 있는 구간 검증·시간 읽기와 실행 구간 값 계약을 소유한다. 구체 세계 시계와 환경 진행은 CCL에 남긴다. 검증 자료는 게임이 구현한 선택 문맥으로 전달하고 공용 헤더가 생활·표면 타입을 참조하지 않게 한다. 구간 등록 객체가 소멸하면 해당 검증 콜백도 해제한다.

`KSIInventory`는 기본 아이템 정의, Fragment 기반 확장 데이터, GUID·수량·슬롯, Fast Array 복제와 기본 보관 실행을 소유한다. 개별 확장 상태는 `FInstancedStruct`로 보관한다. `UCCLItemDefinition`과 `UCCLInventoryComponent`는 공용 타입을 상속하는 게임 어댑터로 유지한다. 음식·탄약 상태와 장비·전투 Fragment, 환경 관측과 기존 저장 변환은 CCL이 소유한다.

게임 어댑터의 네이티브 클래스 경로와 기존 세계·세션 저장 필드 형식을 유지한다. 공용 구간 계약은 기본 인벤토리의 별도 저장 파일을 자동으로 세계 저장에 연결하지 않는다. 구체 저장 참여자는 계속 CCL에서 등록한다. 기본 저장 API는 정의를 게임이 제공한 조회 함수로 해석하고, 확장 상태는 별도 직렬화 훅이 없으면 저장을 거부한다. 완료 판정과 실행 근거는 FrameworkPlan이 소유한다. 단계 3-4와 공용 저장소 배포는 착수하지 않는다.

### 트레이드오프

파생형 어댑터는 기존 게임 클래스·에셋과 저장 형식을 유지하면서 공용 모듈의 역방향 의존을 끊는다. 대신 공용 동작과 게임 확장을 각각 검증해야 하고, 확장 상태의 값 복사·직렬화 비용이 생긴다. 여러 기능을 전역 등록하는 방식보다 등록 수명과 조합 규칙은 적지만 게임마다 파생형의 확장 훅을 구현해야 한다. 이번 분리에서 성능 향상을 주장하지 않는다.
