# 2026-10-07 — 결정 17: 장르 독립적인 공용 UI와 기능별 문맥

### 배경

사용자는 화면이 늘어날 때의 공용 관리자와 위젯 베이스를 요청했다. 지도·능력치·버프·상호작용·NPC 대화·퀘스트를 연결하고 연출 때 여러 UI를 함께 제어하면서 다른 장르에도 사용할 수 있어야 한다고 명시했다. 공용 기반 구현, 기존 인벤토리·장비 화면 이전, HUD·대화창 분리와 통합 검증을 승인했다.

### 결정

공용 관리자는 LocalPlayer 수명으로 두고 UMG·CommonUI의 화면 활성화와 입력 라우팅을 사용한다. 레이어·확장 지점·화면은 등록 데이터로 구성한다. 화면 종류 태그와 인스턴스·등록·비동기 요청 핸들을 구분하고 기능별 타입을 가진 문맥을 연결한다. 장르·게임 상태의 소유권과 서버 검증은 기능 계층에 남긴다.

표시 제어는 소유자와 범위를 가진 요청으로 적용한다. 중첩 요청을 해제할 때 현재 상태와 남은 요청에서 표시·입력을 다시 계산한다. 풀 재사용·소유자 소멸·맵 이동과 비동기 취소를 공용 수명 계약에 포함한다. 구체적인 클래스·인터페이스와 완료 근거는 [UIFoundation](../UIFoundation.md)이 소유한다.

### 트레이드오프

등록 데이터와 문맥 계약을 검증하는 비용이 추가되지만 공용 관리자가 장비나 퀘스트 규칙을 직접 알 필요가 없다. CommonUI를 사용하려면 기존 Slate 메뉴·인벤토리의 입력 적용 경로를 함께 이전해야 한다. FieldNotify 기반 표시 모델은 기능별로 검증하며 공용 문맥을 특정 모델 구현에 결합하지 않는다.
