# 2026-10-06 — 결정 9: 장르에 독립적인 베이스 시스템

### 배경

사용자는 HUD, Inventory, Item, Drop, Save/Load와 일반 전투 판정 등 베이스 작업을 특정 장르에 국한하지 않고 범용적으로 설계하라고 지정했다. ItemDefinition에 Fragment를 조합해 아이템을 정의하는 방식을 예로 들었다.

### 결정

베이스 시스템의 공통 책임과 데이터 흐름을 장르별 콘텐츠 규칙에서 분리한다. 정의 데이터, 개별 상태, 실행 기능과 표현을 구분하며 콘텐츠는 데이터·정책·기능 조합으로 연결한다. Item은 ItemDefinition과 Fragment 조합을 기준으로 설계한다. 원칙과 검토 기준의 정본은 [Coding](../Coding.md)이다.

[CombatFoundation](../CombatFoundation.md)의 일반 판정 기반에도 이 기준을 적용한다. 회피·가드·패링과 스태미나 규칙은 콘텐츠 계층에서 구성한다. 결정 8의 세 방어 행동 포함 범위는 유지한다. 이 결정은 게임의 장르·제작 범위를 바꾸거나 모든 장르의 기능을 미리 구현하라는 뜻이 아니다.

### 트레이드오프

장르 전용 구현보다 인터페이스, 데이터 검증과 연결 코드가 필요하다. 공통 계약과 확장 지점을 먼저 정하면 다른 콘텐츠를 추가할 때 기반 코드의 장르 분기를 줄일 수 있다. 필요한 기능부터 구현하되 제작 기간을 이유로 범용 설계 원칙을 생략하지 않는다.
