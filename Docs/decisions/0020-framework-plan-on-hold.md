# 2026-10-09 — 결정 20: 공용 Framework 계획과 구현 보류

### 배경

사용자는 CCL의 시스템을 다른 개인 UE5 프로젝트에서도 공용으로 사용할 방향을 제안했다. 인게임 콘텐츠는 공용화 대상에서 제외하고 독립적으로 선택할 시스템을 추려 달라고 요청했다. `Framework`와 `Core`를 비교한 명명 논의를 포함해 현재 계획을 문서화하되, 작업량이 늘어난 뒤 실제 분리를 진행하겠다고 정했다.

### 결정

공용화는 시스템 단위로 계획한다. CCL을 첫 사용 프로젝트로 두고, 게임별 규칙과 콘텐츠는 각 프로젝트가 제공한다. 독립 시스템 후보와 선택 확장, 검증 기준의 소유 문서는 [FrameworkPlan](../FrameworkPlan.md)이다.

계획의 이름은 `{Prefix}{System}Framework` 형식을 기준으로 정리한다. 공통 접두사와 최종 모듈·플러그인 구성은 미정이다. 현재는 계획만 기록하고 코드 이동·이름 변경·모듈·플러그인 분리를 보류한다. 사용자가 다시 착수를 요청하면 당시 작업량, 의존 관계와 재사용 수요를 확인한다.

이 결정은 결정 9의 장르 독립적인 계약과 콘텐츠 분리 원칙을 유지한다. 결정 19의 환경 구현 범위를 변경하거나 후속 단계에 착수하지 않는다. 물리적 모듈 분리를 환경 4단계의 필수 선행 일정으로 두지 않는다.

### 트레이드오프

공용 기반을 다른 게임에서 재사용하면 반복 구현과 검증 비용을 줄일 수 있다. 공개 API, 버전·저장 호환과 별도 프로젝트 검증을 유지하는 비용은 늘어난다. 실제 사용과 재사용 수요가 쌓인 뒤 필요한 시스템부터 추출하면 초기 추상화를 줄일 수 있지만, 그때 기존 결합을 정리하는 작업이 필요하다.
