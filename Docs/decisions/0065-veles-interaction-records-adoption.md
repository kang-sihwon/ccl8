# 2026-11-16 — 결정 65: 벨레스 상호작용·작업 기록 IR01-IR06 채택

### 배경

사용자는 [IR01-IR06 선택표](../Narrative/Drafts/2026-10-31-ether-taiga-dawn/2026-11-16-veles-interaction-records/options.md)의 추천과 공통 경계를 검토한 뒤 2026-11-16 다음과 같이 승인했다.

> 추천한 IR01–IR06과 공통 경계를 모두 채택할게. NG04에서 해당 범위를 정본에 반영하고 검토·커밋·푸시까지 진행해줘. 기존 원문·대안·보류·도안·좌표·수치는 유지하고 실제 UE 구현·실행은 제외해줘.

[NG09 작성 독립 검토](../Narrative/Reviews/2026-11-16-veles-interaction-records-review.md)는 PASS, 잔여 지적 0이다. 이번 승인은 여섯 추천의 표현 방식·적용 범위·이점·비용과 공통 경계다. 검토 통과·사용자 승인·실제 실행의 증거는 구분한다.

### 결정

[결정 61](0061-veles-progression-resume-adoption.md)의 정보·작업·인수·현재 조건 구분, [결정 62](0062-veles-validation-design-adoption.md)의 문서와 실행 증거 구분, [결정 63](0063-veles-manuscript-delivery-adoption.md)의 휴대 기록·불완전 보고·현재 인수 보완을 다음 표현으로 구체화한다. NG01-NG08의 확정과 공통 경계는 유지한다.

| 항목 | 채택한 중심 |
|---|---|
| IR01 행동에 붙는 짧은 현재 피드백 | 실제 관찰·전달·작업에 현재 확인한 범위와 다음 부족한 일을 짧게 붙이고 전투에서는 현재 움직임·결박 변화를 우선한다. |
| IR02 출처와 완료 범위를 드러내는 기록 | 관찰/전달 출처·미확인·계획·실제 수행·남은 확인을 나누며 현장 수행자와 전달받은 사람을 구분한다. |
| IR03 불완전 결과를 먼저 알리는 보고 | 작업 없음·해방/분리까지만 수행·송수 후 하류 미확인·하류 확인 후 인수 부족을 서로 다른 기록과 첫 보고로 표현한다. |
| IR04 현재 근거에 한정한 누락 보완 | C03의 빠진 연결과 C03-R의 해방 뒤 남은 자료를 현재 대조하고, 자료·접근이 없으면 미확인 이유와 다음 확인 후보를 드러낸다. |
| IR05 상대가 맡을 일 중심의 문답 | C06의 질문한 점검·부담만 실제 근거로 보완하고 C06-M은 현재 아침의 인수·영향받은 새 점검·운영·배편으로 잇는다. |
| IR06 짧은 안내와 요청 시 상세 열람 | 현재 필요한 차이는 짧게, 실제 보유·전달된 상세 기록은 필요할 때 살펴본다. 저녁의 기록 용도와 아침의 새 결과를 구분한다. |

여섯 항목의 전체 범위·이점·비용과 공통 경계는 [Scenario](../Narrative/Scenario.md#벨레스-첫-장의-상호작용과-기록-상세)가 소유한다. ‘요청 시’는 인물이 기록을 펼치거나 아는 당사자에게 필요한 부분을 다시 묻는 표현 방향이다. 구체적 입력·시스템이나 없는 자료·멀리 있는 사람에게 즉시 접근하는 기능은 확정하지 않는다.

플레이어 열람·이해, 인물이 실제 아는 범위, 물리 작업, 주민 인수, 현재 운영, 실제 출항을 구분한다. 장소 방문·처치·기록 열람·대화 종료·서명으로 나머지를 완료하지 않는다. 실내 직접 대응·바르툴 직접 전투·모든 무기 선택·해방·생존 이격을 유지하고 설명을 위해 위협을 멈추거나 결박·과거 동작을 재연하지 않는다. 현재 조사 접근·귀환 안전을 보장하지 않는다.

같은 세계의 실제 성과와 현재 변화는 나누고 명시적 저장 복원은 결정 5·21의 기존 계약을 따른다. 미확인 정보·물량·시간을 자동 충족시키지 않으며 실제 자료 없는 답·무한 자원·대리 수리·무상 회복·숨은 시한·자동 보충은 추가하지 않는다. 미래 보충과 현재량을 구분한다. 스승과 마렌을 구분하고 린은 첫 출항의 부두에 남는다. 마렌·이르의 현장/원격 합류·새 신상·가족사·연애·후일담을 추가하지 않으며 첫 장은 실제 출항 뒤 상층 수관에서 닫는다.

IRA01-IRA02·IRH01-IRH06과 기존 원문·대안·보류·도안·좌표·수치를 보존한다. PRH05·VDH05·IWH01-IWH02는 위 표현 범위만 구체화했으며 나머지 보류를 일괄 해제하지 않는다. VI01-VI08·R01-R06·C03-C06·C03-R·C06-M의 상세 표·정확한 문장·전체 원고를 고정 대사·입력 규칙·구현 사양으로 승격하지 않는다. 새 진행 조건·보상·의무 교전·도착 레벨·강제 동쪽 왕복·저장 형식·자동 되감기·미저장 기록 영속·다인 지식 공유는 정하지 않는다.

정확한 대사·기록 규격·도식·UI·입력·음성·카메라·코드·에셋과 실제 UE 구현·실행은 제외한다. 원천 기록·과거 작성 검토는 당시 근거로 유지하며 삭제하거나 덮어쓰지 않는다.

### 트레이드오프

현재 행동과 부족한 사실을 짧게 연결하면 반복을 줄이고 근거·시점·완료 범위를 구분할 수 있다. 반면 짧은 표현을 놓칠 수 있고, 출처·담당 범위를 보여 주면서 기록량과 표현 부담이 늘어난다. 현재 근거가 부족한 사례는 해결된 흐름에 합류할 수 없으며 재열람의 발견성과 접근성은 별도 검증이 필요하다.

IRA01의 매 결과 상세 자동 표시는 누락을 드러내기 쉽지만 반복·시선 분산·전투 방해와 읽기를 지식으로 오인할 위험이 있다. IRA02의 요청 시에만 안내하는 방식은 흐름을 덜 끊지만 무엇을 모르는지 모르면 요청하기 어렵다. 사용자는 짧은 현재 안내와 필요할 때 실제 상세를 살펴보는 조합을 채택했다. 두 대안은 비교 자료로 보존하고 정확한 UI와 실제 효과는 미확정으로 남긴다.

문서 반영·검토는 실제 읽힘·인지·공간·전투·운영·재미·UE 동작의 검증 결과가 아니다.
