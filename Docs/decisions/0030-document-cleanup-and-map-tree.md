# 2026-10-31 — 결정 30: 문서 정리와 map+tree 구조

### 배경

사용자는 설정, 규칙, 문서를 주제별로 세분화하고 색인화해 불필요한 내용을 적게 읽게 하려 한다. 2026-10-31에 남아 있던 세션 기록 16개 중 문서를 읽은 6개를 집계했다. 세션당 전체 읽기량은 중앙값 약 101KB, p90 약 121KB였고, 항상 로드되는 `AGENTS.md`와 자동 스킬 설명은 약 7KB였다. 파일 크기는 집계 시점 값으로 계산했으므로 추정치다.

최상위 문서 38개는 1,007KB이고 32KB 이상인 9개가 64%를 차지한다. `EnvironmentEcology.md`의 78%, `EnvironmentPlan.md`의 45%, `ConceptImageToolTest.md`의 66%는 절 하나에 쌓인 실행 기록과 결과다. 경로를 옮기는 것만으로는 읽는 양이 줄지 않으므로 내용 정리가 먼저다.

### 결정

원본은 주석 태그 `docs-tree-v0`(`5a89fad`)에 둔다. 작업 트리에는 사본을 두지 않는다.

문서를 하나씩 다룬다. 불필요하거나 중복된 내용을 정리한 뒤 내용상 갈리는 경계로만 나눈다. 크기 상한은 두지 않고, 경계가 없는 문서는 나누지 않는다. 원래 문서는 하위를 가리키는 부모 지도가 되고, 부모와 하위 군이 폴더가 된다. 하위에 다시 경계가 있으면 같은 방식으로 한 단계 더 나눈다. 나뉘지 않은 문서는 그 자리에 둔다.

순서는 하위부터다. 잎 문서를 정리해 소유를 확정하고, 그다음 부모 문서, `Docs/README.md`, `AGENTS.md` 순으로 올라간다.

뺄 항목과 나눌 경계는 문서마다 정리안으로 사용자에게 보여 주고 승인을 받은 뒤 적용한다. 확정 수치, 결정 번호, 인터페이스 계약, 미검증 표시는 유지한다. 적용 뒤에는 `preserve.cjs`로 빠진 항목을 대조하고, 일부러 뺀 항목은 허용 파일에 넣고 이유를 커밋 본문에 적는다.

결정 본문, QA 보고서, 서사 정본의 확정 영역은 정리 대상이 아니다. 이 문서들의 링크가 경로 변경으로 깨지면 링크 대상만 현재 경로로 고치고 문장은 유지한다.

`node Tools/Agent/docs.cjs check`가 링크, 앵커, 문서 지도에서의 도달을 검사한다.

### 트레이드오프

하위부터 정리하면 부모를 다시 고치는 일이 줄고 첫 문서들에서 정리 기준을 다듬을 수 있다. 대신 읽기 비용이 가장 큰 `FrameworkPlan.md`와 `Docs/README.md`의 효과는 늦게 나타난다. 크기 상한이 없으면 억지 분리가 없지만 큰 문서가 남을 수 있고, 줄어든 양은 문서를 정리한 뒤에야 측정할 수 있다. 내용 삭제는 Git과 태그로 되돌릴 수 있지만 사용자 승인이 문서마다 필요해 진행이 느려진다.
