# 단계별 구현과 검증 계획

로드맵의 각 단계는 구현, 프로젝트 파일 생성, 빌드, 실행 검사와 코드 검토를 통과한 뒤 제출한다. 2026-10-07 사용자는 단계별 오류 수정과 commit·push 후 다음 단계로 진행하도록 지시했다. 제작 범위는 [Direction](Direction.md), 단계의 완료 기준은 [StudyRoadmap](StudyRoadmap.md)을 따른다.

자연 환경과 실험장의 다음 작업은 [EnvironmentPlan](EnvironmentPlan.md)을 따른다. 아래 내용은 기존 제작 단계의 범위와 검증 기록이다. 현재 기기의 엔진 버전은 실제 Build.version에서 다시 확인한다.

## 선행 검증

최소 전투 에셋 생성과 Standalone, Dedicated Server, Listen Server의 전투·이동 검사를 먼저 수행한다. 현재 노트북 엔진은 `Engine/Build/Build.version` 기준 UE 5.9.0이다. 기존 UE 5.8.1 검증 기록과 구분한다. 최종 프로젝트 파일 생성·CCLEditor 빌드, 에셋 생성, 전투 5개 구성과 이동 4개 구성이 통과했다. 렌더링한 화면 6개를 확인했다. 세부 근거와 남은 검사는 CombatFoundation에 기록했다. 원본 로그는 Git에서 제외한 `Saved/StageValidation/`에 보존한다.

## 구현 순서와 범위

아래 세부 내용은 기존 기획을 실행 가능한 단위로 나눈 구현 초안이다. 최종 아트, 조작감과 밸런스의 사용자 검토를 대신하지 않는다.

| 단계 | 구현 범위 | 검사할 결과 |
|---|---|---|
| 3 | 마을 출발점, 일반 적 구간, 보스 초안과 서버 권위의 승리 상태 | 보스 사망 후 모든 접속자에게 승리 표시, 개별 재도전, 새 접속자의 진행 상태 일치 |
| 4 | 정의 데이터와 인스턴스를 분리한 인벤토리, 장비, 성장·스킬과 UI | 획득·장착·소비·스킬 습득의 서버 검증, 중복 지급·비용 초과 방지, 재스폰 후 상태 유지 |
| 5 | 일반 적의 행동 차이, 보스 패턴 보강, 마을 NPC·상점·퀘스트·튜토리얼 | 콘텐츠가 출발부터 보스 격파까지 연결되고 보상·구매를 중복 처리하지 않음 |
| 6 | 시작·방 생성·접속·종료 UI, 저장·불러오기와 설정 | 입력 검증, 접속 실패 표시, 저장 버전·손상 처리, 로드 후 진행과 성장 상태 복원 |
| 7 | Windows 패키징과 전체 실행 검사 | 에디터 외부 실행, 시작·접속·전투·재도전·저장·종료와 필요한 콘텐츠의 포함 |

공통 시스템은 특정 장르의 플레이어·무기·스태미나를 필수로 요구하지 않는다. 서버가 진행과 아이템 변경을 확정하고 UI는 조회와 요청만 담당한다. 성장 상태는 PlayerState 수명, 월드 진행은 GameState 수명, 로컬 메뉴와 저장 요청은 GameInstance 수명을 기준으로 설계한다. 각 단계의 인터페이스와 대안은 해당 사양서에 구현 전에 기록한다.

## 제출 절차

1. AI는 현재 단계의 사양과 변경 범위를 기록한다.
2. AI는 구현 후 `GenerateProjectFiles.bat`을 프로젝트 대상으로 실행한다.
3. AI는 `CCLEditor Win64 Development`와 해당 단계의 추가 타깃을 빌드한다.
4. AI는 변경된 기능과 기존 기능의 회귀를 실행으로 확인한다.
5. AI는 변경 코드를 다시 검토하고 결함을 수정한다. 수정한 최종 코드에서 생성·빌드와 관련 실행 검사를 반복한다.
6. AI는 단계별 검증 근거와 미확인을 문서에 반영하고 의도한 파일만 commit·push한다.

실패한 검사, 생략한 검사와 시각 검증이 남은 항목은 통과로 기록하지 않는다. 기기별 경로, 로그, 빌드 산출물과 개인 저장 파일은 제출하지 않는다. 엔진 전체 재빌드가 필요하면 작업량과 이유를 먼저 확인한다.

## 단계 3 결과

마을·일반 적 2명·보스·승리 표시와 종료 입력을 연결했다. 생성 BAT·CCLEditor 빌드, 실제 AI 접근·공격, Standalone·Dedicated·Listen 원격·호스트·지연과 손실 구성과 늦은 접속 검사를 통과했다. 기존 전투·이동 회귀와 화면 검사도 수행했다. 추가 검사에서 발견한 빈 내비게이션 브러시와 표지판 회전을 수정했다. 상세 근거와 임시 아트의 한계는 [CampaignFoundation](CampaignFoundation.md)을 따른다.

## 단계 4 결과

서버 권위의 인벤토리·장비·회복품·훈련과 UI를 연결했다. 생성 BAT·빌드, Standalone·Dedicated·Listen 원격·호스트·지연과 손실, 늦은 접속과 소유자 구분 검사를 통과했다. 실제 피해 증가, 재스폰 후 성장 유지, 잘못된 요청 거부와 일반 Actor 보관 한도를 확인했다. 기존 전투·이동 회귀와 렌더링 화면도 확인했다. 상세 근거와 저장 기능의 범위는 [ProgressionFoundation](ProgressionFoundation.md)을 따른다.

## 단계 5 결과

경비병·척후병·보스 체력별 패턴과 마을 안내인·상점·원정 퀘스트·상황별 안내를 연결했다. 실제 클라이언트 거래, 비용·공간 부족 거부, 한 번만 보상, 재스폰과 늦은 접속 검사를 통과했다. Standalone·Dedicated·Listen 원격·호스트·지연과 손실 구성, 기존 성장·전투 회귀와 NPC 화면을 확인했다. 근거와 임시 아트의 한계는 [ContentFoundation](ContentFoundation.md)을 따른다.

## 단계 6 결과

시작·직접 접속·종료 메뉴, 호스트 체크포인트 저장·불러오기와 로컬 그래픽 설정을 연결했다. 생성 BAT·빌드·맵 저장, 별도 프로세스 저장 복원, 부분 진행과 승리 복원, 손상된 슬롯 거부, 방 생성·접속과 접속 실패 검사를 통과했다. Enter 입력으로 실제 시작 버튼을 작동시켰고 메뉴 화면의 크기·줄바꿈·포커스를 수정했다. 기존 콘텐츠·성장·전투 회귀도 통과했다. 저장 정책과 미확인 입력은 [SessionFoundation](SessionFoundation.md)을 따른다.

## 단계 7 결과

Windows Development 패키지를 생성했다. 생성 BAT·CCLEditor·게임과 도구 빌드, 쿠킹·스테이징·아카이브가 성공했다. 패키징한 실행 파일에서 시작·방 생성·접속·접속 실패·저장 복원·성장·콘텐츠·전투·이동·개별 재스폰과 종료를 검증했다. 루트 실행 파일의 기본 시작 화면과 종료 코드도 확인했다. 코드 검토에서 검사 스크립트의 인자 배열과 종료 확인을 보완하고 최종 스크립트로 실행 검사를 통과했다. 화면과 테스트 저장 파일은 배포 폴더 밖에 보존했다. 실행 방법, 로그 근거와 Development·기기별 검증 범위는 [Packaging](Packaging.md)을 따른다.

첫 스모크 실행에서는 세 가지 실패가 나왔다. 개인 세션 검사는 계정 재개방을 일반 초기화 경로에 넣은 수정이 기존 계약을 어겨 실패했다. 재개방을 복원 확정의 명시적 호출로 옮긴 뒤 통과했다. 환경 Dedicated 검사는 게임 역할이 모두 통과했지만, 검사 스크립트가 기록 중인 로그를 쓰기 공유 없이 열어 예외로 끝났다. `run_environment_smoke.ps1`의 로그 읽기를 고친 뒤 통과했다. 이동 Dedicated 검사는 한 번 "Dead character moved"로 실패했고 같은 코드의 재실행에서 통과했다. 사망 직전 입력에 대한 서버 위치 보정이 사망 확인 뒤 도착하는 경합으로 추정하며, 원인은 확인하지 않았다. 실패 기록은 `Saved/Tests/NetworkSmoke/Dedicated-20261011-130301`에 있다.

Windows 게임 패키지는 이번에 다시 만들지 않았다. 따라서 패키지 실행 결과는 [Packaging](Packaging.md)의 기존 기록에 머문다. `LocalPlayerClassName`, 아이템 카탈로그 설정과 재접속 신원 연결이 들어간 패키지는 아직 검증하지 않았다. 렌더링 화면 검사와 지연·손실 구성도 이번에는 실행하지 않았다.
