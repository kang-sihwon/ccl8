# 단계별 구현과 검증 계획

로드맵의 각 단계는 구현, 프로젝트 파일 생성, 빌드, 실행 검사와 코드 검토를 통과한 뒤 제출한다. 2026-10-07 사용자는 단계별 오류 수정과 commit·push 후 다음 단계로 진행하도록 지시했다. 제작 범위는 [Direction](Direction.md), 단계의 완료 기준은 [StudyRoadmap](StudyRoadmap.md)을 따른다.

## 선행 검증

최소 전투 에셋 생성과 Standalone, Dedicated Server, Listen Server의 전투·이동 검사를 먼저 수행한다. 현재 노트북 엔진은 `Engine/Build/Build.version` 기준 UE 5.9.0이다. 기존 UE 5.8.1 검증 기록과 구분한다. 최종 프로젝트 파일 생성·CCLEditor 빌드, 에셋 생성, 전투 5개 구성과 이동 4개 구성이 통과했다. 렌더링한 화면 6개를 확인했다. 세부 근거와 남은 검사는 CombatFoundation에 기록했다. 원본 로그는 Git에서 제외한 `Saved/StageValidation/`에 보존한다.

## 구현 순서와 범위

아래 세부 내용은 기존 기획을 실행 가능한 단위로 나눈 구현 초안이다. 최종 아트, 조작감과 밸런스의 사용자 검토를 대신하지 않는다.

| 단계 | 구현 범위 | 검사할 결과 |
|---|---|---|
| 3 | 마을 출발점, 일반 적 구간, 보스 초안과 서버 권위의 승리 상태 | 보스 사망 후 모든 접속자에게 승리 표시, 개별 재도전, 새 접속자의 진행 상태 일치 |
| 4 | 정의 데이터와 인스턴스를 분리한 인벤토리, 장비, 성장·스킬과 UI | 획득·장착·소비·스킬 습득의 서버 검증, 중복 지급·비용 초과 방지, 재스폰 후 상태 유지 |
| 5 | 일반 적의 행동 차이, 보스 패턴 보강, 마을 NPC·상점·퀘스트·튜토리얼 | 콘텐츠가 출발부터 보스 격파까지 연결되고 보상·구매를 중복 처리하지 않음 |
| 6 | 시작·방 생성·접속·종료 UI, 저장·불러오기와 설정 | 입력 검증, 접속 실패 표시, 저장 버전·손상 처리, 로드 후 진행과 성장 상태 복원 |
| 7 | Windows 패키징과 전체 실행 검사 | 에디터 외부 실행, 시작·접속·전투·재도전·저장·종료와 필요한 콘텐츠의 포함 |

공통 시스템은 특정 장르의 플레이어·무기·스태미나를 필수로 요구하지 않는다. 서버가 진행과 아이템 변경을 확정하고 UI는 조회와 요청만 담당한다. 성장 상태는 PlayerState 수명, 월드 진행은 GameState 수명, 로컬 메뉴와 저장 요청은 GameInstance 수명을 기준으로 설계한다. 각 단계의 인터페이스와 대안은 해당 사양서에 구현 전에 기록한다.

## 제출 절차

1. AI는 현재 단계의 사양과 변경 범위를 기록한다.
2. AI는 구현 후 `GenerateProjectFiles.bat`을 프로젝트 대상으로 실행한다.
3. AI는 `CCLEditor Win64 Development`와 해당 단계의 추가 타깃을 빌드한다.
4. AI는 변경된 기능과 기존 기능의 회귀를 실행으로 확인한다.
5. AI는 변경 코드를 다시 검토하고 결함을 수정한다. 수정한 최종 코드에서 생성·빌드와 관련 실행 검사를 반복한다.
6. AI는 단계별 검증 근거와 미확인을 문서에 반영하고 의도한 파일만 commit·push한다.

실패한 검사, 생략한 검사와 시각 검증이 남은 항목은 통과로 기록하지 않는다. 기기별 경로, 로그, 빌드 산출물과 개인 저장 파일은 제출하지 않는다. 엔진 전체 재빌드가 필요하면 작업량과 이유를 먼저 확인한다.

## 단계 3 결과

마을·일반 적 2명·보스·승리 표시와 종료 입력을 연결했다. 생성 BAT·CCLEditor 빌드, 실제 AI 접근·공격, Standalone·Dedicated·Listen 원격·호스트·지연과 손실 구성과 늦은 접속 검사를 통과했다. 기존 전투·이동 회귀와 화면 검사도 수행했다. 추가 검사에서 발견한 빈 내비게이션 브러시와 표지판 회전을 수정했다. 상세 근거와 임시 아트의 한계는 [CampaignFoundation](CampaignFoundation.md)을 따른다.
