# 벨레스 블록아웃

벨레스 마을에서 숲과 동굴 입구를 거쳐 서쪽으로 돌아오는 실제 UE 공간을 제작한다. 2026-11-16 사용자가 도로 자료 통합, 블록아웃 제작, 실행 검증과 기록을 요청했다. 근거 도안은 [제작 도안 보관과 사용](../ArtDirection/EtherWorldMap/IgnisSharedTerrain.md#제작-도안-보관과-사용)이며, 원본 이미지와 좌표를 보존한다.

## 범위와 완료 조건

별도 `/Game/Maps/VelesBlockout`에 공방·나루, 마을 골목, 숲 입구, 동쪽 진입, 동굴 입구와 출구 앞마당, 서쪽 귀환을 배치한다. 로컬 X는 동쪽, Y는 북쪽이고 UE에는 미터를 센티미터로 변환한다. 지형의 높이는 기존 16비트 고도 자료에서 가져온다. 배치 후보의 실제 크기와 통행을 확인하는 단계이며, 최종 아트·건물 내부·지하 동굴·보스·완성된 몬스터 AI는 범위 밖이다.

완료 조건은 도로 끝점 보존과 상세선 통합, 새 레벨의 저장·재로드, PIE에서 플레이어 생성과 실제 이동, 주요 동선의 지면·충돌 검사, 에디터 화면 대조다. 스크립트 내부 검사와 실제 입력 이동의 증거를 구분한다. 전 구간 수동 플레이·전투 난도·멀티플레이 검증은 수행한 경우에만 완료로 적는다.

## 도로 통합 기준

입력은 [기본 도로](../ArtDirection/EtherWorldMap/Atlas/VelesDetailTerrain-v1/data/connections.json)와 [상세 동선](../ArtDirection/EtherWorldMap/Data/veles-forest-detail-v1.json)이다. 원본을 수정하지 않고 제작용 데이터에서 다음 규칙을 적용한다.

| 구간 | 기본 자료 | 제작 기준 |
|---|---|---|
| R04 작업장 연결 | 두 끝점을 잇는 직선, 폭 3m | 끝점을 보존한 상세 곡선 334.758m. 표면 폭 3m와 구간별 유효 통행 폭 6–8m를 별도 보관한다 |
| R03 동굴 입구–W4 | 마지막 직선 구간, 폭 3m | 마지막 구간만 상세 곡선 326.213m로 바꾼다. 문턱 유효 폭 5m, 이후 6–8m를 사용한다 |
| 나머지 도로 | 기존 절점과 폭 | 기존 자료를 유지한다. 마을 출입구 연결로 2.2m를 전투 통로 규격으로 해석하지 않는다 |

상세 도면의 폭은 장애물을 제외한 유효 공간이고 기본 도안의 폭은 도로 표면 후보다. 두 값이 다르다는 이유만으로 기본 도로를 모두 넓히지 않는다. 상세안의 작업 단과 엄폐물을 함께 배치하며, 원본의 과거 S01 전투 배치를 가져오지 않는다. 현행 적 배치의 근거는 [고블린·야생동물 분포](../Narrative/Drafts/2026-10-31-ether-taiga-dawn/2026-11-06-opening-and-continent/2026-11-07-goblin-territories-and-wildlife.md)다.

## 현재 상태

공방–물터–숲문 284.947m의 [실리소스 제작·검증 결과](VelesBlockout/ArtSlice-2026-11-16.md)를 완료했다. 별도 VelesArtSlice에서 건축 외형 8동과 식생 795개를 배치했고 왕복 이동·네 번의 카메라 회전·엔진 CSV 측정을 마쳤다. 다음은 지면·수면·조명과 원경 정리, 전투·NavMesh, 목표 환경의 패키지 성능 검증이다. 최종 아트와 전투 완료는 아니다.

별도 [VelesBlockout 레벨](https://github.com/kang-sihwon/ccl8/blob/d65f96af09f94751d57ac0735e07e8617c2f082c/Content/Maps/VelesBlockout.umap)의 제작·저장·재로드와 주요 순환로의 PIE 이동 검증을 완료했다. UE 5.8.3의 Unreal MCP를 사용했다. Campaign과 원본 도안은 변경하지 않았다. 현재 단계는 공간 배치와 통행을 확인한 블록아웃이며 최종 아트나 전투 콘텐츠의 완료가 아니다.

![벨레스 블록아웃 전체 배치](VelesBlockout-preview.png)

## 제작한 공간

제작 영역은 로컬 `[-512, -128]–[640, 1536]m`, 1,152×1,664m다. 전체 v5 도안에서 마을과 첫 숲 순환로에 필요한 영역을 골랐다. 원본 고도에서 596m를 뺀 값을 UE의 Z로 사용한다. 배치 근거는 [고도 규격](../ArtDirection/EtherWorldMap/Atlas/VelesDetailTerrain-v1/manifest.json)과 [건물·시설 좌표](../ArtDirection/EtherWorldMap/Atlas/VelesDetailTerrain-v1/data/placements.json)다.

- 건물 외곽 86동과 출입구 표식 86개, 기본 도로 103개의 영역 안 선분을 배치했다. 건물은 내부가 없는 충돌 상자다.
- 숲 대체물 326개, 상세안의 작업 단과 엄폐물, 교량 7개, 동굴 문틀을 배치했다. 문틀은 동쪽 진입선과 서쪽 귀환선 사이 방향을 향한다.
- 나루의 기존 점 `[0, 0]m`는 강 중심선에 있다. 물가 길의 끝 `[-46, 20]m`에서 그 점까지 폭 3m의 임시 잔교를 연결했다. 새 제작 후보이며 원본 나루 좌표는 옮기지 않았다.
- 강·개울은 충돌 없는 색 띠로 표시한다. 수심·부력·수영·유속을 구현한 물이 아니다. 강 폭 55m는 검토용 단순화다.

지형은 원본 2m 간격 고도를 8m 간격으로 읽은 StaticMesh이며 정점 30,305개, 삼각형 59,904개다. 빠르게 재생성하고 다른 레벨과 분리하기 쉽지만, Landscape의 편집·지형 재질·스트리밍을 대신하지 않는다. 도로 슬래브는 통행 공간을 표시한다. R03·R04 상세 부분의 슬래브 폭은 유효 통행 폭이며, 원본 도로 표면 폭 3m는 제작 데이터에 별도로 보존한다. 이 구분은 최종 흙길 재질을 만들 때 적용해야 한다.

## 재현과 검증 경로

[자료 준비](../../Tools/WorldBuilding/prepare_veles_blockout.py)는 호스트 Python과 Pillow를 사용한다. 원본 여섯 파일의 해시와 도로 끝점을 검사하고 제작용 데이터를 만든다. [레벨 제작](../../Tools/WorldBuilding/create_veles_blockout.py)은 에디터 Python에서 실행하며, 별도 레벨의 소유 표식과 `VB_` 액터 이름을 사용한다. 공유 엔진 에셋은 읽기만 한다.

[충돌 검사](../../Tools/WorldBuilding/verify_veles_blockout.py)는 에디터의 실제 지면을 추적하고 반지름 42cm·반높이 96cm 캡슐로 장애물을 검사한다. [PIE 순환로 검사](../../Tools/WorldBuilding/walk_veles_blockout.py)는 단일 로컬 PIE의 PlayerStart에서 시작한다. 실행 중 다시 호출하지 않는다. 이동·시점의 Enhanced Input Action을 주입하고 좌표를 기록하며, 순간이동이나 이동 속도 변경은 하지 않는다. 이 경로는 기존 Campaign 진행·전투 스모크와 별개다.

현재 지면·통로 검사는 R01, R02, R03, R04, 물가 길, 서쪽 귀환과 잔교의 2,778개 지점에서 통과했다. 장애물 검사는 중심선을 따라 수행했으므로 폭 전체의 통행이나 회피·적 합류를 검증한 결과는 아니다. 교량과 작업 단은 지형 경사를 반영해 배치했고, 동굴 문틀은 양쪽 접근을 막지 않도록 방향을 맞췄다.

## 실행 결과

2026-11-16 단일 로컬 뷰포트 PIE에서 공방 → 동쪽 숲길 → 동굴 문턱 → 서쪽 귀환 → 공방의 37개 경유점을 통과했다. 설계 중심선은 3,368.478m이고 실제 위치 변화의 합은 3,366.343m다. 기본 이동 속도 500cm/s에서 673.046초, 약 11분 13초가 걸렸다. 기록한 위치 표본 673개에서 낙하 상태는 없었다. 증거 강도는 `MCP/EI`이며, 키보드를 누르는 수동 플레이와 전투 검증은 아니다.

| 검사 | 결과와 범위 |
|---|---|
| 자료 통합 | PASS. 원본 여섯 파일의 해시, 도로 103개의 끝점, 변경하지 않은 도로의 절점 보존 |
| 에셋 저장·재로드 | PASS. 레벨 액터 2,119개, 제작 데이터 액터 2,101개의 누락 없음. Campaign을 거쳐 다시 로드 |
| 지면·통로 | PASS, `internal`. 지면 표본 2,778개와 반지름 42cm·반높이 96cm 장애물 검사 |
| 실제 순환로 이동 | PASS, `MCP/EI`. 순간이동·속도 변경 없이 37개 경유점을 통과해 출발점 1m 이내로 복귀 |
| 화면 검토 | 전체 배치, 물가·마을 확대, 숲 진입·귀환 PIE 화면 확인. 물줄기는 최종 수면이 아닌 위치 표식 |
| 프로젝트 파일 생성 | PASS. 프로젝트를 대상으로 생성 |
| CCLEditor 빌드 | PASS. Win64 Development, 엔진 변경 없이 183.19초 |
| 코드·문서 검사 | `cpp-rules check`, `cpp-rules format`, `floor-guard` 통과. 문서 링크 오류 0건 |

제작 중 GeometryScript 입력과 맵 참조 수명 문제로 에디터가 두 차례 종료됐다. 노멀·UV0를 채우고 World를 미리 읽어 유지하지 않도록 로딩 순서를 수정한 뒤 생성·재로드·이동 검증이 통과했다. 최초 지형 변환 오류의 전체 원인을 엔진 결함으로 확정하지는 않는다. 마지막 물 표식 보정은 충돌 없는 액터만 바꿨고, 주행 검증 당시의 모든 충돌 액터·지형·경로 데이터가 동일함을 대조했다. 최종 충돌 검사도 다시 통과했다.

PIE와 관측기를 종료하고 원래 Campaign을 다시 연 뒤, 검토를 위해 VelesBlockout을 열어 두었다. 새 레벨은 Play로 바로 확인할 수 있다. 순수 이동만 11분 이상 걸리므로 전투를 추가하기 전에 사용자가 탐색 밀도와 반복 이동 부담을 검토하는 것이 다음 판단이다. 현행 거리를 유지하면 지역 규모를 보존하고, 줄이면 왕복 부담이 감소하지만 원본 좌표와 서사 동선의 별도 수정안이 필요하다.

## 남은 범위

지하 동굴, 건물 내부, 최종 Landscape·식생·수면, 길 폭 전체의 회피와 카메라 여유, NavMesh·적 AI·전투, 멀티플레이와 패키지는 미검증이다. 서사 자료의 적 배치를 블록아웃에 구현했다고 취급하지 않는다. 순수 이동 시간은 조우·탐색·실패 후 재도전 시간을 포함하지 않으므로 첫 구간의 최종 플레이 분량으로 확정하지 않는다.

## 실리소스 제작 전 검토

[v5 대조와 실리소스 제작 검토](VelesBlockout/Review-2026-11-16.md)는 배치·동선 차이, 플레이 높이의 화면, 다음 제작 순서를 판단할 때 읽는다. 주요 시설 좌표는 유지할 기반이 있지만 숲 군집, 동굴 암벽과 길·강변 접속의 보완이 필요하다. 다음 후보는 공방–물터–숲문 약 285m를 실제 리소스로 먼저 제작하고 이동·카메라·적 가독성·비용을 검증하는 것이다. 이 순서는 제안이며 검토 중 레벨이나 게임 에셋은 변경하지 않았다.

## 실리소스 시험 구간 제작

사용자가 승인한 공간 보완과 공방–물터–숲문 실리소스 배치·검증을 별도 `/Game/Maps/VelesArtSlice`에서 완료했다. 보유 식생·소품·목재 텍스처와 새 건축·암벽 메시를 사용했다. 저장·재로드, 왕복 입력 이동 566.989m, 네 번의 약 360도 회전과 실제 화면을 확인했다. 최종 엔진 CSV는 평균 10.952ms, GPU 평균 5.603ms였으며 에디터·캡처 비용을 포함한다. 측정 조건, 순간 지연, 실패 수정과 다음 단계는 [실리소스 제작·검증 결과](VelesBlockout/ArtSlice-2026-11-16.md)를 읽는다.

이번 검사에서 원본 지형의 충돌 삼각형이 아래를 향하는 것을 확인했다. 비교용 VelesBlockout은 보존했고 VelesArtSlice의 독립 지형에서 수정했다. 앞선 원본 순환로 성공은 도로 슬래브 위 이동의 증거이며, 길 밖 지형의 정상 충돌까지 확인한 결과는 아니다.
