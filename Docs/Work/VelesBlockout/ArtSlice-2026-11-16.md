# 벨레스 실리소스 시험 구간 제작·검증

공방–물터–숲문 284.947m를 같은 좌표의 별도 [VelesArtSlice 레벨](https://github.com/kang-sihwon/ccl8/blob/d65f96af09f94751d57ac0735e07e8617c2f082c/Content/Maps/VelesArtSlice.umap)에 제작했다. 길·교량 접속과 강변을 보완하고 건축 외형 8동, 보유 식생 795개와 소품 7개를 배치했다. UE 5.8.3의 Unreal MCP에서 왕복 이동, 카메라 회전과 프레임 시간을 검증했다. 원본 v5 자료와 VelesBlockout, Campaign은 변경하지 않았다.

사람 크기, 지붕과 식생이 함께 보이는 플레이 가능한 환경 시험본이다. 완성된 게임 배경으로 판정하지는 않는다. 지면과 길 가장자리, 수면, 건물 재질·조명, 원경의 대체물이 아직 시험 장면의 인상을 남긴다. 이 기록은 [제작 전 검토](Review-2026-11-16.md)의 P0·P1을 대표 구간에 적용한 결과이며, P2의 이동·카메라·성능을 다룬다. 전투·적 가독성·NavMesh는 포함하지 않았다.

## 제작 범위

| 대상 | 결과 |
|---|---|
| 지면·길 | 지형 충돌면을 위쪽으로 수정한 독립 메시. 8m 지형 삼각형에 맞춘 흙길 표면과 주변 기존 슬래브의 표시·충돌 해제 |
| 건축 | 기존 외곽과 위치를 유지한 8동. 지붕·처마·기둥·굴뚝·창·문·기초·측면 울타리 280개 요소 |
| 식생 | 성목 70, 어린나무 95, 관목 140, 양치식물 170, 풀 320. 기존 NorwayMaple·Fishermans Cabin·PN Fern 리소스 |
| 물가 | 강변 암석 112개. 가까운 교량 4개의 상판을 25cm 올리고 사방에 2m 경사 접속면 추가 |
| 소품 | 보유 목재 팔레트와 통 7개. 공방과 물터 주변에 배치 |
| 동굴 | 시험 구간 밖 입구에 암벽 덩어리 6개 추가. 입구 주변의 큰 형태를 확인한 단계이며 지하 동굴·내부 통로 플레이는 미검증 |
| 저장 | 액터 3,324개. 원본 블록아웃을 거친 재로드, 동일 액터 수와 검사 통과, 저장되지 않은 맵 변경 없음 |

건축과 암벽은 새로 만든 시험용 메시다. 완성 건축 팩을 배치한 결과와 구분한다. 보유 식생 메시·소품·목재 텍스처는 그대로 참조하고, 별도 잎 재질의 알파 마스크를 사용했다. 공유 원본 에셋은 수정하지 않았다. 개별 StaticMeshActor 배치는 위치 조절과 문제 추적이 쉽지만 전체 지역으로 확장할 때는 인스턴싱과 가시 거리 관리가 필요하다.

## 실제 플레이 화면

아래 세 장은 최종 왕복 검사 중 실제 CCLCharacter와 HUD가 보이는 PIE 창을 캡처했다. 순간이동, 이동 속도 변경, 별도 촬영용 카메라를 사용하지 않았다.

![공방 앞 실제 PIE](art-workshop-pie.png)

공방에서는 캐릭터와 처마·문·창의 크기를 비교할 수 있다. 마당과 물가에 생활 소품이 생겼지만 외벽의 재질 세부와 그늘의 밝기, 지표 식생 밀도는 더 다듬어야 한다.

![물터 교량 실제 PIE](art-waterpoint-pie.png)

물터에서는 상판 위를 걸으며 양쪽 건물과 갈림길을 볼 수 있다. 수면보다 높아진 상판과 경사 접속면은 양방향 이동을 통과했다. 수면은 여전히 충돌 없는 위치 표식이며, 하상·부력·유속은 구현하지 않았다.

![숲문 실제 PIE](art-forestgate-pie.png)

숲문에서는 양쪽 나무 군집으로 길의 경계가 읽힌다. 열린 먼 배경에는 기존 대체물이 보이고, 길의 반복 재질과 일부 접합선도 남아 있다. 다음 아트 작업은 지면 레이어·길 가장자리와 중경 차폐를 우선한다.

![동굴 암벽 에디터 확인](art-cave-editor.png)

동굴 이미지는 에디터 캡처다. 암벽이 입구를 둘러싸지만 기존 문틀과 상부 틈, 주변 대체물은 남아 있다. 공방–숲문 PIE 검증의 범위를 동굴 내부까지 확장하지 않는다.

## 이동·카메라 결과

최종 왕복 경로는 R01의 앞 네 절점과 그 역순이다. 설계 중심선 길이는 569.893m이고 실제 위치 변화의 합은 566.989m다. 각 경유점 70cm 이내에서 다음 구간으로 전환하므로 두 값은 조금 다르다. 총 184.735초에는 준비 15초와 네 번의 회전 시간이 포함된다.

| 검사 | 결과 | 증거 강도와 한계 |
|---|---|---|
| 왕복 이동 | PASS. 7개 경유점, 교량 양방향 통과, 낙하 상태 표본 0 | `MCP/EI`. Enhanced Input 주입. 수동 키보드 조작감·키 매핑 검사는 아님 |
| 카메라 | PASS. 공방 출발·물터·숲문·공방 복귀에서 각각 359.996–359.997도 | `MCP/EI`. 회전 입력으로 실제 Controller yaw 누적량 확인 |
| 카메라 겹침 | 표본 0건 | 0.25초마다 카메라 원점의 반지름 5cm 구형 추적. 프러스텀 전체·모든 골목의 충돌 보장은 아님 |
| 지면·신규 장애물 | PASS. 441개 지점, 캡슐 반지름 42cm·반높이 96cm | `internal`. 중심선과 좌우 1m의 세 선, 2m 간격. 지형·교량을 바닥으로, 새 VA_ 충돌 액터를 장애물로 검사. 폭 전체와 전투 회피 공간은 미검증 |
| 자료 보존 | PASS. 원본 여섯 자료의 해시 일치 | 원본 좌표·도로·고도 자료 보존 |
| 저장·재로드 | PASS. 3,324개 액터, 재로드 후 같은 검사 통과 | 맵 검사 오류·경고 0, dirty 상태 false |

## 성능 측정

UE 5.8.3, CCLEditor Win64 Development, RTX 4070 Ti 12GB, D3D12 SM6의 단일 로컬 플로팅 PIE에서 측정했다. 화면 캡처는 제목 표시줄·테두리를 포함해 1280×774px다. 내부 렌더 해상도는 별도로 고정하지 않았다. `r.ScreenPercentage=0`, 동적 해상도 0, `t.MaxFPS=0`, VSync 0, ViewDistance·Shadow·Foliage 품질 3이었다. 측정 중 빌드 작업은 실행하지 않았다.

준비 15초 뒤 엔진 CSV 프로파일러를 시작하고 왕복 완료 시 종료했다. 아래 값은 엔진 CSV이며 Slate 콜백 간격을 FPS로 환산한 값이 아니다. 최종 배치본은 15,496프레임을 기록했다.

| 항목 | 원본 블록아웃 참고 측정 | 최종 배치본 |
|---|---:|---:|
| 평균 FrameTime | 10.036ms | 10.952ms |
| FrameTime p95 / p99 | 11.639 / 13.011ms | 12.588 / 13.792ms |
| 평균 시간으로 환산한 FPS | 99.64 | 91.30 |
| 평균 GameThreadTime | 9.697ms | 10.941ms |
| 평균 RenderThreadTime | 10.010ms | 10.255ms |
| GPU 평균 / p95 | 3.827 / 4.224ms | 5.603 / 7.485ms |
| RHI DrawCalls 평균 | 2,086 | 2,365 |
| 50ms 초과 / 최대 FrameTime | 3회 / 78.617ms | 7회 / 169.009ms |

최종 실행은 화면 캡처 네 번을 포함한다. 원본 참고 실행 뒤 검증 스크립트의 시점 감쇠를 개선했으므로 두 실행을 엄밀한 성능 회귀율로 해석하지 않는다. 최종 실행의 순간 지연 전부를 리소스 비용이나 캡처 탓으로 확정할 수도 없다. GPU 평균 증가와 개별 액터·드로콜 비용은 확장 전에 볼 항목이다. 측정 중 텍스처 요청 데이터 적재율은 100%였다. 에디터가 이미 적재한 자원을 공유하므로 프로세스 GPU 메모리로 장면별 VRAM 비용을 분리하지 않았다.

이 조건에서는 대부분 프레임이 16.67ms 이내였지만, 목표 기기·해상도·프레임 예산을 확정한 최종 합격 판정은 아니다. 패키지, 전투, AI, 스트리밍 경계와 낮은 사양은 별도 측정이 필요하다.

## 발견한 문제와 정정

- 원본 지형은 위에서 쏜 추적에 맞지 않고 아래에서 맞는 역방향 충돌 삼각형이었다. 기존 도로 슬래브를 감추자 실제 Pawn이 지면 아래로 떨어져 실패했다. 별도 위쪽 지형 메시를 만든 뒤 상향 법선·왕복 주행을 확인했다. 이전 원본 블록아웃의 통행 성공은 슬래브 위 이동의 증거이며 길 밖 지형 충돌까지 확인한 결과로 해석하면 안 된다. 비교용 원본 맵에는 이 수정이 들어 있지 않다.
- 보유 나무의 기존 재질 조합에서는 잎 카드가 불투명 삼각형으로 보였다. WPO·Nanite 설정만 바꿔서는 해결되지 않았고, 원본 잎 텍스처 알파를 사용하는 별도 masked 재질로 해결했다. 엔진이나 Nanite 자체의 결함으로 원인을 확정하지 않았다.
- 교량 상판을 높인 직후 진입 단차가 MaxStepHeight 45cm를 넘는 지점에서 `No movement progress for 15 seconds.`를 재현했다. 사방 경사 접속면을 추가한 뒤 동일 구간의 왕복 입력 검사를 통과했다.
- 회전 목표 주변의 과도한 검증 입력이 화면을 계속 흔들었다. 검증 스크립트의 입력 감쇠와 실제 누적 회전량 검사를 추가했다. 게임 카메라 코드는 변경하지 않았다.
- 숨겨진 에디터의 3FPS 실행과 빌드가 겹친 실행은 최종 성능 값에서 제외했다. 플로팅 PIE에서 다시 측정했으며, 중간 실패와 원본 로그는 로컬 증거로 보존했다.

## 재현·완료 확인

[제작 스크립트](../../../Tools/WorldBuilding/build_veles_slice.py), [정적 공간 검사](../../../Tools/WorldBuilding/audit_veles_slice.py), [PIE 왕복 검사](../../../Tools/WorldBuilding/validate_veles_slice.py), [엔진 CSV 요약](../../../Tools/WorldBuilding/summarize_veles_profile.py)이 재현 경로다. 제작은 기존 자료 준비 이후 에디터 Python에서 실행한다. 기존 이름의 생성 에셋은 재사용하므로 메시 형상을 바꾸는 후속 작업에서는 에셋 갱신도 함께 해야 한다.

Doctor에서 UE 5.8.3 설치와 실행 중인 CCL 에디터, Unreal MCP 연결을 확인했다. 게임 DLL은 Source의 마지막 변경 커밋보다 새 버전이었다. 프로젝트 파일 생성은 8.00초에 통과했고 CCLEditor Win64 Development 빌드는 4.75초에 최신 상태를 확인했다. C++ 규칙·포맷·floor-guard 통과, 문서 588개의 링크·지도 검사 오류 0건, 새 Python 파일 네 개의 구문 검사를 확인했다. 원본 로그의 기기별 경로를 제외한 [검증값과 CSV 해시](art-validation.json)를 함께 보존한다.

PIE와 관측기를 종료하고 임시 백그라운드 틱 설정 및 GPU CSV 설정을 복원했다. 원래 블록아웃을 거쳐 재로드한 VelesArtSlice를 검토용으로 열어 두었고 에디터 카메라는 작업 전 값으로 돌렸다.

## 다음 우선순위

1. 지면·길 가장자리·수면·조명을 다듬고, 시험 구간 끝에서 보이는 대체물을 중경·원경 구성으로 정리한다. 기존 좌표를 유지한 채 화면의 시험장 인상을 줄이는 작업이다.
2. 같은 구간에서 회피·전투 카메라, 대표 적 가독성·추적과 NavMesh 연결을 검증한다. 이번 이동 통과로 전투 공간의 여유까지 확정하지 않는다.
3. 식생 인스턴싱·LOD·가시 거리와 목표 해상도를 정한 뒤 패키지 성능 및 순간 지연 원인을 측정한다. 통과 후 동쪽 진입·서쪽 귀환·동굴 접근으로 확장한다.
