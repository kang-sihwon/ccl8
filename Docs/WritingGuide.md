# ccl8 문서 작성 가이드

저장소에서 읽히는 글을 쓰고 고칠 때의 기준이다. 대상은 프로젝트 문서, 저장소 지침, 커밋 메시지, 스킬 문서다. 기준 독자는 며칠 뒤 다른 기기에서 앞선 대화 없이 처음 읽는 사람과 에이전트다.

## 새 문서의 파일 형식

CCL에서 새로 만드는 모든 프로젝트 문서는 위치와 종류에 관계없이 HTML로 작성하고 `.html`로 저장한다. 새 문서를 문서 지도에 등록하거나 다른 문서에서 인용할 때는 해당 HTML 파일을 직접 연결한다. 하위 지침이나 예시가 새 문서 이름을 `.md`로 제시해도 이 형식 규칙을 우선한다. 기존 문서를 수정할 때는 현재 파일에서 작업한다.

## 모바일 원격 열람

휴대폰에서 원격으로 열 HTML 문서를 안내할 때는 GitHub에 올라간 파일의 HTTPS 링크를 답변에 넣는다. 주소는 `https://github.com/kang-sihwon/ccl8/blob/<브랜치 또는 커밋>/<저장소 기준 경로>` 형식으로 만들고, 링크 이름에는 문서 제목과 ‘GitHub 원본’을 표시한다. 전달할 버전이 아직 로컬에만 있으면 원격 반영 전이라고 알린다.

GitHub 원본 링크는 HTML 소스 보기용이다. 같은 버전이 GitHub Pages에 배포되어 있으면 실제 페이지가 열리는 ‘문서 보기’ 링크를 먼저 제공하고 원본 링크를 함께 둔다. HTML 안에서 이웃 문서나 이미지를 가리킬 때는 상대 경로를 사용한다.

## 기본 원칙

- 결론을 먼저 쓴다. 문서, 절, 문단 모두 결과부터 적고 과정은 뒤에 둔다.
- 앞선 대화를 가리키는 표현은 구체적인 문서, 결정, 사건으로 바꾼다.
- 한 문장에는 중심 판단 하나를 담는다. 조건, 근거, 결과가 길게 이어지면 인과를 유지한 채 문장을 나눈다.
- 사실, 분석, 추론, 미확인을 구분한다. 문장을 다듬을 때 가능성을 단정으로 바꾸거나 원문에 없던 이유를 넣지 않는다.
- 결정과 수치에는 문서에 남은 근거를 붙인다. 근거가 없으면 미기록 또는 미확인이라고 쓴다.
- 비유를 쓰면 실제로 무엇이 바뀌고 어떤 문제가 생기는지 이어서 쓴다.

## 문서의 종류와 소유

문서를 쓰기 전에 종류를 정한다. 종류가 수정 규칙을 정한다.

| 종류 | 예 | 수정 규칙 |
|---|---|---|
| 규범 | `AGENTS.md`, `Docs/Coding.md`, 이 문서 | 코드나 작업이 규칙을 어기면 규칙을 낮추지 않고 위반을 기록한다 |
| 사양 | `*Foundation.md`, `EnvironmentPlan/`의 시스템 문서 | 확정 수치와 인터페이스 계약에 근거 결정 번호를 붙인다. 구현과 다르면 구현을 확인해 고친다 |
| 정본 | `Docs/Narrative/World.md`, `Docs/Narrative/Scenario.md` | 사용자가 승인한 내용만 적고 항목마다 근거 결정을 붙인다. 바꾸려면 사용자 승인과 새 결정이 필요하다 |
| 이력 | `Docs/decisions/`의 결정 파일 본문, 날짜 붙은 QA·검토 보고서, `Docs/Narrative/Research/`의 조사 기록 | 다시 쓰지 않는다. 정정은 새 항목으로 붙인다. 경로가 바뀌면 링크 대상만 고친다 |
| 절차 | `Docs/Mentoring.md`, `Docs/AgentContextTools.md`, `Docs/Narrative/Workflow.md` | 실제로 실행한 단계만 적고 단계마다 누가 무엇을 하는지 쓴다 |
| 현황 | `Docs/Work/`의 작업 지도, `Docs/LearningLog.md`, `Docs/Narrative/CurrentWork.md` | 지금 상태와 다음 행동만 적는다. 지난 상태는 이력 문서나 Git이 맡는다 |
| 참조 | `Docs/Decisions.md`, `GLOSSARY.md`, `Docs/NarrativeConcept.md`, `Docs/Narrative/Glossary.md`, 로드맵 | 빠짐없이 적는다. 원본과 다르면 원본이 맞다 |

한 주제는 한 문서가 소유한다. 소유는 [문서 지도](README.md)와 그 아래 부모 문서가 정하고, 새 문서는 가장 가까운 부모에 한 줄로 등록한다. 서사 문서의 소유는 [NarrativeConcept](NarrativeConcept.md)가 정한다. 시스템 학습 문서는 [시스템 학습 문서 작성 규칙](SystemExplanationGuide.md)을 함께 따른다.

## 문서 구조

문서는 지도와 잎으로 이뤄진 트리다. [문서 지도](README.md)는 분야별 문서를 가리키고, 큰 문서는 부모가 되어 하위 문서를 "읽는 때"와 함께 가리킨다. 근거는 [결정 30](decisions/0030-document-cleanup-and-map-tree.md)이다.

- 내용상 작업이 갈리는 경계가 있을 때만 나눈다. 크기 상한은 두지 않는다.
- 나누기 전에 불필요하거나 중복된 내용을 정리한다.
- 부모는 원래 경로에 두고, 하위는 부모와 같은 이름의 폴더에 둔다.
- 지도의 한 줄은 내용 소개가 아니라 언제 읽는지를 적는다.
- 실행 기록은 결론, 검사 범위, 측정값만 남긴다. `Saved/` 경로, 수정 내역, 반복 명령, 소스 코드 사본은 쓰지 않는다.
- `node Tools/Agent/docs.cjs check`가 링크, 앵커, 지도 도달을 검사한다.

## 검토 순서

1. 사실, 결정, 상태, 출처를 원본과 대조한다.
2. 제목과 문단 첫 문장만 읽어도 흐름이 이어지는지 본다.
3. 긴 문장, 생략된 주어, 모호한 지시어, 불필요한 영어를 고친다.
4. 코드 블록, 직접 인용, 식별자가 원문대로인지 대조한다.
5. 소리 내어 읽었을 때 한 번에 이해되지 않는 문장을 나눈다.
6. `ccl8-writing` 스킬의 참조로 AI 문체, 맞춤법, 표기 일관성을 본다. 표기 일관성은 [문장과 표기](WritingGuide/Style.md)를 스타일 가이드로 삼고, 그와 어긋나는 제안은 적용하지 않는다.
7. 마지막에 `ccl8-writing`의 납품 점검을 한다. 참조의 em dash 금지와 전달 이력 금지에는 결정 파일 제목, `결정 N`과 커밋 해시 인용의 예외를 둔다.
