# NG01-NG04 이후 작업군 추천

**NG08의 로덴·세르나·하르덴 운영·인계 작성·독립 검토를 완료했다. 다음 선택은 HO01-HO06·공통 경계다.** NG05는 조사 누락·중간 귀환·부분 복구·인수 부족 뒤의 판단을 PR01-PR07로 구체화했다. 작성·독립 검토를 마친 PR01-PR07·공통 경계는 사용자 승인으로 [결정 61](../../decisions/0061-veles-progression-resume-adoption.md)·Scenario에 반영했고 반영 검토도 PASS이며 잔여 지적은 없다.

이 문서는 후속 작업의 순서·완료 기준과 진행 결과를 소유한다. NG05의 작성·채택은 완료했다. NG06은 설계 작성·독립 검토를 완료하고 VD01-VD06·공통 경계의 사용자 채택을 정본에 반영했으며 NG07은 사용자 요청으로 작성·독립 검토를 완료했고 NG08도 작성·독립 검토 PASS로 완료했다. HO01-HO06·공통 경계는 미채택 DISCUSSION이며 실제 실행은 미착수다. NG05 작성 자체와 사용자 채택을 구분하며, 이번 PR 채택도 남은 상세 보류 해제나 실제 구현 지시가 아니다. 보류 원문과 부분 채택의 경계는 [남은 보류 지도](remaining-holds.md), 완료된 NG01-NG04는 [상위 작업군 지도](../WorkGroups.md)가 소유한다.

[당초 추천의 독립 검토](../Reviews/2026-11-15-next-workgroups-review.md)는 PASS이며 잔여 지적은 없다. 그 검토 당시에는 NG05도 미착수였다. 이후 NG05의 실행 결과와 검토는 아래에서 별도로 추적한다.

## 우선순위와 의존

| 순위 | 작업군·첫 범위 | 먼저 하는 이유 | 선행 입력·완료 산출물 |
|---|---|---|---|
| 1 | [NG05 첫 장 진행·재개 규칙](#ng05-첫-장-진행재개-규칙) | 정보·작업·운영 인수와 저장·재접근을 구분해야 뒤의 문장·공간 설계가 흔들리지 않는다. | 현행 정본·C01-C06·VI/VT → 조건·전이·재개 비교표와 선택안·검토 |

| 3 | [NG07 첫 장 통합 집필과 정보 전달](#ng07-첫-장-통합-집필과-정보-전달) | 규칙·공간 제약을 받아야 정확한 대사와 재전달 장면을 다시 고치는 일을 줄일 수 있다. | NG05의 선택된 조건·NG06의 고정/미확인 구분 → 정상 원고와 필요한 대체 장면·정보 대조 |

순위는 개발 일정이나 소요 시간 약속이 아니다. NG06은 NG05 권장안을 가정으로 표시한 상태에서 준비할 수 있다. NG07도 기존 정상 원고를 재사용하고 미확정 지점만 표시해 초안을 쓸 수 있지만, 서로 다른 미채택 가정을 한 확정 흐름으로 합치지는 않는다. NG08의 원문 대조는 별도로 가능하되 첫 장을 제쳐 두고 전 대륙을 다시 작성하는 일을 기본 경로로 삼지 않는다.

**추천 경로는 NG05 → NG06 → NG07이다.** NG08은 후속 지역 상세가 필요할 때 선택한다. 빠르게 문학적 흐름을 읽고 싶다면 NG05 → NG07 초안도 가능하지만 공간·전투·운영 미확인으로 인한 재작성을 감수해야 한다. 실제 제작이 목적이면 NG05·NG06의 선택 뒤 첫 장의 제한된 UE 제작·실행 목표를 별도로 잡는 편이 유용하며, 모든 세계 설정을 끝낼 때까지 제작을 미룰 필요는 없다.

## NG05 첫 장 진행·재개 규칙

목표는 **벨레스 도입부터 출항까지 무엇을 확인했고, 무엇을 수행했으며, 무엇을 남긴 채 다시 시작하는지 일관되게 판단할 수 있는 규칙 후보**다. C01-C06은 입력 사례이고 구현 상태 이름이나 지원 경로의 확정 목록이 아니다. 이미 끝난 NG01의 서사 인과 검토를 다시 하는 것으로 완료를 대신하지 않는다.

입력은 [첫 장 통합 정본](../Scenario.md#벨레스-첫-장의-통합-흐름과-미완료-연결), [실제 인수](../Scenario.md#여정-연결과-현재-인수), [C01-C06](../Drafts/2026-10-31-ether-taiga-dawn/2026-11-06-opening-and-continent/2026-11-15-veles-chapter-comparison.md), [VI·VT](../Drafts/2026-10-31-ether-taiga-dawn/2026-11-06-opening-and-continent/2026-11-14-veles-information-access.md), [결정 5](../../decisions/0005-run-modes-and-respawn.md)와 [게임 기획](../../GameDesign.md)이다. 실제 저장·재스폰 설계와 맞출 때는 해당 소유 문서와 코드를 별도 확인한다. 당초 추천 작성에서는 구현을 조사하지 않았다. 이후 NG05 수행에서 읽기 전용으로 확인한 기존 코드 범위와 한계는 아래 재개 문서에 적었다.

| 결과물 | 완료 기준 |
|---|---|
| 조건·전이 표 | 주인공 지식, 현장 실제 상태, 수행 작업, 담당자 이해·동의, 현재 공급·아침 점검을 분리한다. 각 진행·중단에 선행 조건·확인 근거·발생 변화·남은 작업·재개 조건이 있다. |
| 대표 경로의 서면 추적 | C01-C06 전부에서 마지막 충족 조건과 다음 행동을 추적한다. 조사 누락·복구 전 귀환·부분 복구·인수 부족을 정상 출항으로 자동 합치지 않는다. |
| 재접근·저장·재시도 선택안 | 주요 중단 시점마다 유지·재확인·재실행할 범위를 비교한다. 실제 완료된 구조·해방·분리를 되감지 않으며 기존 개별 재스폰 규칙과의 충돌은 명시한다. 새 저장 구현이나 강제 실패를 몰래 전제하지 않는다. |
| 운영 의존과 판정 불가 | 재고·추가 운반·재작업 시간 중 어떤 값이 없으면 판단할 수 없는지 기록한다. 모르는 값을 무한 자원이나 확정 실패 타이머로 대체하지 않는다. 수치가 필요한 질문은 NG06 또는 NG08의 입력으로 넘긴다. |
| 추천·검토·인계 | 대안의 진행 막힘·자동 완료·반복 설명 위험을 비교하고 독립 검토 지적을 처리한다. 선택 대상과 실제 미검증을 분리해 NG04 및 NG06·NG07에 넘긴다. |

범위 밖은 전 대륙 퀘스트 체계·신규 UI·네트워크·전체 저장 시스템 구현, 새 동료·보상·필수 조우다. NG05의 서면 완료는 모든 경로가 실제 게임에서 동작한다는 증거가 아니다. 관련 스킬은 Game Designer Assistant·ccl8-narrative·docs·writing이며 장면 인과가 바뀌는 부분만 Creative Fiction Writer를 함께 쓴다. 코드 구조까지 요청하면 ccl8-design·graft를 별도 범위로 적용한다.

## NG06 첫 장 공간·운영·전투 검증 설계

목표는 **벨레스에서 기존 동쪽 진입로·작업실·공동·같은 길 귀환·마을 인수·출항 원경을 확인할 수 있는 제한된 검증 설계**다. 같은 길 왕복은 첫 비교 대상으로 고를 뿐 모든 플레이의 필수 길로 채택하지 않는다. 서쪽이나 다른 접근은 첫 범위 밖의 미확인으로 남길 수 있다.

입력은 NG05의 조건 표, [VR 사례](../Drafts/2026-10-31-ether-taiga-dawn/2026-11-06-opening-and-continent/2026-11-15-veles-familiar-route-scenes.md), [도안 사용 경계](../../ArtDirection/EtherWorldMap/IgnisSharedTerrain.md#제작-도안-보관과-사용), [현행 생태·성장 대조](../Drafts/2026-10-31-ether-taiga-dawn/2026-11-15-world-journey-alignment/ecology-and-growth.md)다. 기존 지도·좌표를 유지하고 상세 치수의 필요·근거·미확인을 먼저 표시한다.

| 결과물 | 완료 기준 |
|---|---|
| 장면·공간 제약 목록 | 관찰 자리·조작부 접근·전투와 설비의 구분·이격·귀환로·인수 장소·출항 원경을 기존 도안의 참조와 연결한다. 새 위치나 길이 필요하면 이유·영향·승인 대상을 따로 적는다. |
| 통행·전투 검증 명세 | 적은 조우·통상 탐색·중간 철수·부분 작업 뒤 재접근의 사례마다 시작 상태·행동·예상 관찰·실패 판정·필요 측정을 정의한다. 모든 무기 선택을 유지하며 검증할 무기별 도달성·공격 창을 누락하지 않는다. |
| 운영·성장 가정 표 | 공급원·소모·운반·재작업과 경험치·장비 획득을 구분한다. 단위·근거가 있는 값만 계산하고 가정은 표시한다. 조우를 적게 한 경로에 자동 레벨 6이나 필수 사냥을 붙이지 않는다. |
| 실행 인계 | 최소 블록아웃 범위·필요 계측·검사별 통과/실패 기준·선행 미결을 제시한다. 문서로 대조한 항목과 실제 실행해야 할 항목을 나눈다. |
| 추천·검토 | 공간·운영·전투 가정의 충돌과 대안을 독립 검토하고 남은 위험을 기록한다. 실제 구현 전에는 검증 결과를 PASS로 쓰지 않는다. |

NG06은 **검증 설계까지**다. 실행은 [별도 제작 목표](#실제-제작검증으로-넘길-때)에서 수행한다. 이미지 생성 재개·전역 좌표 이동·전 대륙 분포 재설계·전체 생태 시뮬레이션은 포함하지 않는다. 관련 스킬은 Game Designer Assistant·Worldbuilding Studio·ccl8-narrative·docs·writing, 필요하면 Map Maker다. 새 공간 작업 범위와 스킬 승인은 시작할 때 확인한다.

### NG06 산출물과 현재 상태

[검증 설계 묶음](../Drafts/2026-10-31-ether-taiga-dawn/2026-11-15-veles-validation-design.md)의 작성 [독립 검토](../Reviews/2026-11-15-veles-validation-design-review.md)는 PASS, 잔여 지적 없음이다. PR01-PR07·공통 경계는 확정 입력이며 VD01-VD06·공통 경계도 사용자 승인으로 [결정 62](../../decisions/0062-veles-validation-design-adoption.md)·[Scenario](../Scenario.md#벨레스-첫-장의-공간운영전투-검증-기준)에 반영했다. 이 채택 범위는 `CLOSED`다. [반영 독립 검토](../Reviews/2026-11-15-veles-validation-adoption-review.md)는 PASS이며 잔여 지적은 없다. 원문·대안·보류·도안·좌표·수치를 유지했다.

| 완료 기준 | 작성한 결과·검증 한계 |

## NG07 첫 장 통합 집필과 정보 전달

목표는 **정상 흐름 하나와 누락·미완료에서 달라지는 장면을 함께 읽을 수 있는 첫 장 작업 원고**다. 이미 승인된 VR 흐름과 기존 장면을 기준 원고로 재사용하고, 추가되는 정확한 문장·매체·반응을 별도 후보로 표시한다.

입력은 NG05에서 선택했거나 가정임을 명시한 진행 조건, NG06의 공간 제약·미확인, [첫 장 원문 지도](../Drafts/2026-10-31-ether-taiga-dawn/2026-11-06-opening-and-continent.md), 현행 NC·VR·VB·CP·JC다. NG05·NG06 전체의 정본 채택을 무조건 기다릴 필요는 없지만 원고가 의존하는 미선택 조건은 고정하지 않는다.

원고 완성은 플레이어 인지·연출 길이·전투 피로 검증이 아니다. 신규 신상·혈통·연애·후일담·새 동료를 집필의 필수 조건으로 삼지 않는다. 관련 스킬은 Creative Fiction Writer·Character Creator·ccl8-narrative·docs·writing이며 배경 제약 변경이 필요할 때 Worldbuilding Studio를 함께 쓴다. 상세 스토리보드·음성·이미지는 별도다.

## NG08 후속 지역의 운영·인계 상세

첫 목표는 **로덴의 현재 운영, 세르나 화물 수령·회신, 하르덴 자료 발송·인수 동의·로덴 적용의 한 연결을 운영 조건으로 구체화하는 것**이다. NG03의 전 대륙 표를 다시 쓰거나 모든 정착지의 물량을 채우는 작업이 아니다.

입력은 [IB 관계](../World.md#이그니스의-공급권한생활권), [JC 연결](../Scenario.md#여정-연결과-현재-인수), [이그니스 인계 원문](../Drafts/2026-10-31-ether-taiga-dawn/2026-11-09-ignis-journey-continuity/story-and-handoffs.md), NG05에서 재사용할 수 있는 상태 구분이다. 북행 허용 조건은 현행 SC04를 유지한다.

| 결과물 | 완료 기준 |
|---|---|
| 당사자·물자·정보 흐름 | 발송자·실제 수령자·운영 담당·시험 주체, 현재 물량·예정 물량, 자료·답변·적용 결과를 구분한다. 계약·초청·발송이 현지 성공을 대신하지 않는다. |
| 조건과 비용 | 운송·대기·수리·운영 여유의 필요한 변수·단위·가정·출처를 정한다. 정량 근거가 있으면 범위와 민감도를 계산하고 없으면 어떤 결정을 막는지 남긴다. 임의 숫자로 모든 경우를 성공시키지 않는다. |
| 불완전 인계 사례 | 회신 지연·일부 물량 부족·로덴 시험 미완료에서 누가 무엇을 확인하고 이동을 미루거나 다시 합의하는지 비교한다. 이미 이룬 구조·협력 성과는 유지한다. |
| 권한·책임 경계 | 기존 담당자의 권한과 남은 책임만 필요한 만큼 구체화한다. 새 국경·세율·최종 형벌·제도적 면책을 자동 확정하지 않는다. |

다음 구간이 필요하면 G4 연안·원양 환승 또는 G5 극지 준비·귀환 중 하나를 새 목표로 고른다. 이그니스 한 인계의 완료를 전 대륙 항행·기후·수급 검증으로 확대하지 않는다. 관련 스킬은 Worldbuilding Studio·Game Designer Assistant·ccl8-narrative·docs·writing, 실제 공간 대조가 필요하면 Map Maker다. 외부 사실 조사가 필요해지면 질문·출처 범위를 정하고 조사한다.

## 실제 제작·검증으로 넘길 때

[제작 정본](../../Direction.md#확정-범위)은 마을 하나·전투 구간·보스 하나다. 5대륙의 서사 채택과 5대륙 제작 승인은 다르다. 사용자가 첫 장 제작을 요청하면 NG05·NG06의 선택된 조건, 필요한 NG07 원고만 가져가 별도의 구현·검증 목표를 만든다. 먼저 현재 구현을 조사해 재사용·누락·충돌을 확인하며 이 문서는 구현이 없거나 이미 된 상태를 추정하지 않는다.

실행 목표의 완료 기준은 선택한 시작·중단·재개·보스·인수·종료 사례의 실제 재현, 필요한 무기·정보 접근·재고 검증 증거, 관련 회귀·빌드·실행 검사, 남은 실패와 미검증의 기록이다. 설계 명세를 썼거나 화면을 캡처한 것만으로 전체 통과를 선언하지 않는다. 세부 범위는 요청 시 정하고 ccl8-design·graft·ccl8-verify와 필요한 제작 스킬을 적용한다. 구현 선택에 게임 요구·정본 변경이 필요하면 그 부분을 따로 승인 대상으로 제시한다.

## 공통 완료와 제출

각 작업군은 해당 범위의 실제 결과물, 추천·대안·보류, 독립 검토의 지적 처리, 관련 문서·결정 검사, CurrentWork·지도·인계를 갖추면 작성·검토 완료다. `미확인` 표기만 늘리고 핵심 결과물을 비워 둔 상태는 완료가 아니다. 반대로 범위 밖의 전 대륙·신상·신화를 모두 채울 필요도 없다.

새 규칙·표현·수치의 정본 반영은 사용자 선택 뒤 기존 NG04에서 수행한다. NG04를 미완료로 되돌리거나 NG09라는 새 통합 작업을 복제하지 않는다. 작업군 하나를 선택하면 그 완료 기준까지 이어가며 하위 항목마다 별도 목표 승인을 반복하지 않는다. 사용자 범위 밖의 이미지·코드·에셋 제작, 다른 세션 생성·예약·삭제는 자동으로 시작하지 않는다.
