# 다음 서사 작업의 선택

NG05-NG07의 작성·채택 결과는 [완료 지도](../WorkGroups.md)에 있다. NG08의 HO01-HO06·공통 경계도 사용자 승인으로 [결정 64](../../decisions/0064-ignis-operational-handoffs-adoption.md)·정본에 반영해 `CLOSED`다. [반영 독립 검토](../Reviews/2026-11-16-ignis-handoffs-adoption-review.md)는 PASS, 잔여 지적 0이다. [현재 상태](../CurrentWork.md)가 반영 상태와 다음 선택을 소유한다.

## NG08 후속 지역의 운영·인계 상세

첫 범위였던 로덴·세르나·하르덴은 [운영·인계 묶음](../Drafts/2026-10-31-ether-taiga-dawn/2026-11-16-ignis-operational-handoffs.md)의 흐름·조건·불완전 사례·권한·선택표로 작성했다. [독립 검토](../Reviews/2026-11-16-ignis-operational-handoffs-review.md)는 PASS, 잔여 지적 0이다. 상세 완료 기준은 당시 계획의 Git 이력에 남기고 현재 결과는 산출물에서 읽는다.

## 후속 범위

| 선택 | 첫 범위와 입력 | 남는 경계 |
|---|---|---|
| HO 채택 후 남은 상세 | HO01-HO06·공통 경계의 승인 범위는 결정 64에 반영했다. 수치·계약·표현·재방문·실제 지원은 필요한 범위를 별도로 고른다. | HOA·HOH는 자동 해제하지 않는다. |
| G4 또는 G5 상세 | 사용자가 다음 연결 하나를 고르면 그 구간의 당사자·물자·회신·현지 권한·불완전 인계를 대조한다. | 해외 항행·극지 운영·전 대륙 수치를 한꺼번에 확정하지 않는다. |
| 벨레스 실제 제작·검증 | 채택된 PR·VD와 필요한 통합 원고를 입력으로 제한된 UE 제작·실행 범위를 정한다. | 문서 PASS는 통행·무기·정보 인지·운영의 실행 증거가 아니다. |

신상·제도·기원·후일담은 [보류 지도](remaining-holds.md)의 재개 조건에 따른다. 아직 요청하지 않은 후속 작업을 시작하거나 다른 세션·예약 작업을 자동 생성하지 않는다.

## NG01-NG08 이후의 우선순위

**NG09 첫 장 상호작용·작업 기록 상세는 작성·검토를 완료했다.** 현재 단계는 `DISCUSSION`이며 추천 범위의 사용자 선택 전이다. 아래 표는 NG01-NG08 이후의 추천 순서와 각 완료 기준을 보존한다. PR·VD·IW가 정한 의미를 실제로 어떤 관찰·질문·기록으로 제시할지 좁히는 일이다. NG05 조건표나 NG06 검사표, NG07 정상 원고를 다시 만드는 목표가 아니다. 정확한 입력·매체·문구는 새 후보로 작성하고 기존 원문을 보존한다.

별도 [벨레스 블록아웃](../../Work/VelesBlockout.md)은 외부 순환로의 단일 로컬 PIE 이동과 화면 대조를 기록했다. 이는 해당 경로·검사 조건의 증거다. 지하 작업실·수원 공동·바르툴 전투·정보 인지·재고·저장·다인·출항까지 NG06 GX·WC가 통과했다는 뜻은 아니다. 아래 문서 작업은 이 기록만 읽고 UE를 실행하거나 에셋·좌표·수치를 변경하지 않는다.

| 우선순위 | 추천 작업군 | 먼저 하는 이유·선행 입력 | 완료했을 때 얻는 것 |
|---|---|---|---|
| 1 | [NG09 첫 장 상호작용·작업 기록 상세](#ng09-첫-장-상호작용작업-기록-상세) | PR·IW·VI·MS/C는 있지만 실제 확인·질문·기록의 표현 선택이 남았다. 기존 블록아웃도 읽힘을 보장하지 않는다. | 장면별 행동·정보·피드백, 실제 기록 예문과 누락 안내의 비교 후보 |
| 2 | [NG10 첫 장 운영·성장 계산 입력 후보](#ng10-첫-장-운영성장-계산-입력-후보) | OP 목록 다음으로 계산에 쓸 단위·근거·가정·범위를 선택해야 한다. NG09와 독립적으로 진행할 수 있다. | 제한된 대표 경로의 입력 대조·수지 계산 또는 기호식 추적, 선택할 가정과 측정 과제 |
| 3 | [NG11 G4 연안·원양 환승 운영](#ng11-g4-연안원양-환승-운영) | HO가 정한 인계 판단을 다음 장거리 연결에 적용한다. NG09·NG10 완료를 기다릴 필요는 없다. | 초청·연안 환승·동안항 원양 인수와 불완전 준비의 연결 |
| 4 | [NG12 G5 극지 준비·구조·귀환 운영](#ng12-g5-극지-준비구조귀환-운영) | 귀환 비축·피난·구조와 추가 조사 판단이 얽혀 범위가 더 크다. G4에서 전달·비용 표현을 먼저 정리하면 반복을 줄인다. | 남부항 준비부터 본선 구조 인수·조사 중단·귀환까지의 운영 분기 |

순위는 문서 작업의 기본 추천이며 제작 일정·실제 게임 진행의 선후 조건이 아니다. 첫 장의 구체화보다 후속 여정 확장을 원하면 NG11을 먼저 고를 수 있다. G4 경험을 G5에 참고할 수 있지만 NG11 채택이 NG12 착수나 게임 속 G5의 새 조건은 아니다. NG09는 작성·독립 검토 PASS로 완료했으며 IR01-IR06·공통 경계의 사용자 선택을 기다린다. NG10-NG12는 미착수·선택 전이다.

### NG09 첫 장 상호작용·작업 기록 상세

목표는 **이미 쓴 첫 장에서 무엇을 확인하고, 어떤 말을 듣거나 기록을 읽으며, 누락을 어떻게 알아차리는지 구체 후보로 읽을 수 있게 하는 것**이다. 입력은 [PR](../Scenario.md#벨레스-첫-장의-진행과-재개)·[IW](../Scenario.md#벨레스-첫-장의-표현과-작업-기록), [VI 대조](../Drafts/2026-10-31-ether-taiga-dawn/2026-11-15-veles-integrated-manuscript/information.md), [정상 원고](../Drafts/2026-10-31-ether-taiga-dawn/2026-11-15-veles-integrated-manuscript/manuscript.md)·[대체 장면](../Drafts/2026-10-31-ether-taiga-dawn/2026-11-15-veles-integrated-manuscript/variants.md)다.

| 결과물 | 완료 기준 |
|---|---|
| 상호작용 대조 | VI01-VI08 각각에 근거가 있는 현재 장면·관찰/전달 주체·행동 후보·인물이 실제 아는 범위·피드백·다음 행동을 연결한다. 플레이어 열람과 인물 지식·실제 작업을 구분한다. |
| 읽을 수 있는 기록 예문 | IW02의 휴대 기록을 관찰·미확인·계획/수행/남은 확인으로 구분해 실제 예문을 작성한다. 정상 보고와 작업 전 귀환·부분 수행·인수 부족의 차이, 마을용/로덴용의 용도를 보여 준다. 정확한 규격·도식·UI는 후보다. |
| 누락·근거 소실 대응 | C03-C06·C03-R·C06-M에 필요한 짧은 질문·답변·남은 확인 문장을 작성한다. 출처가 실제로 없으면 새 근거를 자동 생성하지 않고 접근/대체 수단의 후보·한계를 명시한다. |
| 선택·검토 | 자동 표시/요청 시 열람 등 표현 대안의 반복·시선 분산·오인 위험을 비교하고 권장 범위를 분리한다. 읽힘·인지 검증은 미실행으로 남기고 독립 검토 지적을 처리한다. |

완료를 ‘버튼 이름과 빈 표를 정했다’로 대체하지 않는다. 행동과 예문이 장면에 연결돼야 한다. 실제 HUD·메뉴·입력 코드·아이템·음성·카메라 제작, 모든 상태 조합·플레이어 이해 검증은 제외한다. 표현 선택이 실제 진행 조건을 바꾼다면 원문을 고치지 않고 변경 후보로 명시한다.

### NG10 첫 장 운영·성장 계산 입력 후보

목표는 **OP 목록의 정의를 반복하지 않고, 첫 장에서 비교할 입력의 근거와 사용 범위를 골라 정상·중단 경로를 추적하는 것**이다. 입력은 [OP01-OP09](../Drafts/2026-10-31-ether-taiga-dawn/2026-11-15-veles-validation-design/operations.md), [PR 사례](../Drafts/2026-10-31-ether-taiga-dawn/2026-11-15-veles-progression-resume/cases.md), VD04·VD05, 기존 분포·상승분 예산이다. NG08 OV는 같은 정의를 비교하는 참조이며 로덴 수치를 벨레스에 복사하지 않는다.

| 결과물 | 완료 기준 |
|---|---|
| 입력의 소유와 범위 | 생활 자원·작업/운반·장비·성장별 단위·발생 시점·담당·출처·값 유무를 채운다. 원문 값, 실제 기록, 별도 가정 후보를 구분하고 서로 다른 경로·시점·규격 값을 섞지 않는다. |
| 대표 경로 추적 | 적은 조우·통상 탐색, 복구 전 귀환·부분 수행·보충 지연을 제한된 비교로 추적한다. 완료 성과·이미 소모한 양을 보존하고 각 필요 시점의 수지와 남은 작업을 계산한다. |
| 범위·민감도와 한계 | 근거 있는 값이 있으면 단위 검산과 지연·소모·추가 운반 변화의 결과를 제시한다. 값이 없으면 같은 사례의 기호식·부족을 가르는 조건과 추가 입력 주체를 끝까지 추적한다. 미확인 목록만 복제해 완료로 삼지 않는다. |
| 선택·검토 | 필요하면 원본과 분리한 가정 후보를 이유·범위·효과와 함께 비교한다. 가정만으로 실제 재고 충분성·적정 난도·도착 레벨을 확정하지 않는다. 자연 획득 비교와 통제된 무기 시험의 입력을 구분하고 독립 검토한다. |

새 후보 수치는 기존 원문·도안·좌표·분포·성장 예산을 덮어쓰지 않는다. 근거 없는 숫자로 성공을 맞추거나 외부 순환로 이동 시간을 전투·조사·인수·출항까지의 소요 시간으로 사용하지 않는다. 자동 레벨 보정·필수 사냥·무료 재고·시간 제한·경제 시스템·밸런스 구현은 제외한다.

### NG11 G4 연안·원양 환승 운영

목표는 **오르다스 성과·실제 초청에서 연안 환승을 거쳐 동안항의 원양선·선원·왕복 보급 인수까지 한 연결을 구체화하는 것**이다. [G4](../Scenario.md#대륙-이동과-귀환-조건)·[JC03](../Scenario.md#여정-연결과-현재-인수), [HO](../Scenario.md#로덴세르나하르덴의-운영과-인계), [기존 이동 대조](../Drafts/2026-10-31-ether-taiga-dawn/2026-11-15-world-journey-alignment/journey.md)를 입력으로 쓴다.

| 결과물 | 완료 기준 |
|---|---|
| 구간·인수 흐름 | 초청 요청/실제 회신, T3/T4 연안편·루세아·동안항·T5 원양편의 기존 연결을 대조한다. 발송자·수령자·각 선장·보급 담당의 실제 책임과 남을 사람을 구분한다. |
| 물자·비용 조건 | 주민·구호 몫과 상업/원정 몫, 현재 적재와 예정 계약, 귀환 몫·항만 비용을 나눈다. 물량·기간·용량이 없으면 막히는 판단과 필요한 근거를 남긴다. |
| 불완전 환승 | 초청 회신 지연·연안편 변경·원양 적재 일부 부족·귀환 계약 미완료·당일 운항 변경의 다음 행동을 작성한다. 준비 이동과 G4 인수 완료, 실제 출항은 별개다. |
| 선택·검토 | 담당 인수·재협의의 대안·비용을 비교하고 독립 검토한다. 적용할 HO 판단과 로덴에만 해당하는 사례를 구분한다. G5·실제 항행 검증은 미착수로 남긴다. |

새 기항지·해안·좌표·항해 일수·즉시 보충·같은 배의 무제한 원양 운항을 전제하지 않는다. 선주·현지 권한을 새 국경·조약·세율 체계로 확대하지 않는다.

### NG12 G5 극지 준비·구조·귀환 운영

목표는 **주민 수원 분리·구조 요청 확인 이후 남부항의 준비, 니베르의 본선 구조 인수와 선택 조사·귀환 판단을 잇는 것**이다. [G5·G6 구분](../Scenario.md#대륙-이동과-귀환-조건), JC05, [기존 이동 대조](../Drafts/2026-10-31-ether-taiga-dawn/2026-11-15-world-journey-alignment/journey.md)를 기준으로 한다. HO와 NG11에서 선택한 인계 표현이 있다면 재사용하되 새로운 선행 채택 의무는 만들지 않는다.

| 결과물 | 완료 기준 |
|---|---|
| 준비와 책임 | 별도 연안편·남부항·극지 개조·선원·귀환 비축·피난 준비의 현재 완료와 예정 협력을 나눈다. 발신 정보·실제 생존 현황·승선 여유를 구분한다. |
| 자원과 구호 | 원정·주민·구호·귀환 몫과 실제 회수/보온 능력을 나누고 불명확한 값의 판단 한계를 적는다. 협조·장부 제공을 구호 조건으로 만들지 않는다. |
| 미완료·귀환 사례 | 준비 부족·접근 중단·구조 후 조사 미완료·재상륙 보류·기상/회수 여건 변화에서 담당자·남길 성과·다음 행동을 추적한다. 귀환은 G6 및 조사 완료와 독립이며 즉시 안전 운항의 보장은 아니다. |
| 선택·검토 | 추가 조사와 귀환의 비용·대안을 비교하고 독립 검토한다. 귀환 뒤 G6 현지 적용과 결말 완료는 이번 범위 밖으로 남긴다. |

새 안전 섬·자동 구조선·강제 사망·무한 대기·조사 연장용 귀환 비축 소비를 기본 해법으로 넣지 않는다. 실제 기후·항행·구조·UE 검증은 별도다.

## 공통 완료 기준과 선택 경계

각 작업군은 요청된 실제 문서 결과물, 기존 확정과 새 후보의 대조, 선택표·대안·보류, 독립 검토 지적 처리, 문서·결정 검사, CurrentWork의 완료·미승인·미검증 인계를 갖추면 작성·검토 완료다. 표나 원고를 쓴 것과 사용자 채택·실제 성공은 별개다. 수치가 없다는 이유로 필요한 사례·근거·다음 판단까지 비워 두거나, 가정 결과를 실제 성공으로 바꾸지 않는다.

공통 기반은 ccl8-narrative·docs·writing이다. NG09의 표현 비교에는 Creative Fiction Writer·UI/UX Reviewer, NG10에는 Game Designer Assistant, NG11·NG12에는 Worldbuilding Studio·Game Designer Assistant가 관련 선택 스킬이다. 이번 지도 정리에서 이 전문 스킬의 제작·실행 범위를 시작하지 않으며, 선택한 작업의 범위와 기존 승인에 맞춰 적용 여부를 정한다.

NG04는 앞으로도 사용자가 고른 범위를 결정·정본에 반영하는 절차다. NG09를 새 통합 승인 작업으로 만들거나 NG01-NG08을 미완료로 되돌리지 않는다. 코드·설정·에셋·UE 실행, 원본 도안·좌표·수치 수정, 원문 삭제는 이 문서 추천에 포함하지 않는다.

## 조건이 생겼을 때 고를 범위

정확한 저장 형식·개인/세계 소유권·부분 전투 복원·다인 정보 공유는 실제 구현 확인이 필요한 별도 설계·검증 범위다. NG09의 사용자에게 보이는 표현 선택만으로 PRH01·PRH02·PRH06·VDH06을 해제하지 않는다.

HOH03·IWH06의 로덴·세르나·하르덴 후속 집필은 해당 장면을 읽을 필요가 생길 때 고른다. HO 운영·인계는 이미 확정됐으므로 다시 조건표를 만드는 대신 실제 장면·정보 전달 차이를 써야 한다. 신상·제도·기원·후일담은 계속 [보류 지도](remaining-holds.md)의 재개 조건에 따른다.

실제 제작을 별도로 선택하면 [진행 중인 벨레스 작업](../../Work/VelesBlockout.md)과 NG06의 [실행 인계](../Drafts/2026-10-31-ether-taiga-dawn/2026-11-15-veles-validation-design/handoff.md)를 먼저 대조한다. 외부 블록아웃을 처음부터 다시 만들거나 기존 PIE 기록을 서사 전체 검증으로 확대하지 않는다. 이번에는 문서 추천만 수행하며 후속 작업을 자동 시작하지 않는다.

추천의 [독립 검토](../Reviews/2026-11-16-post-ng08-workgroups-review.md)는 PASS, 잔여 지적 0이다. 이는 당시 지도 작성·검토 완료 판정이다. 이후 선택된 NG09의 현재 상태는 [CurrentWork](../CurrentWork.md), 새 후보는 [상호작용·작업 기록 상세](../Drafts/2026-10-31-ether-taiga-dawn/2026-11-16-veles-interaction-records.md)에서 읽는다.
