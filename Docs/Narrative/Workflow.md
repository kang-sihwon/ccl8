# 서사 조사·저작 절차

Guide, Decisions, NarrativeConcept과 CurrentWork를 확인하고 현재 요청의 질문·범위·완료 조건을 정한다. 이전 프로젝트의 설정, 작품 수 할당량과 일회성 예외를 적용하지 않는다.

## 역할·진행

- 한 항목의 작성자는 한 도구가 맡고 CurrentWork의 `active_owner`에 기록한다. 다른 작성자의 진행 중 산출물을 임의로 덮지 않는다.
- 조사에서는 1차 출처를 우선하고 접근한 원문·확인 범위·추론을 구분한다. 작품의 이름과 표현을 복제하기보다 작동 방식과 반례를 분석한다.
- 후보는 2-3개의 선택지, 제작 범위와 장단점으로 비교한다. 고유 설정과 장르 방향은 사용자와 정한다.
- 작성자와 독립 검토자의 역할을 구분한다. 검토자는 출처·논리·유사성·기존 정본 충돌을 검토 문서에 기록한다. 실제 독립 검토가 없으면 미검토라고 남긴다. 이 절차 자체가 에이전트 생성이나 다른 채팅에 메시지를 보낼 권한은 아니다.
- 사용자가 범위를 명확히 승인한 내용만 World·Scenario에 반영한다. 호감 표현과 질문은 승인으로 간주하지 않는다. 기존 확정 내용의 변경도 승인과 새로운 결정 기록이 필요하다.
- 정본 반영 후 승인 범위, 문장, 결정 로그의 일치와 게임 요구사항과의 충돌을 확인한다. 결과와 다음 행동을 CurrentWork에 남기고 담당을 해제한다.

## 상태와 산출물

기본 단계는 `SCOPED → RESEARCHING → REVIEW → DISCUSSION → APPROVAL_PENDING → CANONIZING → CLOSED`다. 수정 요청은 해당 작성 단계로 돌아가고, 보류는 `PARKED`, 근거 부족은 `BLOCKED_SOURCE`로 남긴다. 간단한 작업은 필요한 단계만 사용하되 승인·검토 사실을 만들어내지 않는다.

조사는 Research, 후보는 Drafts, 검토는 Reviews에 기록한다. 검토 결과는 `APPROVED`, `CHANGES_REQUESTED`, `BLOCKED_SOURCE`, `CANON_CONFLICT`로 구분한다. 검토 통과와 사용자 승인은 서로 다른 상태다.

인계에는 완료 사실, 미승인 내용, 출처·검토 장애, 기다리는 결정과 다음 행동을 적는다. 문서 제출은 `../VersionControl.md`를 따른다. 코드·설정·에셋 변경은 이 절차에 포함되지 않는다.
