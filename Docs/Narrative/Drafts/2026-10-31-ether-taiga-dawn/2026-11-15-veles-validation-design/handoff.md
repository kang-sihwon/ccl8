# 최소 블록아웃과 실행 인계

채택 범위·보류·검증 상태는 [상위 문서](../2026-11-15-veles-validation-design.md)를 따른다. 본문은 작성 당시 후보 기록이며 원문 전체를 정본화한 것이 아니다.

**후속 제작은 한정된 실제 연결과 필요한 계측부터 시작한다.** 이 문서는 제작·실행 요청 시 사용할 입력이며 지금 UE 맵·에셋·코드를 만들거나 실행하는 지시가 아니다. [GX·WC](tests.md)의 결과는 모두 미실행이다. 서면 검토와 원천 수치 대조는 [상위 문서](../2026-11-15-veles-validation-design.md)의 이번 완료 범위다.

## 최소 제작 범위

| 묶음 | 별도 제작 때 필요한 것 | 제외·완료 판정 경계 |
|---|---|---|
| 마을 시작·종료 | 기존 공방·급수·보관·숲 입구·나루 참조를 잇는 이동/접근 공간, 실제 보고·인수·아침 근거를 관찰할 수단 | 마을 86개 건물을 모두 제작할 의무는 없다. 접근·운영을 대표할 입력으로 충분하되 단순 버튼이 실제 인수·사용을 대신했다면 해당 검사는 미완료다. |
| 동쪽 연결 | 숲 입구·R02·기존 접속·B04·동굴로 이어지는 통행면과 필요한 가림·경사·물가·충돌, 해당 경로에 영향을 주는 현재 개체 | v5 전체 사각형, 서쪽 생활권 전부, 전 대륙·전체 생태 시뮬레이션은 제외한다. 제외한 외부 개체의 실제 합류 영향까지 검증했다고 쓰지 않는다. |
| 작업실·공동·정비 | 지하 옛 작업실의 조사/전투 구분, 공동 결박·곰·정상 설비, 실제 작업과 사람/곰 이격 경로 | 원본에 없는 방 치수·층 연결·표적 크기는 먼저 별도 제작 가정으로 명시한다. 배치 변경이 필요하면 원본 보존 수정안으로 분리한다. |
| 출항 원경 | 기존 나루·배 경로·능선과 상층 수관 관찰에 필요한 최소 지형·가림·시점 | 전 세계수·다른 도시·항행 전체 구현은 제외한다. 평면 표식이나 연출 한 장으로 실제 배 통행·원경 검사를 대신하지 않는다. |

실행에 필요한 상세 공간이 원천에 없으면 새로운 실제 배치가 필요하다는 사실을 선행 미결로 기록한다. 이번 후보는 그 위치·치수를 채택하지 않는다. 독립된 전투 시험장으로 도달성 문제를 먼저 찾을 수 있지만 실제 작업실·입구·귀환 경로에 통합한 결과를 별도로 남겨야 한다.

## 계측과 결과 양식

| 기록 | 단위·관찰 | 사용할 검사 |
|---|---|---|
| 위치·충돌·시야 | 좌표계/단위·수직 층·캐릭터 실제 충돌 크기·무기 궤적·카메라 위치·장애물/표적 식별자·선분/몸 전체 가림 | SP01-SP10, WC01-WC06 |
| 행동·위협 | 실제 입력, 예고·준비·접촉·회복·대응 시각, 탐지·추격·합류·이격 전환, 피격/사망 원인 | GX01-06·09, WC 전체 |
| 사실·작업 | 실제 관찰/전달 출처·아는 범위, 결박/설비의 완료·미완료, 인수 질문·동의·현재 변화 | GX03·05-08·12 |
| 자원·성장 | 자원 정의·단위·시점별 실제 증감·원인·소유, 장비 획득과 지급 식별, 시험 상태와 자연 획득 구분 | GX01·02·04·06·11, OP 전체 |
| 종료·재개 | 같은 세계/새 비교/명시 불러오기 구분, 저장 시점과 참가자 예외, 아침·실제 출항 근거 | GX05-12 |

결과 한 건에는 `검사 ID / 무기·행동·경로 / 빌드·콘텐츠 버전 / 초기 입력과 가정 / 실제 수행 / 기대·관찰 / 시각이 맞는 영상·로그·상태 근거 / 판정 / 남은 미확인`을 함께 적는다. 기록 수단·저장 스키마·디버그 UI는 후속 구현 선택이다. 영상은 가시성을, 서버/실제 상태 기록은 성과·재고·적중을 뒷받침하며 어느 하나로 다른 쪽까지 추정하지 않는다. 여러 모드의 결과는 별도로 표시한다.

## 후속 실행의 순서와 종료 조건

1. **입력 고정:** 실제 지원 무기 명부, 시험할 동작·장비·체력·소모, 첫 공간의 치수/층/변환, 적의 현 상태, OP값과 그 근거를 준비한다. 없는 항목은 선행 미결이다. 원본 해시·좌표·수치와 제작 사본의 차이를 남긴다.
2. **공간·전투 분리 확인:** SP01-SP10의 필요한 형상·관찰 자리와 WC 전 항목을 해당 무기별로 확인한다. 결박 접촉·정상 설비 분리·생존 이격을 수동 설명이나 사망 Victory로 대체하지 않는다. 서사 진행 지원이 없으면 지원되지 않는 GX는 선행 미결로 남긴다.
3. **대표 경로 연결:** 같은 입력에서 GX01·GX02를 각각 수행하고, GX03·GX04·GX06·GX07의 누락·귀환·부분 작업·인수 부족을 이어 검사한다. 정상 예 하나만으로 재개 사례를 통과시키지 않는다.
4. **변화·재개 검사:** GX05·GX08·GX09·GX11로 세계 성과·새 이상·현재 적·자원 시점을 비교한다. GX10의 실제 출항·원경을 확인한다. GX12는 명시 저장·기존 세션 계약의 별도 검증으로 분리한다.
5. **결과 제출:** 선택한 실제 무기와 검사별 실행/미실행/미결을 모두 공개한다. 요구 조건 실패와 수치·가독성·난도 문제를 구분하고 수정 후보를 낸다. 사용자가 선택한 실행 범위에 필요한 검사를 빠뜨렸으면 그 실행 목표를 완료로 쓰지 않는다.

개별 검사의 통과 기준은 tests의 기대 관찰, 실패 기준은 같은 행의 금지 결과다. 무기 도달성·공간 성립은 실제 측정, 운영 지속은 시점별 사용 가능량, 정상 종결은 실제 필수 작업·인수·아침·출항으로 판단한다. 정량 목표가 필요한 재미·난도·카메라 여유·입력 지연은 목표값을 선택하기 전 적정성 통과를 선언할 수 없다. 참조 숫자를 그대로 채택해 빈 목표를 채우지 않는다.

## 선행 미결과 병행 가능한 준비

| 미결 | 막히는 실제 판정 | 지금 넘긴 구체 입력 |
|---|---|---|
| 실제 무기 목록·행동·장비 조건 | 모든 무기 도달성·대응 가능성 | WC 명부 필드와 각 실제 항목의 GX 연결. 현재 지원과 제작 목표의 차이를 기록한다. |
| 지하 구조·표적·이격·배 경로의 실제 형상 | 충돌·층 연결·전투·원경 | SP별 원천 ID·제약·필요 측정. 기준점 이동을 선행 해결책으로 삼지 않는다. |
| OP의 재고·시각·비용·변환 | 비상 지속·재작업·성장 | 자원별 시점 장부·경로 비교와 무기 통제 실험의 분리. |
| 서사 상태·기록·저장 대응 | 부분 성과·정보 누락·인수·명시 복원 | PR·C·RT와 GX의 시작/기대 상태. 코드·스키마 선택이나 구현 완료 주장은 없다. |
| 플레이 시점·인지·난도 목표 | 읽힘·학습·피로·적정 시간 | 예고/입력/접촉 시각·행동·관찰 근거를 수집할 양식. NG07 원고와 실제 사용자 검증은 별도다. |

범위를 늘리지 않고도 이 명세를 NG07의 원고 제약으로 넘길 수 있다. 예를 들어 SP04의 관찰 가능성이 미검증이면 원고가 ‘여기서 모든 도면이 선명하게 보인다’고 확정하지 않게 한다. 실제 제작 요청 전에는 위 준비가 실행 승인으로 바뀌지 않는다.

## 현재 코드 참조의 한계

이번 Graft 조회에서는 [BeginAttack](../../../../../Source/KSICombat/Private/KSICombatComponent.cpp) `Source/KSICombat/Private/KSICombatComponent.cpp:47`의 서버 권위·정의·Reach·Radius·방향 유효성 검사를 확인했다. 이 제한된 조회는 무기 목록 전체·실제 적중 궤적·바르툴 표적·첫 장 검사의 구현 여부를 확인한 것이 아니다. Reach나 Radius가 유효하다고 공간의 실제 접촉을 통과시킬 수 없다. [전투 수치](../../../../CombatFoundation/Actions.md)·[장비 계약](../../../../ProgressionFoundation/Equipment.md)은 현재 프로토타입 소유 문서이며 그 수치를 첫 장의 정본으로 옮기지 않는다.

실제 제작 때는 당시 소유 코드·에셋·데이터와 기존 검증 도구를 확인하고 ccl8-design·graft·ccl8-verify를 해당 요청 범위에 적용한다. 이번에는 코드·에셋 탐색을 확대하거나 기존 UE 검사를 실행하지 않았다.
