# 기존 참조와 첫 장의 공간 제약

2026-11-15 사용자 승인으로 VD01-VD06과 공통 경계를 [결정 62](../../../../decisions/0062-veles-validation-design-adoption.md)·[Scenario](../../../Scenario.md#벨레스-첫-장의-공간운영전투-검증-기준)에 반영했다. 이 채택 범위는 `CLOSED`다. [반영 독립 검토](../../../Reviews/2026-11-15-veles-validation-adoption-review.md)는 PASS이며 잔여 지적은 없다. VDA01-VDA02·VDH01-VDH06과 아래 원문·도안·좌표·수치는 보존한다. SP·GX·WC·OP 및 상세 표·실행용 가정 전체는 일괄 정본화하지 않았고 실제 GX·WC 검사는 모두 미실행이다. 아래 후보·미채택·다음 선택 표현은 작성 당시 기록이다.

**기준점과 연결은 보존하고, 캐릭터·무기·위협이 함께 들어갈 실제 여유를 검증한다.** [도안 사용 경계](../../../../ArtDirection/EtherWorldMap/IgnisSharedTerrain.md#제작-도안-보관과-사용)에 따라 v5 이미지는 참고 도안이다. 작업 사각형 전체를 플레이 영역으로 만들거나 그림에 맞춰 좌표를 옮기지 않는다. 이번에는 좌표·참조 문서를 대조했으며 v5 브라우저·이미지의 새 육안 검토나 실제 통행 검사를 하지 않았다.

## 참조의 역할과 좌표 구분

| 참조 | 사용할 근거 | 그대로 추정하지 않을 것 |
|---|---|---|
| [첫 장 연결 JSON](../../../../ArtDirection/EtherWorldMap/Data/veles-opening-connections-v1.json) | `local_points_m`, `new_cave_nodes_m`, 지하 연결과 배 원경의 인접 관계 | `combat_nodes`의 옛 다람쥐 전투 목록은 현행 전투 요구가 아니다. `arena_bounds_m`도 최종 경기장 크기가 아니다. |
| [현행 숲 v2](../../../../ArtDirection/EtherWorldMap/Data/veles-forest-ecology-v2.json)·[생활권 원문](../2026-11-06-opening-and-continent/2026-11-07-goblin-territories-and-wildlife.md) | R02·기존 접속로, GB03과 G04의 별도 현재 상태, 같은 개체의 활동·이동 | S01-S04는 은퇴한 전투 ID다. `squirrel`은 장소 이름이다. 평소 영역·이동 예시가 탐지 거리·강제 조우·동시 개체 수가 되지 않는다. |
| [숲 상세 JSON](../../../../ArtDirection/EtherWorldMap/Data/veles-forest-detail-v1.json)·[시야·폭 원문](../2026-11-06-opening-and-continent/2026-11-07-forest-sightlines-and-clearance.md) | R04와 동굴–W4의 상세 굽이·장애물·관찰선 | 이번 동쪽 왕복 전 구간에 폭 6–8m를 적용하지 않는다. 평면 광선·중심선 여유는 몸 전체·카메라·추격 차단 증거가 아니다. 서쪽은 첫 연속 실행 범위 밖이다. |
| [상세 지형 규격](../../../../ArtDirection/EtherWorldMap/Atlas/VelesDetailTerrain-v1/manifest.json)·[배치](../../../../ArtDirection/EtherWorldMap/Atlas/VelesDetailTerrain-v1/data/placements.json)·[연결](../../../../ArtDirection/EtherWorldMap/Atlas/VelesDetailTerrain-v1/data/connections.json) | 공통 원점, POI·외곽·도로와 지상/지하 구분 | `workshop` 건물 외곽은 마을 공방이다. 지하 `old_workshop`을 같은 건물로 대체하지 않는다. 새 치수·높이·다리는 제작 후보이지 승인된 충돌 형상이 아니다. |

첫 장 원점은 나루 `(0,0)m`, 지역 원점은 `(150,145)km`다. 상세 지형 원점 `(150000,145000)m`과 단위를 맞춘다. 이 평면 좌표의 축·척도와 UE 변환은 별도 제작에서 확인하며 고도·경사·수직 층은 이 평면 일치만으로 알 수 없다.

마을 공방 참조점은 `(60,110)m`이고 배치 문서의 건물 중심 `(60,124)m`, 문 `(60,114)m`은 서로 다른 역할이다. 동굴 입구 `(260,1250)m` 뒤 지하 옛 작업실 `(280,1300)m`과 공동의 보스 기준점 `(300,1360)m`을 구분한다. 옛 작업실·보스는 상세 배치 POI에서 `underground`로 표시된다. 수원 `(320,1390)m`과 관찰·조작·곰 퇴로·고립 웅덩이 역시 서로 다른 참조다. 이 값을 수정하거나 새 위치로 확정하지 않는다.

## 이번에 계산한 참조 범위

[원천 대조 기록](source-audit.json)의 23개 입력을 보존하고 다음만 계산했다. 각 길이는 미터 좌표의 연속 두 점 사이 유클리드 거리 합이며 고도·장애물·적 회피·속도를 포함하지 않는다.

| 대조 | 결과 | 해석 한계 |
|---|---:|---|
| 첫 장 연결과 상세 배치의 같은 ID POI | 15개 모두 평면 좌표 일치 | 지상·지하의 실제 층 연결이나 최종 배치 채택은 아니다. |
| 숲 입구 → `squirrel` → E1·E2·E3 → `wolves` → B04 → 동굴 | 1,136.379m | 현행 v2의 동쪽 야외 참조선. 마을·실내·선택 탐색·전투 움직임은 제외한다. |
| 상세 연결의 R02 자체 | 721.357m | `squirrel`에서 `wolves`까지의 부분이다. 전체 수원행 거리로 쓰지 않는다. |
| `boat_to_reveal_m` 참조선 | 1,772.990m | 배 운항 거리·수심·시간·원경 가시성을 검증한 값이 아니다. |

기존 1,136.4m 같은 반올림 값과 비교할 수 있지만 원문 숫자는 바꾸지 않는다. 4,096×6,144m의 v5 작업 사각형, 40×32m 공동 후보, R02 폭 3m와 상세 출구 폭 5m 등은 서로 다른 범위·버전의 후보 값이다. 이를 최종 이동 시간이나 공격 공간의 여유로 합산하지 않는다.

## 장면·공간 제약 SP01-SP10

| ID·기존 참조 | 유지할 관계·확인할 행동 | 측정과 실패를 판단할 조건 |
|---|---|---|
| SP01 마을 `workshop`·`water_point`·`water_store`·`forest_gate` | 공방·급수·보관·출발 분담의 실제 접근을 나눈다. 휴대 공구·동력과 무기 선택을 혼동하지 않는다. | 출입구·연결로의 실제 충돌 폭/높이·회전·짐 상태, 상호작용 가능 자리와 정보 노출을 측정한다. 공방 중심을 출입점으로 쓰거나 멀리 있는 공급 정보를 자동 획득하면 실패다. |
| SP02 R02 및 기존 남북 접속 | 적은 조우와 통상 탐색을 같은 참조망에서 비교한다. 일반 동물·거점 방문은 필수가 아니다. | 왕·복 이동 궤적, 경사·다리·몸/카메라 간섭, 현재 개체 위치·탐지·합류를 기록한다. 적 배치를 삭제해 안전한 길을 만들거나 과거 다람쥐 추격값을 이식하지 않는다. |
| SP03 B04·동굴 입구·G04 | 동굴 밖 G04와 실내 작업실 파수꾼을 별개로 둔다. 진입 때 피한 적은 현재 세계에 남는다. | 입구 양방향 접근·문턱·회전·회피 공간, G04가 보이는 위치·추격 종료를 측정한다. 광선 하나가 가려졌다고 추격 종료로 세지 않는다. |
| SP04 `old_workshop` | 직접 위협 대응 뒤 도면·얼음·우회 연결·정상 회로를 실제 대조할 자리가 필요하다. 지식 누락도 자기방어를 막지 않는다. | 싸울 위치와 관찰 위치의 차이, 가림·시선·공구 접근을 확인한다. 공격 가능한 위험 공간을 영구 안전 자리로 표시하지 않는다. 실내 구조 미정은 제작 선행 미결이다. |
| SP05 `observation`·`entry` | 결박·곰·조작부를 구분해 현재 상태를 읽되 버튼만 눌러 직접 전투를 건너뛰지 않는다. | 실제 플레이 시점에서 외부 결박·정상 설비의 식별, 진입·물러남·공격 준비 중 시야와 가림을 기록한다. 강제 카메라·무적·퀴즈를 전제하지 않는다. |
| SP06 공동·바르툴 결박 | 선택한 무기로 전투해 앞다리·가슴 연결을 해제하고 생존 이격을 만든다. 앞다리 해제 후 늘어난 활동을 수용한다. | 무기마다 실제 표적 접촉·도달 높이·가림·공격 창·대응 공간을 WC 검사로 확인한다. 몸 사망·특정 무기 교체·정밀 점 표적만으로 성공시키면 실패다. |
| SP07 `controls`·`isolation_sump`·`spring` | 외부 결박과 정상 설비, 채취 해제·분리·파편·동력·첫 물을 구분한다. 완료 작업은 재접근 때 유지한다. | 각 작업 자리의 접근·위험·도구 공간, 잔류 파편·사용 자원·작업 순서를 확인한다. 해방·기록만으로 송수 완료면 실패다. 물리 작업의 세부 형상·순서는 보류다. |
| SP08 사람 귀환 연결·`bear_exit`·`sun_ledge` | 사람의 복귀, 살아 있는 곰의 이격, 정상 물길을 서로 대체하지 않는다. 같은 동쪽 길 귀환은 첫 사례다. | 양측 이동 궤적·몸 겹침·추격·퇴로 막힘·재접근을 측정한다. 곰 소멸·순간 이동·새 출구로 결과를 대신하지 않는다. 서쪽 대안의 실제 성립은 별도다. |
| SP09 마을 하류·보관·담당자 자리 | 첫 물과 실제 사용, 보고·이해·동의·현재 보유분·아침을 나눈다. | 물 사용 관찰, 전달 가능한 거리·동선·역할, 시간별 재고와 인수 근거를 기록한다. 도착·서명·대화 종료만으로 완료시키지 않는다. 정확한 매체는 NG07이다. |
| SP10 `quay` → `ridge` 주변 → `reveal` | 기존 배의 실제 출항 뒤 상층 수관으로 닫고 린은 부두에 남는다. | 배 경로·수면/강안 간섭·능선 가림·실제 관찰 시점과 상층 수관 프레이밍을 확인한다. 표식 가시성이나 평면 선분으로 원경 성공을 선언하지 않는다. |

현재 자료만으로 새 위치나 길이 반드시 필요하다는 결론은 내리지 않는다. 실패가 드러나면 **실패한 SP·GX·WC, 현재 위치/치수, 원인, 원본을 유지한 별도 수정 후보, 영향받는 물길·생활권·전투·인수, 선택할 범위**를 한 변경표로 낸다. 캐릭터 배치·계측 오류를 먼저 확인하고, 도안 좌표 이동·새 출구·범위 확대는 사용자 선택 전에 정본이나 원본에 적용하지 않는다.
