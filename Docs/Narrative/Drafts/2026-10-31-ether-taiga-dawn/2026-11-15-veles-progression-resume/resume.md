# 재접근·개인 재스폰·저장 불러오기의 경계

**같은 세계에서 돌아오거나 개인 재스폰을 하는 경우와, 사용자가 과거 저장을 명시적으로 불러오는 경우를 구분한다.** 전자는 실제 완료 성과를 유지하고 현재 조건을 다시 보며, 후자는 선택된 저장과 기존 복원 계약에 따라 복원한다. 늦은 참가자를 현재 상태로 유지하는 예외도 포함한다. 자동 되감기·최대 진행도 병합·새 저장 형식은 제안하지 않는다. [PR03·PR04](options.md)의 미채택 후보이며 기존 [결정 5](../../../../decisions/0005-run-modes-and-respawn.md)·[결정 21](../../../../decisions/0021-server-issued-player-identity.md)을 유지한다.

## 주요 중단 시점

아래 ‘보존’은 같은 세계에서 실제로 끝낸 사실의 보존이다. 아직 저장하지 않은 사실이 프로세스 종료·손상 파일 뒤에도 자동 영속된다는 뜻은 아니다. 사용한 물자·부상·현재 위치·적 상태까지 초기화하지 않는다는 일괄 약속도 아니다. 각 세부는 현재 소유 규칙 또는 PRH의 미결로 구분한다.

| 중단 시점 | 유지할 완료 사실 | 다시 확인할 것 | 다시 수행할 것·하지 않을 것 |
|---|---|---|---|
| 조사 일부 뒤 이탈 | 실제 확인한 사실·근거와 주민에게 전달한 범위 | 현재 위협·관찰 여건·바뀐 연결, 아직 없는 계획 | 빠진 대조만 한다. 이전 설명 전체·미방문 흔적·강제 조우를 요구하지 않는다. |
| 보스전 중 일부 결박 해제 | 실제로 해제된 연결과 현재 세계의 변화 | 곰의 현재 상태·남은 연결·이격·접근, 개인 생명 상태 | 남은 직접 전투 판단을 잇는다. 해제한 결박을 설명을 위해 다시 묶지 않는다. 체력·타이머·위치의 재개 정책은 PRH02다. |
| 곰 해방·이격 뒤 | 바르툴 생존·해방·상호 이격 성과 | 정상 설비·손상 연결·잔류 위험·정비 계획·도구 | 남은 정비를 한다. 보스 처치나 재전투를 수원 정비의 새로운 자격으로 넣지 않는다. |
| 정비 도중 | 실제 끝낸 채취 해제·분리·회수 등 확인 가능한 작업 | 현재 연결·파편·동력·사용한 물자, 작업 중인 부분 | 끝나지 않은 작업과 필요한 시험을 잇는다. 중단된 시도는 완료로 처리하지 않으며 완료 작업을 이유 없이 되풀이하지 않는다. |
| 송수 뒤·하류 확인 전 | 현장 송수 확인 당시의 결과 | 현재 물·마을 사용 결과·이상 | 하류 점검·인수를 한다. 현장 성과로 주민 지식·사용 안전을 자동 채우지 않는다. |
| 인수 도중 | 실제 전달된 내용과 이미 동의한 범위 | 남은 질문·근거·현 재고·분담 변화 | 부족한 설명·현지 확인·동의만 잇는다. 지정·서명·기록 배부 같은 새 필수 절차는 정하지 않는다. |
| 인수 뒤·출항 전 | 과거 인수·작업 사실과 준비한 자료 | 이번 아침 결과·그 뒤 새 이상·현재 운영·배편 | 현재 출항 판단에 필요한 확인만 한다. 같은 아침 결과가 계속 적용될 때 새 대화 횟수로 재검사를 강제하지 않는다. |

확인 가능한 작업 결과를 재개의 기준으로 삼되 최소 단위를 미리 구현 필드로 고정하지 않는다. 한 물리 작업이 중간에 불안정한 상태를 만들면 실제 상태·위험을 기록하고, 완료는 그 결과를 확인했을 때만 인정한다. 수행하지 않은 소모를 청구하거나 이미 지불한 비용을 중단 때마다 다시 청구하는 규칙도 함께 채택하지 않는다. 비용·물자 적용 단위는 별도 설계·검증이 필요하다.

## 재개 종류별 후보

| 종류 | 추천 처리 | 유지하는 경계 |
|---|---|---|
| 걸어서 재접근 | 같은 세계의 사실·미완료를 유지하고 현재 위험·접근·연결만 다시 확인한다. | 귀환권은 통행 성공·무적·시간 정지가 아니다. |
| 개인 사망·재도전 | 기존 서버 권위·개별 재스폰을 따른다. 다른 플레이어·세계 성과를 초기화하지 않고 돌아갈 수 있는 현재 조건부터 확인한다. | 바르툴 결박·복구·마을 인수의 영속 데이터가 현재 구현됐다는 주장은 아니다. HP·물품 손실·스폰 위치의 새 규칙을 정하지 않는다. |
| 같은 세계에 재접속 | 기존 신원·프로필 계약으로 연결하고 현재 세계 상태와 개인이 실제 안 사실을 구분한다. | 동료의 경험·보고·동의를 자동 복사하지 않는다. 다중 플레이어의 지식·기여·보상은 별도다. |
| 유효한 저장을 명시적으로 불러오기 | 선택된 저장의 세계·개인 상태를 해당 복원 계약에 맞춰 적용한다. 이후의 완료 상태를 과거 재고·시간과 임의로 합치지 않는다. | 이는 세션 복원이며 같은 진행 안에서 성과를 없애 새 사건을 만드는 서사적 퇴행과 구분한다. 저장 이후 미저장 진행 보존을 약속하지 않는다. |
| 저장 실패·누락·지원하지 않는 상태 | 성공한 저장·복원이라고 표시하지 않는다. 필요한 진행 근거가 빠졌다면 출항·정비 완료를 추정하지 않고 거부 또는 명시적 이관 검토 대상으로 둔다. | 새 실패 UI·자동 덮어쓰기·보상·복구 알고리즘은 제외한다. 기존 파일·현재 상태의 실제 실패 보존 범위는 소유 계약을 따른다. |

후보 PR04는 ‘모든 과거 저장에서 절대 되감지 않음’이 아니다. 그런 보장은 기존 저장 복원과 충돌하고 저장 시점이 다른 현재 성과·자원을 섞게 만든다. 보존 원칙은 같은 진행 세계의 성과에 적용하며 명시적 복원은 선택된 기록의 경계를 적용한다. 저장 후 접속한 등록 플레이어를 유지하는 결정 21의 예외도 그대로 둔다. 이 예외를 모든 신규 플레이어의 서사 지식·완료 상태 복사로 확대하지 않는다.

## 기존 계약과 읽기 전용 코드 확인

2026-11-15 기준 커밋 `b4107226`에서 관련 소유 문서와 아래 코드 범위를 확인했다. Graft 조회 뒤 잘린 `ApplyRecord` 범위만 실제 파일에서 이어 읽었다. 엔진 내부·전체 저장 호출 그래프·모든 에셋·첫 장 구현 전체를 조사하지 않았고 코드를 바꾸거나 실행하지 않았다.

새 요구와 차이가 있는 부분은 세 가지다. 첫째, 필요한 정보를 실제 확인한 근거와 현재 유효성을 구분해야 한다. 둘째, 살아 있는 곰의 해방과 하위 정비·사용·인수·아침을 별도로 표현해야 한다. 셋째, 그 조건을 복원 가능한지 확인한 뒤 저장 성공을 주장해야 한다. 이는 후속 제작의 확인 목록이며 이번에 클래스·스키마·코드 변경안을 확정하지 않는다.
