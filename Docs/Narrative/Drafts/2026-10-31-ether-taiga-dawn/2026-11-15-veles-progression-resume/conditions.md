# 진행 조건과 현재 운영 판단

2026-11-15 사용자 승인으로 PR01-PR07과 공통 경계를 [결정 61](../../../../decisions/0061-veles-progression-resume-adoption.md)·[Scenario](../../../Scenario.md#벨레스-첫-장의-진행과-재개)에 반영했다. 이 채택 범위는 `CLOSED`다. PRA01-PRA02·PRH01-PRH06과 아래 원문을 보존하며 TR·C·RT 및 상세 표 전체·실제 UE 구현은 함께 채택하지 않았다. 아래 후보·미채택·다음 선택 표현은 작성 당시 기록이다. 반영 검토는 [별도 기록](../../../Reviews/2026-11-15-veles-progression-adoption-review.md)에서 확인한다.

**‘끝낸 적이 있는 일’과 ‘지금 다음 행동을 해도 되는 조건’을 따로 기록하는 안을 추천한다.** 과거 송수 성공은 남겨도 새 이상이 있으면 현재 사용·출항 판단을 다시 해야 한다. 반대로 확인할 부분이 하나 생겼다고 조사·보스전·모든 정비를 처음부터 되풀이하지 않는다. 이는 [PR01·PR02·PR05-PR07](options.md)의 미채택 규칙 후보이며 기존 [NC·VR](../../../Scenario.md#벨레스-첫-장의-통합-흐름과-미완료-연결)·[JC](../../../Scenario.md#여정-연결과-현재-인수)를 입력으로 쓴다.

## 구분할 사실

| 항목 | 완료·확인을 인정할 근거 | 따로 남길 현재 조건 |
|---|---|---|
| 주인공 지식 | VI01-VI08 중 실제로 관찰·전달받은 사실과 그 근거. 현재 고장·계획·공동의 위협을 각각 구분한다. | 해당 사실의 대상·현재 연결이 바뀌었는지. 과거 사실을 아는 것과 지금도 같다는 판단은 다르다. 플레이어의 이해는 별도다. |
| 현장 상태 | 현재 적·곰·결박·정상 설비·손상 연결의 관찰과 실제 변화. | 보이지 않는 대상·현재 접근 위험·추격·작업 여건. 미관찰을 안전으로 읽지 않는다. |
| 전투 성과 | 실제 직접 전투, 외부 결박 해제, 살아 있는 곰과 상호 이격의 결과. | 이미 풀린 부위와 아직 남은 연결, 현재 곰 위치·이격 여건. 생존·해방을 사망 플래그로 표현하지 않는다. |
| 현장 작업 | 채취 해제·손상 연결 분리·파편 회수·정상 동력·첫 물 확인의 실제 수행 내역. | 미완료·중단된 작업과 현재 연결·작업 도구·접근 조건. 기록이 작업을 대신하지 않는다. |
| 하류 사용 | 주민이 현지에서 실제 확인한 사용 결과. | 현재 공급 상태·새 이상. 현장 첫 물만으로 하류 결과를 채우지 않는다. |
| 운영 인수 | 담당자가 맡을 점검·보충·교체와 이상 시 대응을 이해하고 실제 동의한 내용. | 맡은 범위·조건이 달라졌는지, 답할 근거가 남아 있는지. 대화 종료나 방문 횟수는 동의의 증거가 아니다. |
| 현재 공급 | 보관인의 보유분 확인, 운반·보충 담당과 실제 인수 근거. | 지금 쓸 수 있는 물량, 예정 거래의 불확실성, 작업·대기 동안의 소모. 수치가 없으면 충분하다고 판정하지 않는다. |
| 아침 점검 | 인수 이후 이번 아침에 담당자가 실제 확인한 결과와 전달. | 그 뒤 알려진 새 이상·운영 변경. 전날 점검·시간 경과·밤의 결심은 이번 결과가 아니다. |
| 여행 준비·종료 | 마을용·휴대 기록 구분, 로덴 전달 목적·개인 여행 의사, 기존 운송 배편의 실제 승선 준비와 출항. | 마을 운영과 운항의 현재 조건. 정상 출항 후 배에서 세계수 상층 수관을 보는 첫 장 종료를 보스 승리와 합치지 않는다. |

이 표는 클래스·플래그 이름이나 저장 필드를 정하지 않는다. 처음에는 사실별 근거·대상·현재 조건만 구분한다. 후보 판정은 `충족`, `미충족`, `미확인`, `재확인 필요` 네 가지다. `미확인`은 거짓도 참도 아니며 정상 완료를 인정할 근거가 없다는 뜻이다. 진행 중인 행동은 별도로 적고, 시도·설명·계획을 완료 근거로 쓰지 않는다.

확인 인정은 장소 진입·적 처치·대사 버튼 횟수가 아니라 대상 사실이 실제 관찰·전달되는 행위와 결과에 둔다. 이후 구현에서 어떤 입력·시간·트리거가 이를 대표할지는 PRH05다. 퀴즈로 이해를 증명하게 하거나 강제 시청·새 필수 물건을 추가하지 않는다. 비어 있는 사실은 기존 확인 자리와 연결하되 가능한 접근·관찰 여건도 별도로 점검한다.

## 조건과 전이

TR01-TR11은 **판정 비교용 행동 묶음**이다. 하나의 일렬 퀘스트·잠긴 문 목록이 아니다. 현재 상태에 따라 귀환·보고·재확인이 끼어들며, 필요한 사실이 없는 상태에서도 눈앞의 위협에 대응할 수 있다. 표의 선행 조건은 해당 성과를 정상 완료로 인정하는 근거이지 모든 물리 행동을 막는 장치가 아니다.

| 묶음 | 선행 조건·확인 근거 | 실제 수행 뒤 인정할 변화 | 중단·미충족 때 남는 일과 재개 |
|---|---|---|---|
| TR01 출발 분담 | VI01의 급수 이상·대상 공급선, 기존 주민 분담·현재 비상 대응과 개인 준비를 확인한다. | 조사 목적·분담·알고 있는 길을 구분해 수원행을 시작한다. 야외 흔적·곰의 원인은 아직 모른다. | 현재 지원·준비가 불명확하면 그 부분을 확인한다. 전 여정의 비축 충분성을 가정하지 않고 미확인을 운영표에 남긴다. |
| TR02 작업실 대조 | 실내 위협에 직접 대응해 현재 연결을 살필 여건이 있고, 물·얼음·우회·정상 회로를 실제 대조한다. | VI02의 확인된 원인·멈출 연결·보존할 회로·전투 뒤 작업을 근거와 함께 기록한다. | 놓친 연결만 기존 자리에서 확인한다. 재접근 안전이 없으면 판정은 미확인으로 남고 먼저 위협 대응·철수 판단을 한다. |
| TR03 공동 관찰 | 현재 곰·외부 결박·정상 설비와 조작부 접근 방해를 관찰한다. | VI03의 현재 전투 대상·필요를 안다. VI02를 얻지 않았다면 별도 누락으로 남긴다. | 지난 장소를 통과했다고 VI02를 채우지 않는다. 공동 관찰을 다시 하기 위해 과거 퇴각 동작을 재연하지 않는다. |
| TR04 해방 전투 | 실제 직접 전투에서 외부 연결을 끊고, 앞다리 변화·가슴 해제·상호 이격을 확인한다. | 실제 해제한 부위와 생존·해방 성과만 인정한다. VI04는 관찰한 변화 범위만 갱신한다. | 도중 중단이면 실제 해제한 연결은 남고 미해제 연결·현재 위협을 다시 본다. 지식 누락은 공격·자기방어를 봉쇄하는 조건이 아니며, 해방했어도 정비 계획이 없으면 TR05의 필요한 대조를 보완한다. |
| TR05 실제 정비 | 해방 뒤 현재 작업 여건과 정상 회로 계획을 확인한다. 하위 작업마다 필요한 선행 분리·도구·접근을 확인한다. | 실제 끝낸 채취 해제·손상 연결 분리·파편 회수·정상 동력·첫 물 확인을 따로 기록한다. 모두 끝난 현장 송수와 하류 사용을 분리한다. | 중간 완료는 보존하고 시작만 한 작업은 완료로 세지 않는다. 돌아오면 현재 연결·잔류 파편·남은 작업을 대조해 이어 한다. 새 안전 장치·자동 수리를 가정하지 않는다. |
| TR06 귀환·보고 | 실제 귀환 경로를 통과해 주민에게 도달한다. 현장 완료는 귀환 자격 조건이 아니다. | 본 사실·끝낸 일·모르는 것·못 한 일을 나눠 전달한다. 주민은 보고받은 범위만 안다. | 현재 위협·몸·장비를 보고 기존 길에서 대응·이격·재선택한다. 안전한 귀환·즉시 이동을 보장하지 않는다. 미완료 보고 뒤 현장 작업·공급 판단은 그대로 남는다. |
| TR07 하류 점검 | 실제 현장 결과와 현재 마을 공급을 주민이 확인할 수 있다. | 정상 사용을 실제 확인했을 때만 현재 사용 조건을 충족으로 둔다. 이상을 확인했다면 그 이상을 기록한다. | 현장 송수가 미완료면 정상 사용으로 세지 않는다. 주민이 현장 원인을 추정해 메우지 않고 필요한 작업·현지 확인으로 돌아간다. |
| TR08 운영 인수 | 실제 보고·하류 확인·현재 재고·예정 거래를 구분하고 맡을 점검·보충·교체·대응 범위를 설명한다. | 담당자의 실제 이해·질문 해소·동의를 해당 범위의 인수로 인정한다. | 담당자가 모르는 부분만 설명·실제 대조한다. 주인공도 모르면 원천 현장을 확인한다. 새 부담·조건 변경이 있으면 관련 동의·운영 여유만 다시 확인한다. |
| TR09 저녁 준비 | 정상 인수 후 도움을 받고 마을용·휴대 자료와 여행 목적을 구분한다. | 기록의 용도와 여행 의사가 이어진다. 다음 아침 결과는 미확인으로 남는다. | 인수가 부족하면 밤 장면으로 덮지 않는다. 준비 일부를 했어도 미완료 조건은 유지하며 정확한 대사·물건은 NG07로 넘긴다. |
| TR10 이번 아침 점검 | 인수 뒤 이번 아침의 실제 공급·설비·운영·보충 조건을 담당자가 확인하고 결과를 전달한다. | 새 이상이 없고 관련 조건이 충족됐다는 근거를 현재 출항 판단에 쓴다. | 이상·근거 부족이면 출항 완료를 인정하지 않는다. 과거 성과는 남기고 영향을 받은 사용·운영·동의만 다시 확인한다. 검사를 반복한 횟수로 통과시키지 않는다. |
| TR11 정상 출항·첫 장 종료 | 현장 작업·하류 사용·인수·현재 공급·이번 아침 결과·자료와 여행 목적·기존 배편 준비가 각각 충족되고 알려진 새 이상이 없다. | 실제 승선·출항 뒤 세계수 상층 수관에서 첫 장을 닫는다. 린은 부두에 남는다. | 무엇이 미충족·미확인인지와 확인할 자리만 드러낸다. 승선 장소 도착·보스 승리·레벨·야외 처치 수만으로 완료하지 않는다. 출항 지연의 정확한 일정·실패 결과는 보류다. |

전이의 출항 조건은 현재 정상 완료를 인정하는 데 필요한 조건들의 결합이다. 하류·인수·아침의 결과가 저장돼 있어도 그 결과가 현재 적용할 설비·분담과 맞지 않으면 재확인한다. 모든 조건을 매 프레임 처음부터 확인하거나 담당자를 같은 대사로 무한 반복시키자는 규칙은 아니다. 특정 조건의 근거·대상·실제 변화가 재확인의 범위를 정하며 유효 시간 숫자는 정하지 않는다.

TR09-TR10은 정상 흐름의 저녁·다음 아침을 비교한 것이다. 이미 그 아침에 인수 누락을 찾았다면 현재 시각에서 부족한 인수·준비를 보완하고 관련 조건을 새로 점검한다. 저녁 장면 재연이나 하루 추가 대기를 강제하지 않는다. 반대로 아직 다음 아침에 이르지 않은 정상 흐름을 전날 점검으로 통과시키지도 않는다. 실제 작업 때문에 달라지는 시간·배편은 PRH03의 미결이다.

## 운영 의존과 판정 불가

| 판단 | 필요한 실제 근거 | 없거나 부족할 때 | 다음 소유 |
|---|---|---|---|
| 미완료 귀환 뒤 재작업을 계획할 수 있는가 | 현재 사용 가능한 재고·비상 공급, 현재 소모·운반 부담, 재접근·작업·귀환 동안의 필요량, 담당자의 수행 가능 범위 | 현장 미완료와 현재 부담을 보고하고 필요한 값·업무를 확인한다. 부족을 확인한 것과 아직 모르는 것을 구분한다. 재작업 기간을 반드시 버틴다고 쓰지 않는다. | 첫 장 수치·공간은 NG06. 주인공·주민의 실제 다음 행동 표현은 NG07. |
| 현재 정상 운영을 인수할 수 있는가 | 하류 사용 결과, 다음 보충·교체의 담당·실제 확보·운반 여건, 당사자의 이해·동의 | 기록·예정 거래·이웃 마을의 생산 능력만으로 현재 재고를 늘리지 않는다. 설명 부족이면 그 부분, 물량 부족이면 그 공급 근거를 확인한다. | 운영 판단은 NG05, 물량 가정은 NG06. |
| 출항을 판단할 수 있는가 | 이번 아침의 점검, 그 뒤 알려진 변화, 기존 운송선의 현재 적재·출항 준비와 마을 운영 | 정상 출항은 유보한다. 자동 수리·시간 정지·강제 파국을 덧붙이지 않는다. 어떤 증거가 생겨야 판단을 재개할지 남긴다. | 실제 배편·원경·시간은 NG06, 구체 지연 원고는 NG07. |

자원 종류별 비교가 필요하면 같은 단위의 `현재 사용 가능량 + 해당 기간 안에 실제 인수 가능한 보충량`과 `작업·운반·소비에 필요한 양`을 대조한다. 단위·기간·손실·가용성이 없으면 수치 판정은 미확인이다. 주문·거래 가능성을 보충량으로 넣지 않는다. 사람의 노동·도구·물·동력을 하나의 숫자로 합치거나 한 자원이 넉넉하다는 이유로 다른 부족을 통과시키지 않는다. 이 식은 확인할 입력의 관계이며 실제 수급량을 계산한 결과가 아니다.

진행 막힘을 줄이려면 미충족 조건마다 다음 확인 주체·자리·행동 또는 보류 사유가 있어야 한다. 실제 접근 불가·재고 고갈·부상 같은 상태에서 항상 회복 경로가 존재한다는 보장은 이번에 만들지 않는다. 그런 사례는 NG06의 검증 입력으로 넘기며 원래 요구를 지워 출항시키거나 무한 비축을 넣지 않는다.
