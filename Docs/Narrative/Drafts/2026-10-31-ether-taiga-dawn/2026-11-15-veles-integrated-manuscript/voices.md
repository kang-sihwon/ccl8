# 인물의 말과 설명 부담 검토

채택 범위·보류·검증 상태는 [상위 문서](../2026-11-15-veles-integrated-manuscript.md)를 따른다. 본문은 작성 당시 후보 기록이며 원문 전체를 정본화한 것이 아니다.

**말의 차이는 각자가 실제 맡는 일과 아는 범위에서 만든다.** 주인공의 첫 신뢰는 필요한 일을 넘기는 작은 선택으로 보이며 후속 약점을 없애지 않는다. 아래는 작성자의 서면 점검이고 독립 판정은 별도 검토 기록이 소유한다.

## 인물별 말과 행동

| 인물·근거 | 이번 원고의 욕구·충돌과 행동 | 말의 예와 소유한 근거 | 넘어가지 않은 범위 |
|---|---|---|---|
| 주인공. Scenario K01·CP01·NC·PR | [MS01](manuscript.md#ms01)에서 수리부터 말하고, [MS08](manuscript.md#ms08)에서는 더 맡으려던 말을 멈춘다. [MS09](manuscript.md#ms09)에서 개인 여행 욕구를 말하고 기록을 남긴다. | ‘못 한 것도’, ‘마을 사용 점검은 아직’, ‘나도 다른 공방을 보고 싶어’는 수행·미확인·사적 욕구를 구별한다. C04-C05의 미완료 인정도 같은 능력과 책임의 범위다. | 모든 친절을 인정 욕구로 해석하지 않는다. 겁이 없어지거나 타인을 항상 믿는 완성된 성장으로 쓰지 않는다. 이름·성별·가족사·전용 무기는 정하지 않는다. |
| 스승. Scenario 복구와 마을의 역할·VS02·VB | [MS01](manuscript.md#ms01)의 비상 설비와 [MS08](manuscript.md#ms08)의 하류 점검을 맡는다. C04에서 계획과 실제 작업을 구분해 묻는다. | ‘네가 볼 건 수원이다’, ‘작업한 곳은?’은 출발 분담과 주인공의 보고에 근거한다. 답을 듣기 전에 현장 원인을 알아맞히지 않는다. | 마렌과 합치거나 현장 원격 지시·동행으로 바꾸지 않는다. 새 과거·권위·계급을 만들지 않는다. |
| 린. CP02·VS01·VS11·NC | 현재 운반·적재·출항 일을 계속하며 자기 운항 욕구를 짧게 드러낸다. 주인공의 여행은 돕지만 [MS10](manuscript.md#ms10)의 부두에 남는다. | ‘운반은 이쪽 일이야’와 ‘내 배로 어디까지 갈지 내가 정하고 싶으니까’는 자기 역할·선택의 말이다. 본류 보고는 직접 확인한 물에서 나온다. | 보유 선박·항해 실적을 새로 확정하지 않는다. 자기 배는 욕구이며 이번 동승·후속 타르넬 합류 완료를 뜻하지 않는다. 친구의 조력자 역할만으로 축소하지 않는다. |
| 보관인. IB01·PR06 | MS01의 배분, MS08·C04-C06의 현재 사용 가능량과 예정 보충을 나눈다. | 보고는 현재 확인한 물량·사용 조건에 근거한다. 미래 거래를 도착한 재고처럼 말하지 않는다. 정확한 숫자 없는 예문은 충분성 계산의 대용이 아니다. | 새 인명·직책·국가 권한을 붙이지 않는다. 스승의 부하로 쓰거나 비축 지속 시간을 단정하지 않는다. |
| 점검 담당 주민. VS10·PR05 | MS08에서 묻고 이해·동의한 뒤 실제 일을 맡는다. C06에서 모르는 상태를 말하며 MS10에서는 새 점검 결과를 보고한다. | 질문과 답의 차이가 인수의 내용이다. ‘모르는 건 물을 거고’는 전지식이나 자동 지원 약속이 아니다. | 새 동료·수리 대행자를 만들지 않는다. 같은 대사를 모든 NPC의 이해 판정 입력으로 쓰지 않는다. |
| 선장. NC·VR10·PR07 | 준비된 기존 운송 배편에서 짐과 운항을 판단한다. 주인공은 그 안내를 따른다. | MS10의 ‘짐은 어디에 둘까요?’와 배치 안내만으로 맡길 행동을 보인다. | 새 이름·운임·시간표·예외 대기·새 배를 정하지 않는다. 마을의 미완료를 무시하고 태우는 해결사가 아니다. |

인물 중심 근거는 [Scenario 인물 동기](../../../Scenario.md#네-인물의-개인-동기)와 [첫 장의 역할](../../../Scenario.md#복구와-마을의-역할)이다. 마렌·이르는 후속 인물로 유지하고 이 첫 장의 설명을 위해 현장·원격 대화에 넣지 않았다. 정확한 말투는 새 후보이며 성우·음성·연기 지시가 아니다.

## 반복·설명·전투 중단의 점검

| 위험 | 원고의 처리와 근거 | 남은 실제 확인 |
|---|---|---|
| 생활·분담에서 사고 원인까지 강의한다. | MS01은 급수·북쪽 공급선·역할·준비에서 끝낸다. 우회·곰은 MS03-MS04가 처음 제공한다. | 도입 길이와 역할 구분을 실제로 이해하는지는 미검증이다. |
| 숲의 모든 교전에 단서 설명을 넣는다. | MS02의 싸움은 통행 공간을 얻는 결과로 닫는다. 미관찰 야외 흔적을 조사 기록에 넣지 않는다. | 교전량·이동 피로·실제 우회·성장 충분성은 GX·OP에 남긴다. |
| 작업실의 계획을 공동에서 다시 낭독한다. | MS03은 물·연결·계획, MS04는 몸·결박·현재 장애다. C03은 빠진 대조만 보완한다. | 현재 관찰 여유·가시성·C03-R 근거 잔존은 실제 검사 대상이다. |
| 전투 변화 사이에 대사·기록 읽기로 위협을 멈춘다. | MS05에는 해설 대사·기록 열람을 넣지 않는다. 재배치·해제·추격 중지로 변화가 이어진다. | 문장만으로 읽히는 공격 창·모든 무기 접촉·전투 시간은 증명되지 않는다. |
| 복구 계획과 수행을 같은 것으로 쓴다. | MS06의 직접 정비 뒤에만 수행 결과를 적는다. C04의 ‘아직 없어’와 C05의 ‘물을 못 보냈어’는 다른 실제 상태다. | 공구·자원·작업 시간·운반 부담을 아직 수치로 검증하지 않았다. |
| 마을·저녁·아침에 같은 사고를 반복한다. | MS08은 주민의 첫 보고·질문, MS09는 도움과 욕구, MS10은 이번 아침 결과다. | 주민에게 처음 필요한 설명을 줄이면서도 이해를 확인할 분량은 실제 읽기·플레이에서 봐야 한다. |
| 반복을 줄이면서 필요한 인수·동의를 생략한다. | C06에서 답 없는 질문은 실제 확인으로 남긴다. C06-M은 현재 아침에 인수·영향받은 점검을 보완한다. | 인수 표현이 단순 확인 시험처럼 느껴지는지, 재고 정보가 읽히는지 미검증이다. |
| 주인공의 한 번의 신뢰를 완성된 성장으로 만든다. | MS09의 남은 불안, 마을 기록을 남기고 MS10의 결과를 듣는 행동만 쓴다. | 후속 로덴·세르나에서 같은 약점이 다른 조건으로 이어지는 것은 기존 CP·JC 범위다. 새 후일담은 쓰지 않는다. |

## 공간·운영과 표현의 연결

[SP01-SP10](../2026-11-15-veles-validation-design/spatial.md)의 도안 역할·지상/지하·귀환·인수·원경 경계를 유지한다. 마을 공방과 지하 옛 작업실은 다른 장소다. MS04-MS05의 서로 물러남을 곰 순간 이동·새 탈출로로 해결하지 않으며, MS10의 수관은 이미 알고 있는 세계수를 배의 현재 관점에서 보는 결말이다. 정확한 관측점·카메라·가시 거리를 추가하지 않는다.

[OP01-OP09](../2026-11-15-veles-validation-design/operations.md)의 값이 없으므로 원고의 정상 운영 충족을 실제 충분성 결과로 쓰지 않는다. C04-C05에서 도움을 받는다고 재고가 늘거나 부상이 자동 회복되지는 않는다. 현장 정비·인수·아침을 지나가는 문장이 실제 소모·시간·입력을 대신하지 않는다.

다듬은 문장이 짧다는 이유로 전달이 자연스럽거나 전투가 충분하다고 판정하지 않는다. 이번 자체 점검은 근거·정보 순서·반복 위험을 찾은 문서 검토다. 외부 작품을 새 근거로 가져오지 않았으며 독창성 전체를 검증했다는 주장도 하지 않는다.
