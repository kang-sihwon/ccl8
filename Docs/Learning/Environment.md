# 환경 시스템: 기존 Agent 시간에서 공통 세계 시뮬레이션으로 확장하기

이 장은 공통 시간·천체·날씨·지형·눈·물·불·차폐·생태계의 연결을 학습한다. 게임에 연결된 현재 코드와 구현 계획을 구분한다. 환경 기능 전체가 완성된 것으로 설명하지 않으며 구현·검증 상태의 원본은 [EnvironmentPlan](../EnvironmentPlan.md)이다.

`aea2deb`의 Agent 시간 진행과 `823a254`의 환경 계획 도입을 비교한다. 환경 계획 도입은 새 환경 코드의 구현 커밋이 아니다.

조사 중 별도 작업이 추가한 `aab86619b813db2af3d72365cae10fc6a15b0bdc`의 환경 사전 점검 기록도 확인했다. 그 기록은 공통 시계의 로컬 소스 준비와 미검증 상태를 보고한다. 이 장의 게임 코드 발췌는 `50e5838`에 고정하며 진행 중인 코드 초안을 확정 구현으로 포함하지 않는다.

## 2. 해결할 문제

비가 내리는 동안 시간이 흘렀다면 눈·물·땅의 젖음·불·생물·주민이 같은 경과 구간을 해석해야 한다. 각 시스템이 제각각 시간을 진행하면 주민은 하루를 살았는데 눈은 한 시간만 녹는 식의 불일치가 생긴다.

지형 변경은 화면 메시만의 문제가 아니다. 플레이어가 딛는 충돌과 AI가 사용하는 경로, 저장과 다른 클라이언트의 지형이 함께 준비돼야 한다.

## 3. 두 시간과 확정 상태

GameSeconds는 일시 정지를 제외한 게임 경과 시간, WorldSeconds는 배율을 적용한 세계 시간이라는 계획상의 구분이다. 이동·전투가 세계의 계절 배율만큼 빨라지지 않도록 소비하는 시간을 명시한다.

후보 상태는 아직 외부에 게시하지 않은 계산 결과다. 확정 상태는 소비자와 저장·복제가 읽어도 되는 상태다. Revision은 같은 지형·표면 상태를 참조하는지 구분한다.

이름이 같은 XY라도 동굴 바닥과 지붕은 다른 표면이다. 계획은 천체·위치·방향·요구 Revision을 가진 질의를 사용하고 Actor 포인터나 삼각형 번호를 영구 ID로 쓰지 않는다. 이는 프로젝트 설계이며 UE5가 자동 제공하는 완성 환경 시스템의 계약이 아니다.

## 4. 기존 Agent의 시간 진행

출처: `aea2deb`, [CCLAgentWorldSubsystem.cpp](../../Source/CCL/Agents/CCLAgentWorldSubsystem.cpp):63의 `UCCLAgentWorldSubsystem::Tick`. 실제 코드 전체 함수이며 들여쓰기를 공백으로 바꿨다.

```cpp
void UCCLAgentWorldSubsystem::Tick(float DeltaTime)
{
    Super::Tick(DeltaTime);
    if (bRunning)
    {
        PendingSeconds += DeltaTime;
        if (PendingSeconds >= 0.25)
        {
            Simulation.AdvanceTo(Simulation.GetTime() + PendingSeconds * 60.);
            PendingSeconds = 0;
        }
    }
}
```

게임 DeltaTime을 누적하고 0.25초 이상일 때 60배를 Simulation에 넘긴다. 이때 현재 Simulation 시각에 누적 시간을 더하며 호출 뒤 누적분을 비운다.

이 구조는 생활 시뮬레이션 하나를 진행시키는 데 쓰였다. 서로 실패할 수 있는 지형·물·생태계까지 같은 완료 시각으로 묶는 계약은 들어 있지 않다.

## 5. 공통 실행기로 확장하려는 이유

결정 19는 환경과 생태계, 영구 변경과 검증 실험장을 범위에 넣었다. 기존 `AdvanceTo`는 `void`이며 부분 진행 가능성이 있으므로 공통 시계만 앞당기면 모든 소비자가 그 시각까지 완료했다고 보장할 수 없다.

계획은 실제 완료 시각과 오류를 반환하고 후보 계산·검증·확정을 분리한다. 소비자가 이미 자원을 바꿨는데 시계만 되돌리는 처리를 허용하지 않는다.

## 6. 현재 구현과 준비 상태

고정한 게임 기준의 시간 진행은 위 코드와 같은 구조다. 환경 실행기로 교체한 실제 전후 코드는 아직 제시할 수 없다.

별도 사전 점검 기록의 `FCCLWorldClock`은 입력 누적, 배율 변경, Prepare·Commit·Abort, 메모리 Capture·Restore를 준비한 코어다. 서버 Subsystem, Agent, 세션 디스크 저장과 연결하지 않았고 UE 자동 검사도 실행하지 않은 상태로 기록돼 있다.

따라서 ‘시간 코어 소스 준비’, ‘게임에 연결’, ‘빌드 성공’, ‘통합 검증 완료’를 나눠 읽어야 한다. 이 문서는 진행 중인 초안의 API를 새 정본으로 복제하지 않는다.

## 7. 환경 하위 시스템의 연결

| 시스템 | 계획된 입력과 결과 | 핵심 계약 |
|---|---|---|
| 천체·현지 시각 | 천체 부모 관계·회전·궤도에서 위치·일조 | 세계 공통 시각과 지역 표현 분리 |
| 날씨 | 경과 구간의 강수·기온·바람 | 강수량을 하위 단계에 이중 적용하지 않음 |
| 영구 지형 | 굴착·성토 요청에서 청크 변경 | 보호 구역·저장·충돌·내비게이션 준비 |
| 눈 | 적설·융해·통과 흔적 | 보이는 깊이와 이동 지지 높이 연결 |
| 물·젖음·얼음 | 유입·유출·건조·결빙 | 양의 보존과 안정된 계산 단계 |
| 불 | 연료·열·수분에서 연소·소화 | 환경 변화와 확산 조건 연결 |
| 공간 차폐 | 지붕·벽·문·동굴 | 강수·일사·바람·환기를 구분 |
| 생태계 | 서식지·개체군·무리·개체 | 집계와 개체 표현에서 생명 중복 금지 |
| 식생·부패 | 성장·수분·시간에서 상태 | 보이는 생물과 부패 수치의 범위 구분 |

이 표는 계획의 책임 연결이다. 현재 실행 결과가 아니다. 세부 수치와 검증 통과 기준은 EnvironmentPlan을 따른다.

## 8. 서버 권위와 수명

계획상의 서버 World 실행기가 공통 시간을 한 번 진행한다. 기존 AgentWorldSubsystem은 LifeSimulation의 소유권을 유지하고 향후 공통 실행기의 호출을 받는다. 환경이 Agent의 삶을 별도 사본으로 동시에 갱신하지 않는다.

GameInstance 수명의 저장소는 맵 전환 자료를 보존하되 독립 시간 실행기가 되지 않는다. 클라이언트는 확정 상태를 표현하고 입력 요청을 전달한다. 예측·보간과 실제 권위 상태의 경계는 각 기능의 구현 때 검증해야 한다.

## 9. 실패와 미완료 구간

배율이 바뀌어도 이미 받은 과거 입력에는 당시 배율을 적용해야 한다. 처리 예산을 넘긴 시간은 미처리 상태로 보관하고 완료 시각에 넣지 않는다.

지형의 비동기 충돌 생성이 끝났다고 모든 청크와 내비게이션이 동시에 준비된 것은 아니다. 편집 Ticket·Revision·준비 상태를 확인한 뒤 통과 가능한 상태를 게시해야 한다.

저장에는 확정 상태만 포함한다. 영구 지형 자료가 커질 수 있으므로 기존 세션 레코드에 제한 없이 넣는 방식은 계획에서 허용하지 않는다.

## 10. 대안과 비용

| 선택 | 이점 | 비용·제약 |
|---|---|---|
| 높이맵 지형 | 표면 처리와 저장이 비교적 단순함 | 터널 표현 요구에 한계 |
| 밀도 청크 후보 | 굴착·성토·터널 기반으로 확장 가능 | 메시·충돌·저장·복제 비용 |
| 전 영역 정밀 물리 | 균일한 계산 모델 | 현재 범위의 성능·구현 비용이 큼 |
| 지역별 해상도·개체군 집계 | 먼 지역 비용을 줄일 여지 | 경계 전환과 양·생명 보존 검사 필요 |

환경 계획의 선택은 실험 결과에 따라 수정할 후보를 포함한다. UE5의 Geometry·Water·Niagara·PCG 플러그인을 켰다는 사실만으로 위 계약을 만족하지 않는다.

## 11. 확인 방법

| 실험 | 통과를 위해 볼 것 |
|---|---|
| 배율 변경·일시 정지·중간 실패 | 입력 구간 보존과 실제 완료 시각 |
| 눈 속 이동·발자국 | 화면·충돌·예측 지지 높이 |
| 물 유입·유출·결빙 | 양의 변화와 단계별 중복 적용 |
| 수로·구덩이·보호 구역 편집 | 충돌·경로·저장·권한 일관성 |
| 지붕·문·동굴 변화 | 강수·일사·바람 차폐의 구분 |
| 개체군과 개체 전환 | 개체 수·삶·자원의 중복과 소실 |
| 저장·복원·네트워크 | 확정 Revision과 세계 상태 일치 |

EnvironmentPlan의 별도 작업 기록은 엔진 설치 미완료, 시간 코어 자동 검사 미실행, 두 실험 맵 미구현을 명시한다. 이번 학습 문서 작성에서도 빌드·환경 실행·맵 생성은 하지 않았다. 실제 설치 파일에서 API를 읽은 사실은 설치 완료나 게임 실행 성공을 증명하지 않는다.

## 12. 이해 확인

**세계 시간이 60배면 캐릭터 이동도 60배 빨라져야 할까?**

계획에서는 이동·전투와 세계 변화가 소비하는 시간을 나눈다. 세계 배율을 물리 이동에 그대로 곱하는 계약이 아니다.

**Agent 실행 도중 실패하면 시계만 원래대로 돌려도 될까?**

이미 거래·기억·자원이 바뀌었다면 다음 재시도에서 중복 적용될 수 있다. 소비자 상태의 확정·복구와 완료 시각을 함께 설계해야 한다.
